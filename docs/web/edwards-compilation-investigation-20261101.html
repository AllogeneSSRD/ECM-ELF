原因与依据

  1. 3 个设备入口对 1 个入口。Edwards 实例工厂在同一个表中保存三个 launcher；Montgomery 工厂每个 param 只取一个内核。日志确认对应内核均仅含选定的位宽，未意外实例化其他位宽。
  2. 设备代码优化与汇编主导。原始 6656 位 Edwards 的 cicc 与 ptxas 合计约 92.1% 的该单元墙钟时间。预处理、主机编译与压缩所占较小。阶段指标来自 NVCC --time，残余时间未归因于某个具体系统瓶颈。
  3. 内联的大整数路径扩大优化输入。扩展坐标点运算、字典及 NAF 路径使用大量 forceinline 域运算，CGBN 底层按每线程 limb 数展开。binary 还包含多次 bn2mont 转换。单项 binary 的体积与编译耗时也超过本次 Mont0。更细的各优化 pass 因果尚未单独追踪。
  4. 并发并非必要条件。串行仍复现差距；原始 8 路记录可能含 CPU、频率和内存争用影响，本次未独立量化各项贡献。两个样本组不能混作同一测速条件。

优化方向（未实施）

优先验证每个位宽分别生成 binary、prepare、NAF slice 三个独立单元，以薄主机表组装。每个内核仍包含完整内联算术，保留三个运行入口和现有功能；还需要同步模块清单、源/对象身份、发布探针和 JIT 资格验证。NAF 的实际执行顺序是 prepare 后循环调用 slice，不能遗漏准备内核。

其次可评估按历史耗时优先调度大任务，或针对 Edwards 测试有限的 --split-compile；外层和内层并发需要一起计入资源预算。降低优化级别、关闭展开或改变内联需另做数学与运行性能验收，不能凭编译提速直接采用。
