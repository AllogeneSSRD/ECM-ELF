BOINC 的做法：科学数据 + 视觉包装

固定第三方研究集中在BOINC 图形与屏保机制，包含 SETI、Rosetta、Einstein 的画面语义、一手资料与版本边界。对本项目最有用的原则是：低频发布科学状态，独立绘制连续画面，区分真实数据和装饰运动。

科学计算进程继续独立执行，低频更新状态
→
共享内存 / 状态文件进度、心跳、暂停状态及项目自定义数据
→
图形进程按自己的帧率绘制窗口或全屏画面

由此推导的工程建议是：将可视化作为随时可关闭的观察器，让 GPU 计算继续独立执行。该建议是对本仓库的设计判断，不代表 BOINC 的某个项目实现可以直接移植。

ECM 的可视化边界

适合成为主画面

  • 标量的素数幂分解及额外乘子；为什么需要覆盖点阶中的完整素数幂。
  • ladder 的相邻双点、PRAC 的差分加法依赖、NAF 的正负奇倍点选择。
  • 已采样的投影坐标及其表示约定；不能只把随机颜色叫作曲线。
  • 末点 GCD 与非平凡因子、未命中、饱和的区别。

不能据此推断

  • 未知因子对应的小素数域曲线；上图只因教学 N 已知分解而能画出。
  • “离发现因子还有多远”或单条曲线成功率随运算上升。
  • 相同构造在不同算法下有完全相同的中间轨迹。
  • 把旋转椭圆、星轨或颜色起伏解释成真实椭圆曲线运动。

生产计算在模合数 N 的环上进行，并使用投影坐标及可能的 Montgomery 域表示；屏幕上的实数椭圆不是它的几何图像。将大整数取低位、做哈希或归一化到 [0,1) 可以得到漂亮的纹理，但相邻帧的距离没有“趋近因子”的数学含义。投影缩放与后端表示还会改变原始坐标，不能承诺同一构造在各算法下产生相同的残数画面。

教学模式已用 N=17×67 的同一条曲线展示两个真实约化，点阶分别为 12 和 36。B1=3 时 s=6、末点 GCD=1；B1=5 时 s=60、GCD=17；B1=9 时 s=2520、GCD=N。此处只在末点取 GCD；生产实现可能还有构造期检查与其他验证边界。

因子亮起必须由验证结果驱动。以 Montgomery 末点为例，只有 1 < gcd(Z,N) < N 才是非平凡因子；gcd = N 是饱和 / 退化，不能庆祝为成功。Edwards 需按其实际转换与退化判定处理。通常在构造或末端验证时才确认因子，不应为了动画频繁插入 GCD。

建议的接入顺序

先做单条曲线的数学状态与运算依赖图

为所选曲线导出构造身份、实际标量约定、计划游标、数学寄存器名称和少量坐标。展示层根据实际计划画出 ladder 的 R0/R1、PRAC 的差点关系或 NAF 的奇倍点字典；正在回放的局部关系与最近一次设备端点采样分开标注。完整微操作轨迹若未采集，就只画已知的计划关系，不虚构指令实时性。

先在已有安全边界、约 0.2～1 s 发布少量数学状态，绘制帧率独立限制；这些是待测建议。数学点保持离散跳转，视觉强调当前算子、依赖边与实际坐标。生产 N 的因子未知时，主画面采用代数关系图与投影坐标，不能套用教学算例的两个有限域点阵。

再增加独立观察器与 Windows 屏保入口

计算进程在现有完成切片边界形成轻量快照；发布器提供有界、非阻塞的“最新状态”。观察器慢时覆盖旧快照，主计算不等它，因子及结果仍走现有可靠发布流程。GUI 消费同一模型，全屏观察器退出或崩溃不改变 worker 生命周期。真正的 .scr 入口再负责系统预览、退出输入、多显示器和会话边界。

不用为了采用这种架构引入 BOINC runtime。共享内存适合同机快照，文件适合先做低频原型；若选择文件，需原子替换、限定频率并避免 UI 逐帧轮询。多实例读者、worker 重启和批次切换都要能分辨。

建议快照字段含义与约束
版本、长度、序号、采样时间避免读取半份状态；时间使用单调时钟并声明时基。共享内存需要跨进程同步协议，不能只加 volatile。
worker、运行代次、批次代次、数学身份运行代次只服务观察器关联，不创建新的 worktodo 业务任务 ID。曲线族、param 适用性与 sigma 显式表示；N 可用摘要关联。
phase、heartbeat、last_work_update进程存活与数学工作推进分开。长内核没有新进度不能直接判定进程死亡；暂停 / 准备状态不能继续假装推进。
实际标量、计划身份、游标与局部算子保留 lcm 与额外乘子、PRAC 当前素数幂或 NAF 字典索引 / 符号；区分主机计划回放与设备状态。
数学寄存器与点关系例如 R0=[k]P、R1=[k+1]P，或差分加法中的 P、Q、P−Q。系数可用计划表达式，不需逐帧传巨大整数。
点坐标、domain、sample_cursor、验证结果说明普通域 / Montgomery 域、投影坐标与采样边界；少量固定曲线按需发布，不改变 sigma、算法计划或检查点格式。因子结果来自现有验证。

让数学关系驱动美观，而不只给残数加特效

可把一次 xDBL 画成一个输入点分叉为平方、相加和模乘的关系，再收敛到输出点；xADD 明确绘制第三个差点输入；NAF 展示从奇倍点字典选择正点或负点。运算节点和边都有明确含义。残数位纹理可作为坐标的辅助编码，不能取代这些关系。Edwards 可复用已有回读；Montgomery 仍需评估少量导出与回读成本。

性能：能控制开销，不能先承诺零损失

主机上的标量计划可直接生成数学关系图；生产端点采样会增加整理、转换或回读成本。还需要测量画面和满载 CUDA 是否竞争同一块 GPU 的调度、显存带宽、功率及热预算；独立进程和低优先级不保证消除竞争。若有核显，可尝试让展示使用核显。

采样载荷示例：32 曲线 × 4 坐标 × (4096 / 8) 字节 = 64 KiB / 次
若每秒 1 次，仅原始坐标载荷约 64 KiB/s；不含同步、导出核、域转换、GMP、IPC 和绘制成本。

以上是容量估算，不是带宽或性能测量。第一版以少量曲线的数学关系为主，限制图的节点数、状态采样频率与绘制帧率，隐藏和最小化时停止绘制。以配对测量决定是否允许同卡动态模式，以及需要的自动降帧条件。

  • 结果一致：固定 N、曲线族、param、sigma、B1、实际标量与执行选项，关闭 / 仅快照 / 动画三种模式比较因子、最终点与可恢复状态；不同投影表示按数学等价验证。
  • 吞吐成本：覆盖 Montgomery ladder / PRAC 与 Edwards NAF、代表位宽和批大小。建议至少 5 组交错配对，记录设备、驱动、功耗限制、程序身份、预热与计时边界，给出中位数和波动。完整批次墙钟与 kernel 时间分别报告。
  • 运行可靠：观察器关闭、慢读、多实例、worker 重启、暂停、恢复、长内核无进度、GCD=N、保存失败和批次切换。快照不能替代 checkpoint。
  • 资源边界：测 CPU、设备 / 进程显存与整机或设备功耗；不将互相嵌套的时间相加，不将不同组件峰值相加成进程峰值。
