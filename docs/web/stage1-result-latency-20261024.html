恢复与账本丢失

Stage1 本批首条最终内部结果携带独立散列校验的发布计划。内部文件先成功、提交文件失败时，保留 checkpoint，重试补齐缺失后缀；重复批次、部分重叠批次、旧即时因子均去重，损坏或缺行则拒绝覆盖。归档保留配对最终文件；旧账本保留，不自动清理。

Stage2 的 data 是恢复与去重依据。已有 Stage2 内部结果、提交记录或恢复进度却没有整个提交账本时，下一条算术前及封存前报错。不会自动猜测哪些结果已经申报；全部历史同时丢失无法辨认，局部缺失也不等同于整个账本丢失检查。当前规则见 ECM 结果输出，开发验收见 临时草稿。

方案分析：Stage2 只靠 ckpt 恢复，取消中间回执

结论：取消逐曲线小文件可行；仅使用现有完成进度不足以保留当前结果语义。本节是分析，未实施该方案。前述 Stage2 仍保留按 save 分目录的回执与逐条追加的最终 JSONL。

“不保留中间结果”的范围影响
取消 .curve/.batch，保留最终 stage2_results.jsonl、提交文件和扩展 ckpt可行。以最终 JSONL 和 ckpt 承接结果归属、NF 聚合、发布恢复及去重；减少小文件和目录扫描。
只保留当前 ckpt，已完成结果仅在内存中中断后丢失之前曲线的结果与汇总元数据。跳过 done 条后无法准确输出整批 NF/F；进度本身不能重建结果。

现有 ckpt 能恢复什么

Stage2 队列 State V2 保存任务 identity、run、done/total、pending token 与 pending_results 路径。任务身份绑定 AID、实际 N、save SHA256、skip/数量和 B2/Auto B2。它是曲线之间的队列进度，不含单条 GPU Stage2 多项式/点积的算术状态；中断当前曲线仍需重算整条。CPU 直接读 save 的独立入口目前没有这份队列进度，不能直接套用 GPU 队列恢复结论。

直接删回执会失去什么

  • NF 计数：done 同时含 F 与 NF。例如完成 100 条、其中 7 条因子命中，NF 应为 93；当前 ckpt 没有这项分类。
  • 已找到因子：若最终 F/内部 JSONL 也未持久化，跳过已完成曲线会永久丢失因子报告。只保存进度不能重建因子。
  • 整批报告参数：Auto B2、D/P 可随曲线变化，NF 需要最后完成的 NF 曲线实际参数与完成时间，不能用恢复后的参数冒充旧工作。
  • 发布与确认间隙：结果先写、进度后写，崩溃会重算/重复发布；进度先写、结果后写，崩溃会漏结果。当前 pending token 与已刷盘 JSONL 的 queue_receipt 用于判定这段间隙。
  • 完成后去重：正常完成会删除队列 ckpt。失去账本后，重复导入同一 save/范围仍需从最终记录辨认已完成工作，不能仅靠一个已经删除的 ckpt。

建议的最小替代设计

保留两份最终输出的现有用途，Stage2 JSONL 仍完成一条追加一条。父进程统一拥有发布和进度提交；子进程返回已验证结果，避免两处同时决定完成。ckpt 至少补充以下内容：

状态用途
任务身份、已确认序号、NF/F 累计数量恢复计算与正确聚合，NF 不再依赖逐曲线 receipt 文件。
最后 NF 的实际 B2、D/P、时间和必要报告身份保持变参任务的现有提交语义。
待发布曲线的唯一身份、完整输出文本、目标偏移及前缀校验先持久化待提交状态，再追加最终文件；重启补齐或确认同一记录，避免两文件与 ckpt 的发布间隙。
任务封存状态、最终 NF 提交内容及偏移整批 NF 与 finished/worktodo 推进成功前保留恢复依据；done=total 不等于发布完成。
最终 JSONL 中的稳定 task/curve 身份完成后删除 ckpt 仍可从最终历史建立去重索引；旧输出兼容需要明确版本和迁移边界。

因此可以做到“不再保留逐曲线中间文件”，但 ckpt 需要成为当前任务的小型提交状态，不能仍然只是完成计数。内存与 ckpt 保留一个待提交结果和累计摘要即可，不必把整批全部曲线结果反复写进 ckpt。若接受最终 JSONL 为恢复依据，也可从它读取已完成结果重建摘要，但此时结果恢复已不是只读取 ckpt。

性能收益主要来自减少小文件、原子替换与历史目录扫描；逐条最终 JSONL 刷盘及必要 ckpt 持久化仍然存在。Stage2 通常以单曲线算术为主，本轮没有测量此方案，不能套用 Stage1 的 30 秒现象推算收益。验收应在结果已写/进度未写、进度已存/最终文件部分写入、封存 NF 未确认及队列推进四类边界注入中断。
