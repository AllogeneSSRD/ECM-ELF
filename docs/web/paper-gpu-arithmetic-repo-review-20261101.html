GPU 整数加乘论文与 ECM-ELF 算术优化评估

优先研究 Stage1 的真正专用平方及 Stage2 宽位点算术的小规模协作与私有状态缩减。保留现有 CGBN 和 Goldilocks NTT 主体；单点短 NTT 作为后续宽位实验，不直接移植论文的完整方案。

代码快照：ECM-ELF 0.57.2，HEAD 2e1d8b7c。工作区已有协作点算术探针及相关文档改动；这些是实验状态，不作为已接入生产或已取得收益的依据。本评估没有修改程序、构建配置或测试，也没有运行 GPU 实验。

Stage1 的 CGBN 路径

现有实现已经具备哪些论文思想

Montgomery 主循环的 double_add_v2、double_add_v2_suyama 在内核内融合倍点、差分加法及模运算。Edwards 的 edwards_naf_slice 在同一内核内遍历 NAF 切片，并把坐标保持在 Montgomery 域。它们已经避免每次整数加乘单独启动内核。

tiers.def 按容器使用 TPI4/8/16/32；例如 2048 为 TPI8、2560–8192 为 TPI16、9216 起为 TPI32。每线程本来就处理多个 32 位字。论文的“高效顺序化”和“融合中间运算”并不是这里尚未采用的整套新方案。论文对 CGBN 的明显优势主要发生在更宽整数，其 FFT 与经典 CUDA 实现的采样交叉位于约 32k–64k，而本仓库现有代表矩阵最高目标约 16k 位。

最值得研究的是专用平方

项目入口为 mont_sqr_normalized 与 Edwards 的 cgbn_edwards_field::sqr。本地 CGBN 的 mont_sqr 直接调用 mont_mul(a,a)，sqr_wide 同样复用一般乘法。接口名称没有带来对称部分积优势。

可借鉴论文“输出系数由线程独占、用少量寄存器累加”的组织方式，另写项目内的协作平方后端，保留 CGBN 分组及表示。平方只计算上三角与对角线，交叉项加倍；其大整数乘积部分由 n² 项降为 n(n+1)/2 项。该平方对称性是整数算法的通用优化，论文提供的是适合 GPU 的分工和存储思路，不宜把对称平方本身称为论文的新贡献。

在普通模数下，如果 REDC 仍约花 n² 的部分积，则模平方从约 2n² 降到约 1.5n²：理想主导部分积减少 25%，不是模平方时间减半。Suyama PARAM0 的每位约 6M+4S，PARAM3 的核心为 4M+4S 另加小常数乘。对应理想主导工作减少约 10% 和不足 12.5%；若实际单次模平方仅减少 10–20% 耗时，PARAM0 主循环约减少 4–8%，PARAM3 约减少 5–10%，还应扣除加减、取标量位、检查及其他固定成本。

Edwards 默认 HWCD 的 edwards_naf_double 每步为 4S+3M，按需生成 T 再加 1M；稀疏加点约为 10M。因此平方也值得优先研究，但要按窗口和非零密度统计实际平方占比。当前 2XY 算法 5 用 1M 替换第 4 次平方；如果专用平方变快，HWCD 与算法 5 的相对次序可能变化，不能沿用旧选择结论。

实现风险在于 CGBN 已将乘积与 Montgomery 消元交错：现代架构默认由 cgbn.h 选择 WMAD，底层见 core_mont_wmad.cu。不能把独立完整平方再加通用 REDC 当成必然更快的替代，它会拉长双宽数组存活期、增大寄存器压力，并可能破坏原有指令交错。先做保持分组的小后端，不直接修改第三方通用库。

寄存器布局值得借鉴，整块扫描不宜全面替换

cgbn_params_t 已有分档寄存器目标：≤2048 为 56、至 5120 为 128、更宽为 255。现有 Stage1 性能资料 还指出增加驻留率可能只消除末波浪费，并不总提升计算吞吐。因此值得比较小 Q、累加器数量、别名安全的临时量复用和指令级并行，而不是把线程数或占用率最大化。

论文的 block scan 对当前 CGBN warp 内进位未必更便宜；跨 warp 会引入 shared 访问和同步，且减少每块独立曲线数。原来的 normalize_addition 与借位补回保证规范残数；不能为减少比较而删除它们。可预期收益目前只宜表达为少量百分比的调度优化目标，实际结果可能为零或回退，须有新 SASS/计时才能量化。

Stage2 的点乘与平方

当前已不是用普通乘法执行所有平方

s2g_mont_mul 仍是单线程 64 位 schoolbook 完整乘积，再调用 s2g_mont_reduce。但 s2g_mont_sqr 已使用上三角、交叉项整体左移、对角线累加；s2g_point_square 是生产分派，NTT_POINT_SQUARE 默认 1。普通模数走一般 REDC，精确梅森走 线性折叠及 R⁻¹ 旋转。

已有资格数据见 位宽报告第 10 节：RTX4060 Laptop、目标 SM1500MHz、不修改功耗/频率，13 个目标宽度 318–16272 bits，普通/承载两条路径，固定各格 D、布局、链长、Stage1 点和约 2.7×10¹⁰ 的 B2。0.57.1 显式 on 的引擎 init+main 相比 0.56.4，普通合计少 3.24%、承载少 6.18%、合计少 4.37%；0.57.2 默认启用对应设备对象。最高目标位宽分别少 3.58%/7.67%。多数格 n=1，最高档另有逆序复测；不能保证其他设备和工作量具有相同收益，也不能再作为本轮待做收益。

最值得借鉴的是宽位协作和小片段寄存器累加

当前 ladder_kernel 一线程做一个点，chain_kernel 一线程做一条链。一个 NW256 线程需要多个坐标数组和约 2NW 的乘积临时数组，动态索引使“写成线程私有数组”不等于“存入寄存器”。旧构建记录 chain 栈约 26640 B、ladder 约 32784 B；这些是静态容量而非累计访存量。

论文方法应转化为小 TPI 协作：先比较 4/8/16 个线程分摊一个点整数，每线程仅维护固定 Q 个字或输出系数，用 shuffle 或少量 shared 交换摘要。宽位、独立链较少时有望降低每线程串行跨度和局部工作集；大量独立 baby 点时则可能因每点占用更多线程而失去吞吐，必须分别测量。

按结果分工也要调整：论文主体是低 M 字截断乘积，而本项目 REDC 和梅森折叠都要完整 2W 字乘积。完整卷积 C₀…C₂W₋₂ 两端对称的项数相同，直接镜像配对不会负载均衡。一般乘法可配对 Cₖ 与 Cₖ₊W（0≤k<W，令 C₂W₋₁=0），两者合计 W 个部分积，再按平方的上三角权重单独设计分工。不能丢掉高半积。

对于承载路径，必须保留当前线性梅森归约。若直接用 CGBN mont_mul 替代，会重新引入二次 REDC；若直接用其 mont_sqr，还会失去现有对称平方。应对照“协作乘积/专用平方＋当前梅森归约”，不能只更换库名。

工作区已有 stage2_point_coop.cuh 和 协作点算术草稿，目前说明仍是独立原语实验，尚无生产完整点链收益资格。本评估不重复创建或修改这些实现。

普通模数还应关注归约，短 NTT 放在后面

点 REDC 本身有约 W² 的循环。单把完整乘积换为论文卷积或浅层 Karatsuba，普通模乘总体仍保留平方项；梅森折叠为 O(W)，更容易暴露乘积优化的价值。普通多项式系数的 s4_reduce_kernel 调用 s4_div_rem，同样是一线程长除法与修正；它是 NTT 之外的独立候选，不应称为“NTT 乘法太慢”。

单点短 NTT 数学上可行：采用 Goldilocks 域、b=27 的 digit，4k/8k/16k 位输入分别约需 152/304/607 个 digit，完整线性卷积取 512/1024/2048 点；平方只需一次正向和一次逆向变换，乘法需两正向加一逆向。必须同时满足 T(2ᵇ−1)²<q 和补零长度约束。还要计入域算术、carry、重组、模归约及共享空间；它不是直接调用现有巨大多项式 NTT API 就能消除这些成本。

该候选须在设备内与点运算融合，不能每次模乘都由主机提交短变换。优先测试 8k–16k 和梅森路径，并与已经优化的对称平方、小 TPI schoolbook 及单层 Karatsuba 比较。现阶段不能给出可靠数值收益或自动切换阈值。

Stage2 多项式 NTT 的借鉴边界

主体已经比论文朴素 FFT 使用了更多专门优化

  • gl_mul 使用 64×64 高低积及固定 Goldilocks 归约；不是论文的通用双宽取模。论文提出未来采用 Montgomery 表示，不构成这里应改域表示的证据。
  • ntt_run_passes 使用 DIF 正向和 DIT 逆向，已经消除显式位逆序，并批量处理卷积。
  • tile_kernel 已在 shared 中融合多层，含 radix4 和 warp tail；pointwise 与逆归一化已进入逆向 tile，避免额外整数组 pass。
  • outer_fwd_kernel 的 x[2ᴹ] 是每线程多元素处理；outer_coop_kernel 则在 shared 里展开 radix 轴，控制寄存器爆炸。两者体现了论文顺序化思想的不同权衡。
  • pack_zero_kernel 已融合输入打包和补零；常量根表和执行计划也已有缓存。

值得继续做的是在特定 tile/outer 热点中比较每线程 Q=2/4 的固定寄存器小块、共享交换频率、根表复用和融合层数，而不是把整个变换挤入一个线程块。实际 Stage2 主矩阵有 2²⁵–2²⁷ 点变换，单线程块无法容纳。

已有 outer 计划资格报告 表明，更激进的联合表相对中段 M6 的固定 D 全矩阵仅少约 0.19%，未默认启用。这是已有特定实验的结果，不代表所有新内核只有这个收益；但足以说明“继续融合几层就能再快几十个百分点”没有依据。该实验的设备、二进制、样本数和计时边界应沿原报告核对，不能与点平方的数据混合。

carry 的扫描思路仍有局部价值

carry_cone_value 对邻域执行有限轮进位；carry_cone_kernel 已通过 ballot 找到生成/停止位置，warp 的 lane0 在必要时向前寻找跨 warp 进位。融合检查路径见 carry_partial.cuh，分派见 ntt_run_passes 的 carry 部分。

论文可借鉴的是把固定小段先局部处理、再扫描段摘要，从而复用相邻线程重复读取的数据，并用分层摘要限制全最大 digit 长链的跨边界扫描。初始卷积系数的进位可能大于 1，不能把论文的布尔进位运算直接套到原始 NTT 系数；应先证明归一化到二值进位状态，或使用更一般的进位传递函数。

对长变换，跨块扫描需要额外摘要 pass 和全局有序依赖，可能比当前局部 cone 更贵。新增收益应写为 fcarry·(1−1/gcarry)，先从当前曲线取得 fcarry；没有这项剖析，不应填一个虚构的百分比。论文图 2 的分段 exclusive scan 还存在段首处理疑点，不能照搬其伪代码。

如何把局部优化换算成完整收益

当前范围中候选占比 f，候选加速 g 倍： 新时间 / 旧时间 = (1 − f) + f / g 耗时减少比例 = f × (1 − 1/g) 整体加速倍数 = 1 / [(1 − f) + f/g]

冻结的 0.56.0 主矩阵在最高宽度的点组占比为普通 53.90%、承载 58.76%。如果优化真的让整个点组快 1.25 倍，则引擎耗时理想减少 10.78%/11.75%；若整个点组快 2 倍，则减少 26.95%/29.38%，对应约 1.369/1.416 倍加速。它们是旧矩阵的预算模型，专用平方启用后必须重新测 f；点组中的归一化、等待和叶准备也未必被模乘优化加速。

同一旧矩阵中普通 S4 占引擎 24.03%，承载仅 2.56%。假定让整个 S4 快 1.25 倍，理想引擎耗时分别少约 4.81%/0.51%。这是为什么普通系数归约更值得单独研究，承载路径则应先把资源放在完整点乘上。S4 时间嵌套于多项式阶段，不再相加到完整时间。

这组冻结矩阵使用 RTX4060 Laptop、目标 SM1500MHz、CUDA13.3、普通/承载 13 格、B1=50000、sigma26（M2003 为27），实际 B2=27015978990（M6011 为27567389850），每格 off 侧 n=1，计时为引擎 init+main。二进制 SHA256 为 9e2eba5821ac8593b897c7d56cfc7e76324717214a51fef73369e8c286f1a282，原始证据根 data/experiments/stage2_point_matrix_20261031/min1_full03/。这些工况不代表现在工作区的一次新测量。

建议的验证顺序

  1. Stage1：先做保持 TPI 的对称平方原语，分别测试依赖链与足量实例吞吐；再放进 PARAM0/PARAM3 ladder 和 Edwards HWCD NAF，测寄存器、local、完整切片与整条曲线。不先全面替换 CGBN。
  2. Stage2：以 0.57.2 专用平方为基线，完成已有协作原语实验；W=128/129/160/192/255、普通/精确梅森分别比较，保留当前 Montgomery radix 和规范残数。原语通过后再测试完整 xADD、seed、chain、baby ladder。
  3. 普通归约：单独统计 S4 与点 REDC，尝试小规模协作或分块累计。更复杂的快速 Barrett/Montgomery 归约应作为完整算法研究，不能在成本表中省略。
  4. NTT：只针对剖析确认的 tile、outer、carry 瓶颈比较固定小 Q 或分层摘要。变更融合层数后重新计算 shared/寄存器及 arena 计划，不改变 digit 精确性门限。
  5. 后续算法：已有协作 schoolbook 基线后，再比较浅层 Karatsuba 与设备内短 NTT。最终固定 Stage1 点、D、P、布局和链长测完整 Stage2；不同候选收益不能简单相加。

所有候选都应与 GMP 核对边界输入、别名、长进位链及完整输出；曲线/param/sigma 固定时保持相同数学结果和因子行为。NTT 使用 exact_ok_terms 与 choose_cfg 的当前精确性合同，不使用论文参数替代上界检查。
