关键规则

曲线 × 执行位置
Montgomery 可运行在 CPU 或已链接的 GPU 后端；Edwards 当前只运行在 CPU。独立配置避免把 GPU 与曲线模型混为同一种“方法”。
CPU 实现
impl 为 auto、simd 或 scalar；reduction 为 auto、montgomery 或 mersenne-fold。显式 reduction 要求 impl=simd，避免 auto 选中标量时被忽略。两个 Auto 的内部值均为 0，IFMA 的常量通过显式映射传入。
标量构造
Montgomery 的 lcm 为 1 或 12，分别构造 lcm(1..B1) 与其 12 倍。Edwards 固定使用 48·lcm(1..B1)，拒绝 12。
参数化
GPU 接受 0、2、3 作为语法值；是否能运行由链接的后端和构建能力决定。OpenCL 仅实现 PARAM3。CUDA 构建可因禁用 PARAM2 或启用 Mersenne fold 而限制可用项。
sigma
-sigma i:s 会选择 PARAM i；与显式 --gpu-param 不一致时报错。CUDA PARAM0 以 64 位 sigma 构造每条曲线，批次不得在 2^64 处回绕；GPU PARAM2/3 的固定 sigma 及整个批次不能越过 2^32。
队列存档
ECM=/ECM2= 没有显式 save 名称，Montgomery GPU worker 在 tmp_dir 中按 m{n}_{b1}.save 生成；CPU Montgomery 使用同一默认名称。最终 save 写入失败时保留 worktodo，CPU 的可恢复 checkpoint 也保留。
任务失败
队列中某条任务的 sigma 不适配当前 GPU 批次时停止并保留 worktodo，避免截断 sigma 后运行另一条曲线。

选择项是解析结果，不等于通用计算后端接口。CPU 曲线算法、OpenCL/CUDA 内核及私有 checkpoint 仍由各自的实现负责。

下一步的接口位置

将 Stage1 的一次曲线任务或批次作为执行接缝，逐个接入 CPU Montgomery、CPU Edwards、OpenCL 与 CUDA 适配器。未来 Stage2 多后端应复用已验证曲线、队列身份、子进程及回执事务，保留各后端自己的规划和中间存档。此项仍是后续设计，本页不把它写成已实现能力。
