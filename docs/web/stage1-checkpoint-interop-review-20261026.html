先明确“同一曲线”：param 也是构造身份

数字 sigma 相同不足以判定同一数学任务。还要保持实际 N、曲线族、Montgomery param、原始构造/基点及完整标量 S 一致。Mont 的 1·LCM 与 12·LCM、Edwards 固定的 48·LCM 需要明确编码。互通只发生在目标后端已有的构造能力中。

若要求三端至少支持一种相同构造，优先增加 CPU param3。CPU xDBL/xADD 已接收 a24 和任意 affine xdiff，主要缺参数化初始化及身份/保存联动；OpenCL param0 要改目前固定的五槽布局、构造、差分点与常量乘法、64 位 sigma，以及多种设备内核。

CPU param3 的构造应复用共同数学实现：a24=σ·2⁻³² mod N、P=(2:1)、xdiff=2。仍遵守 param3 的种子范围。不能通过把任务 param0 改成 param3 来继续旧工作。

依据：后端选择；OpenCL 明确限制；CPU 通用点运算；param3 构造。

公共状态：数学身份、批次计划、每曲线状态三部分

建议定义新一代批次格式，暂称 V3；旧 V1/V2 外层及 native payload 继续可读。文件名可以保留现有不含后端的命名。一个任务保持一个 checkpoint 主文件和既有备份，不新增逐曲线磁盘文件。

首版保留“一批一种计划”：所有曲线使用相同标量与编码，只有 cursor 和完成状态可以不同，未开始的曲线也继承该计划。无需先建立多计划表或允许同一批同时运行不同窗口。param 字段仅用于 Montgomery，Edwards 使用自己的固定标量约定。

部分必要内容约束
数学身份完整实际 N、曲线族、param、构造版本、B1、LCM 倍数/固定标量约定、曲线总数；每条 sigma 与稳定 curve_index。构造和原始基点须由版本唯一重建；必要时带规范基点摘要。曲线数量变更不并入本轮互通合同。
批次计划规范 S 的位长与摘要、计划种类/版本、NAF window/编码约定、总步骤及计划摘要。大整数用规范编码后求摘要；不使用 GMP 本机 limb 字节作为跨平台摘要。整批只保存一次，不逐曲线复制完整指数/字典。
未完成状态Mont ladder：R0=(X0:Z0)、R1=(X1:Z1)；Edwards：X/Y/Z/T；引用计划及该曲线的 next cursor。全部为普通域模 N 数值；保留投影形式，无需转 affine。源端必须在算法安全边界导出。
种子与完成状态未开始/只有种子、计算中、已完成可用点、真因子、已完成无 Stage2 点。完成结果有自己的类型与数据，不再借用游标表示；恢复只补发布，不能重跑完成曲线。
执行信息来源 CPU/CUDA/OpenCL、BITS/TPI、ISA、倍点或乘法内核、计时资料。用于诊断和装载。只要数学等价与目标能力验证通过，就不纳入任务相等条件。

窗口属于计划，设备属于执行。首次执行可按目标选择计划；已有进度后默认沿用所存计划。显式要求另一个不兼容窗口/算法时说明冲突。HWCD/2XY、CIOS/其他乘法实现等在已证明切片末尾状态相同后可自由选择，不应只因名称不同而拒绝。

V3 沿用整体和逐记录完整性校验、长度与上限检查、备份轮换及批次独占。校验和用于发现损坏；数学验证还需检查规范范围、构造、点关系、计划和游标。新格式不承诺旧程序可读，新旧写入者仍需成组升级。

尚未定义公共数学状态的 PRAC 等计划保留现有 native codec 与严格匹配条件，可用明确的 native 类型分支保留本后端读写；不能因外层身份放宽而直接跨端装载。它们只在独立数学合同和测试通过后转入公共状态，不为首版互通删除已有恢复功能。

两种曲线的数学恢复条件

Montgomery：同一 binary ladder 的相邻点对

L=bit_length(S)，d=已消费的 MSB 位数
kd=⌊S / 2L−d⌋
R0=[kd]P，R1=[kd+1]P；下一步处理第 d 位。

CPU、默认 CUDA 和 OpenCL 的 ladder 都能在现有切片安全边界表示此状态。初始化通常已消费首位，d=1；d 不是点倍数 k。保存两个逻辑点及 d，恢复时重建 a24、原始差分点和剩余位序列即可。不能仅保存 R0 或百分比，也不能保留 GPU 临时 swap 的数组顺序。

普通域与设备 Montgomery 域的转换为 x̂=xR mod N，x=x̂R⁻¹ mod N，R=2BITS。新后端用自己的 R 重编码。N 为奇数时 R 为单位；容器位宽与 TPI 无需沿用来源。OpenCL 当前四坐标同乘 R，仅从投影数学看误认数值不必然换点，但不能据此绕过格式和域合同。常量、limb 布局和校验也必须正确转换。

resident ladder 可作为同一数学状态的另一 Adapter；PRAC 的 next 是素数计划位置，属于另一计划。PRAC 可在完整乘积边界研究 Q=[M]P、剩余 S/M 的续算合同，但现有 ladder 会重建原基点，仍需新增续算基点支持；任意 binary 前缀也不一定整除 S。本轮应保留 PRAC 同算法恢复，另列跨算法 TODO。

依据：CPU 位序列、CUDA 初始位游标、OpenCL 位循环、域转换、PRAC 计划执行。

Edwards：完整扩展坐标与完全一致的 NAF 计划

CPU 与 CUDA 的同窗口 NAF 源码具有对应编码，可优先统一为一个明确版本的计划生成器和摘要；随后以真实互跑确认初始化、首列、负号、零串和最后一列的 cursor 完全一致。不同 window 的相同 done 数字没有同一含义。

例：S=48·LCM(1..10)=120960。w=2/6/12 的 NAF 总列数分别为18/14/8，首列前缀分别为1/15/945。直接把 done=1 交给另一个窗口会继续错误的标量。固定 chunk 大小或恰好落在零串，均不能作为转换证明。

新状态直接导出内存中的 X/Y/Z/T。当前 CPU scalar 和 SIMD 都持有 T，但旧 codec 丢掉 T，恢复时求逆重建。新导入入口应直接接受完整普通域 XYZT，并验证 XY=ZT 和曲线方程，重新建立本地字典与表示。

旧 CPU XYZ 需先处理 gcd(Z,N)：等于1才可逆恢复 T；若为真因子，可转成已发现因子；若等于 N，则 XYZ 一般不足以唯一恢复原 T，应保留旧档并明确无法无损迁移，或选择经验证的旧代。不能任意填 T，也不能把 (XZ,YZ,Z²,XY) 当作对非单位 Z 的通用补救。

CPU 主流程目前接受 NAF auto 或3..12，GPU 另支持 w=2 和 binary。若承诺所有已有 Edwards GPU checkpoint 都可转 CPU，还需支持来源 w=2（避免 SIMD 自动改窗口）及 CPU binary 续算计划；共同 NAF3..12 的首轮不能称作任意 Edwards 算法互通。

依据：共同 NAF 约定、CPU XYZ 恢复、SIMD T 重建、CUDA 计划/窗口验证、CPU 窗口准入。

↓ 汇总回原任务
单份 checkpoint；整任务完成后一次 save / Stage1 结果发布

CPU→GPU 往往是部分曲线完成，其他曲线处于不同游标。建议按 (plan_id,next_cursor) 分组，再选择本地布局；保留完整总曲线数与原始 curve_index，完成结果直接并入汇总。不能统一取 min 游标而丢弃已有工作，也不能取 max 游标跳过计算。

sigma 必须显式带入。当前 GPU Mont 构造、param3 kernel 和结果归属普遍假设 sigma0+i。CPU 随机种子或重组后不连续的种子会破坏该假设。建议 GPU API、构造和结果链路接收逐曲线 sigma/逻辑索引；param0 算术已有 a24/xdiff，可少改内核。param3 需 sigma 数组支持。只按连续 sigma 再拆组可作为过渡，但随机任务可能退化为大量单曲线启动。

恢复分组与现有 CPU Edwards 的“固定连续8 lane、进度不一就重跑”逻辑需要一起调整。不支持 SIMD 形状的尾组可使用 scalar；不支持某个有效计划时应给出能力诊断，不能悄悄改窗口或重算。

现有齐步 GPU 新任务仍可保持一个计算组。迁入不同曲线进度时，分组会增加启动和字典构建次数；若要求这些曲线仍在同一 GPU 组内并行，就需要每 lane 游标/掩码支持，改动和验证范围更大。建议先接受恢复时分组，同时保持整任务只发布一次结果。

一次快照只发布一次。各后端先交付拥有的安全快照，再由现有 Context 串行提交整份批次。不要为1000条记录循环调用1000次现有 write_blob：它每次都会重写整份外层。CPU 可收集各曲线最近一次安全状态；不要求所有曲线停在同一游标。GPU 小组完成不单独发布最终 save/JSONL，也不改变 Stage1 批内按 sigma 排序的合同。

计算游标、安全快照游标与成功持久化游标继续分开；保存失败优先于“正常停止”。所有完成结果与发布恢复材料保留到最终输出及队列提交成功。checkpoint 继续持有同一个长期批次锁；互通不引入两端同时执行同一任务。

依据：逐曲线种子、CPU Mont 游标分组、CUDA 连续种子限制、整批序列化。

方案取舍

方案优点代价建议
A：两两转换 native checkpoint一对后端的单一算法可较快打通，便于过渡验证。转换器逐渐成网；身份、游标、域和批次语义分散；每新增格式均扩大互转矩阵，仍未解决异步进度。仅作为旧格式的只读导入，不作为长期架构。
B：公共数学快照 + 精确计划各后端只连接一个 Seam；数值与磁盘协议统一，内核和本地布局可保留。新旧 importer 有明确出口。需改身份、每曲线记录、导入/导出和分组；计划支持范围必须明确。推荐。一次设计合同，按真实构造能力分期交付。
C：所有后端强制同一算法/全局游标游标和数组关系直接，首个 codec 容易实现。可能限制 NAF/PRAC、浪费 CPU 已完成进度，或改变成熟内核；强制齐步/重算把运行成本转嫁给用户。不作为默认路线。通用素数幂边界方案需另做算法与性能研究。

方案 B 的 Locality：数学状态与验证按曲线集中，磁盘责任归 IO，布局转换归后端。Interface 是数学身份、计划、状态及失败语义；Implementation 中的 CGBN、SIMD、OpenCL 数组不向外泄漏。无需增加 Manager、Factory 链或独立转换守护程序。

重构后的调用流程与实施顺序

  1. main 完成原有归一化，冻结 N/curve/param/B1/sigma 等数学输入，选择现有 run_xx_stage1 入口。
  2. task 建立数学身份和同一个批次锁；Context 识别新/旧格式并进行物理完整性检查。
  3. 曲线工作流生成或重建 S，读取所存计划；共同 checkpoint Module 核对构造、计划、各曲线状态与游标，成功前不提交来源种子。
  4. 目标后端按精确计划/游标组批，重建本地表示和字典，调用原有计算 Implementation；各子批结果映射回原始曲线。
  5. 周期/停止时收集安全快照，一次提交整个 checkpoint；全部计算完成后仍由 task 一次发布 save、Stage1 JSONL 和提交结果。

P1新公共格式、数学身份、批量快照；旧格式只读导入。同后端 round trip、故障/备份/停止/发布恢复通过；旧文件不被错误覆盖。
P2Mont0 CPU↔CUDA，Mont3 CUDA↔OpenCL；逐曲线 sigma/游标与逻辑索引。双向及连续跨端恢复、随机/非连续 sigma、混合完成状态通过。
P3Edwards 共同 NAF3..12、完整 XYZT；调整 CPU SIMD 恢复分组。每个共同窗口双向中途恢复，退化点和不同游标不丢进度。
P4若要完整承诺：CPU param3、Edwards来源w2与binary续算。Mont3 三端双向覆盖；明确CPU scalar/SIMD可执行计划，不自动换算法。
后续PRAC跨算法、OpenCL param0/2、Edwards OpenCL及任意NAF重编码。各自数学转换证明与独立性能验收；不混入格式统一的默认承诺。

旧文件读取应先校验外层，再按来源解析完整身份，验证对应数学字段，最后选择旧 payload decoder。不能简单删除 identity 的 cpu/gpu 子串放行。新格式首次成功写入之前保留原始档；不支持的计划、任务不匹配与损坏应给出不同诊断，不自动清空进度或随机换 sigma。

旧格式缺少的证明不能凭空补齐。CPU Edwards 导入要额外核对窗口对应的 dict_size、指数长度、原始基点与点关系；旧 Mont 没有规范 S 摘要时，只能按受支持版本的既定标量生成约定重建并核对现存字段。给重建的 S 新算摘要，不等于追溯证明旧文件当时保存了该 S；应明确这一兼容假设。

建议对外承诺：“在目标支持相同构造和 checkpoint 计划时，可停止后切换后端，无需重新计算已保存工作。”默认沿用所存计划；互通不要求两个程序同时持锁运行。完全改算法和任意调整 B1/曲线数属于另外的恢复合同。

验证、耗时与内存评估

本页为源码分析，未执行 CPU↔CUDA↔OpenCL 中途 checkpoint 实测。现有 GPU probe 的“最终点与 CPU 比较”、各自停止恢复和旧格式迁移测试，并不能替代真实跨后端中途恢复。两种 Edwards NAF 编码的独立转录比较仅为辅助核对，不作为生产互通验收证据。

验证必要样本与判定
数学续算Mont0 CPU scalar/SIMD↔CUDA；Mont3 CUDA↔OpenCL，增加CPU3后六个有向组合。Ed共同窗口3..12双向，补齐后再测w2/binary。保存→转端→再保存→转回，最终与不中断、独立参考一致。
边界与状态初始种子、d=1、31/32/33、GPU切片非对齐、最后一步、已计算未发布；不同NAF首列/符号/零串；混合未开始、进行中、完成、因子、无点。
身份与几何实际余因子N、LCM1/12、固定48LCM、param、64位Mont0 sigma、param3范围、随机/非连续sigma、不同BITS/TPI/ISA、不同曲线游标，保证原逻辑索引/结果身份正确。
错误与持久化错S/计划/游标、点损坏、截断/CRC、错误身份、有效但不支持的计划、Z不可逆、备份恢复、写入/flush/替换失败、两文件发布恢复；验证失败保留来源，不静默重算。
比较方法规范状态和计划核对；可逆时比较最终affine点，非可逆时检查gcd/真因子/无点语义；对投影点做方程与交叉乘积检查，但不能只靠复合模数下的交叉乘积或CRC证明计算正确。

可以先估算的成本

若仅保存4个普通域坐标，每条最多4·ceil(bits(N)/8) bytes。1000条曲线、10267位N，坐标上界约5,136,000 bytes（4.90 MiB）；521位约264,000 bytes（0.252 MiB）。这只是坐标载荷估算，不含计划、索引、完成结果、临时编码、旧候选和设备副本，不能当作进程峰值。N与同一计划只保存一次；d/a24/基点可按构造重建。

Mont0 CPU与CUDA已有普通域快照，新增成本主要是结构验证/装配。OpenCL需在checkpoint边界转换四坐标，原执行期间继续保留设备域；不应为每个切片额外做主机转换。Edwards补存T约增加一个大整数/曲线，却避免新格式恢复时对每条曲线求逆。字典仍重建，不写成每条checkpoint的大数组。

保留来源 NAF 窗口需要先做目标内存准入。当前 CUDA Edwards 字典约为 4·C·2w−2·container_bytes，同样 C/容器下，w12 的字典为 w6 的64倍。CPU w12 checkpoint 转 GPU 时，应先减少本次计算组的曲线数以适应预算，保持同一计划；不能遇到显存不足就改窗口并沿用旧游标。若最小组仍不支持，明确报错并保留 checkpoint。减少恢复逆运算也不会消除 CPU 仿射字典的重建成本。依据：字典分配。

应实测：同端/跨端加载→首个有效批次、停止请求→持久提交、周期checkpoint耗时、进程峰值与GPU驻留、按游标碎片化的额外启动/字典成本，以及整任务吞吐。使用1000曲线、521/10267位N，分别测试统一与混合游标、连续与随机sigma；标注B1/窗口、硬件、功率、二进制、样本数和计时边界。当前没有数据支持具体毫秒数或加速百分比。

建议的实施范围

先采用 B，完成 P0–P3 作为可验证首轮；若目标明确包含 Montgomery 三端同构造和全部现有 Edwards 模式，则把 P4 一并列入完整交付范围。PRAC、缺少的计算后端及任意算法切换单列，不将它们隐含在“格式统一”中。进入实施前只需确定这一交付边界，后续接口和文件合并由上述职责推进。

临时规划草稿保留，当前生产实现仍为 0.53.4。源码依据为本仓库现状；数学恢复等价性需以实际后端中途恢复测试完成验收。本页不修改现行格式规范或实施状态。
