不以通用 driver、虚函数树或统一循环制造新跳转；实际机制形成后再提升 Leverage。

统一可阅读的六个阶段

01
resolve_options

解析曲线/算法/参数化及能力限制；显式选择不允许静默回退。

02
prepare_scalar

准备数学标量与缓存身份。Montgomery 使用现有 s 或 12s；Edwards 使用 48·lcm。

03
restore_or_construct_batch

恢复已保存算法、sigma、进度和状态，或构造新曲线；恢复校验后才向外报告实际身份。

04
execute_batch

选择实际档位，准备设备资源和算法计划，执行切片；由运行时回报已完成切片和可恢复状态。

05
finalize_batch

检查末点，求 GCD，归一化或转换完成点，区分因子、有效点及完成但无可用 Stage2 点。

06
publish_batch

发布现有格式的因子与 save，填充逐曲线执行结果；任务层随后发布结果账本并最终清理批次检查点。

以上是流程词汇和职责清单，不要求每一项再增加一个只转发参数的函数。曲线工作流可以顺序表达小阶段；有实质状态或复用行为时才提取 module。算法计划的准备应遵从恢复后已确定的模式，并保留原计时顺序。

P4 运行时整理与必要优化收拢 Edwards 公共入口、显式化 resident/PRAC 依赖；提取真实共用进度工具与资源预算，保留算法循环和测试 seam。重复转发减少；GPU回读/launch/同步次数无非必要增加；主机修改不扩大设备重编译。
P5 全矩阵验收与说明运行正常路径和新增缺陷门禁；固定条件比较吞吐、内存/显存、响应与重编译范围，更新正式说明。行为修正各有证据；正常数学等价、旧档、受限构建、CPU/OpenCL兼容与探针隔离全部达标。

保留合同与明确修正范围

  1. 构造身份始终是 curve + param（仅 Mont）+ sigma；算法、容器与内部实现不能改变对外曲线身份。
  2. Mont ladder、resident/PRAC、Edwards 保留各自载荷表示和兼容规则；Edwards 可重选容器，不将它强行绑定 Mont 的 BITS/TPI 条件。
  3. binary bits、NAF columns、PRAC plan index / M-equiv 分别表达；恢复位置不能当作本次运行的新速度样本。
  4. 已完成 GPU 切片 → 同步/错误检查 → 所需状态回读 → 更新进度 → 回调/保存；不发布部分 Stage1 点。
  5. Mont 普通切片不增加强制回读/归一化；checkpoint 按需导出。Edwards 保留现有每片规范坐标回读；已完成 NAF 恢复不重建字典。
  6. 任务会话保留锁、批次外壳、结果账本与最终清理所有权；曲线检查点 module 只管理载荷。普通成功路径不可提前丢失尚未发布的恢复状态。
  7. PARAM0/2/3、fold 与 PRAC 构建限制、Mont 六位余量、Edwards 一位余量及受限构建选档差异继续有效。
  8. 保留原始格式的版本、字段次序、size_t/time_t 布局和兼容读取。统一函数名不意味着统一字节格式。
  9. 允许修正本报告 R1–R7 明确列出的缺陷及必要合同；保留正常数学结果、算法资格、载荷兼容和持久化最终清理所有权。错误退出、错误归类、伪造退化曲线、保存失败误报不作为必须保留的行为。
  10. 切片策略、公式与性能计时的现有区间先保持；周期 checkpoint 的触发时间统一为单调墙钟是本方案明确提出的行为修正，需独立验收。错误处理改变后不承诺 CUDA context 可继续执行。

最终清理依据：storage/checkpoint/ecm_stage1_checkpoint_runtime.cpp:155–166 拦截活动批次/curve record 的底层删除；service/stage1/task.cpp:180–200 完成 save 与结果流发布后才关闭成功会话。

低层普通残基范围检查现已存在；不将其误称为缺失。数学不变量增加到哪个 Interface，须按生产与探针合同确定，避免在每片重复执行昂贵主机检查。主机可恢复普通坐标与 resident 域载荷不能混用完成档快路径。
