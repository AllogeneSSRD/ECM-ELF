# CUDA Stage1 NTT 调优

```text
-tune [ntt][,exp=P|,length=L][,naf=W][,batch=B][,time=N][,repeat=A:B][,find95] [B1]
```

所有字段均可省略，字段值留空也使用默认值。以下示例中引号把逗号串作为一个参数传给 Windows 程序。省略 `ntt` 时也可直接写第一个字段。末尾的 B1 默认 128，原生 NAF 使用该 B1 的生产标量。

```powershell
.\ecm_cuda.exe -tune
.\ecm_cuda.exe -tune "ntt,exp=65521,repeat=2:5,time=1"
.\ecm_cuda.exe --param e -tune "exp=65521,naf=6-8,batch=1-16,time=2" 4096
.\ecm_cuda.exe -tune "ntt,length=2560-4096,batch=8" -d 1
.\ecm_cuda.exe --param m0 -tune "ntt,exp=8191,batch=1"
```

- `exp` 取 32–5242880。调优器将启用的 linear 和 IBDWT 条目按连续支持上限 `max_exp` 从小到大合并。对于输入区间 `[a,b]`，从首个严格大于 `0.8 × a` 的上限，扫到首个严格大于 `1.2 × b` 的上限，包含两个端点及同上限的所有条目。单值按 `a=b` 处理。上界越过表尾时扫到末项，下界越过表尾时没有候选。每个类型和长度单独粗筛、精调及扫描 Graph，测试指数取该项连续上限，显式 digit 位宽可进一步限制测试指数。例如只测 linear 时，`exp=3554-3560` 选择 256 点（p=3556）和 512 点（p=7140）。
- `length` 按实际点数筛选，支持单值或闭区间。例如默认 auto 下 `length=8192` 分别调优 8,192 点 linear 和 IBDWT。省略 `exp` 和 `length` 时遍历整表。这两个字段互斥。各类型的连续上限见下表。[预计算长度表](../../include/ecm/stage1/ntt_sizes.h)
- `naf` 适用于 Edwards，显式取 2–12 内的单值或闭区间，包含奇数。省略或填 0 时筛选 6、8、10、12，即使生产配置固定了窗口也执行该筛选。命令行 `--naf-w W` 可固定一个窗口。Montgomery PARAM0 按 x-only 测量。
- `batch` 是并行曲线数，接受 1–512 内的单值或闭区间。`[stage1] ntt_max_batch` 默认 512，可设为 1–512，限制调优和生产新批次。例如设为 128 后，`batch=64-256` 在 64–128 内测量，`batch=129` 报错。各长度和 NAF 窗口还要满足设备显存、NAF 字典和主机内存预算。省略 `batch` 时自动搜索可容纳的批量；显式单值只测该批量。`--tune-exhaustive` 逐批精测。只有显式给出非空 `batch=` 才保存全部已测批量。
- `find95` 开启 95% 批量二分搜索，默认关闭。可写作 `find95=1` 或用 `find95=0` 关闭。例如 `-tune "ntt,length=4096,naf=6,find95"`。
- `repeat=A:B` 指定每个候选粗测 A 组、精测 B 组，默认 `2:2`。两项独立取 1–20 的整数。`repeat=3:5` 可按三组粗测、五组精测。
- `time` 是每组时长的正数倍率，默认 1。目标设备时间为 `100 × time` ms，四舍五入到整数毫秒，最少 1 ms。例如 `time=2,repeat=2:5` 时，每个粗测候选测 2 × 200 ms，精测候选测 5 × 200 ms。`--tune-seconds N` 限制整个命令启动新测量的墙钟预算。正在测的候选会完成并写表。
- `--tune ntt --bits P` 仍可用于单一指数。显式的卷积、长度、tile、outer、Graph 和 profile 设置约束候选。共享表由 `[shared] tune_file` 指定，默认在配置文件旁的 `tune.toml`，支持按 worker 覆盖。

## 采样与吞吐

1. 粗测每个 NAF 窗口、卷积族和布局在最小批量、内部批量、最大批量的吞吐。容量受 NTT 工作区、NAF 字典、主机内存和请求曲线数限制；实际分配失败时，用二分查找缩小上限。混合长度比较 twiddle radix-5、直接 PFA 和合并访存 PFA。
2. 自动选窗先汇总 6、8、10、12 的粗测结果。按每个窗口**实际测通的最大批量**分档，每档选在该上限聚合 `iter/s` 最高的窗口，吞吐相同取较小窗口。例如 w12 上限 35、w10 上限 128 时，两者可分别进入精调，搜索范围各自截至 35、128。同一上限的其他窗口保留粗测结果。日志 `stage1_ntt_naf_screen` 给出上限、上限吞吐和是否进入精调。显式 `naf=W`、`naf=A-B` 或 `--tune-exhaustive` 时，精调所有指定且可运行的窗口。
3. 入选窗口精调 NTT 布局、tile、outer 和 batch。默认比较倍增批量和峰值邻档。`--tune-exhaustive` 比较区间内每个可行批量。粗测和这一步统一临时用 16 步/Graph，显式 Graph 或 profile 沿用其设定。
4. 每个入选窗口仅对精调吞吐最高的 **一个 batch 及其胜出 NTT 形状**扫描 Graph，比较 4、8、16、32、64 步，复用已经测过的 16 步。日志 `stage1_ntt_graph_scan` 标出该批量。随后按更新后的峰值计算 95% 批量。显式 Graph 或固定 profile 直接使用指定步数。
5. 启用 `find95` 后，Graph 确定后以胜出配置的 batch 为上界，以请求的最小 batch 减一为下界，二分到两端相邻。每个中点按精测条件测量或复用，更新该批量的最高吞吐。若中点刷新 Best，后续比较立即使用新 Best 的 95%。最终取全部已精测批量中的最小达标者。关闭时也从已有测量报告 95% 档。

默认搜索结束后，每个 GPU、NAF 窗口和同一组 NTT 候选最多保存四种并行数。日志中的 `Single` 是单曲线，`Max` 是当前预算下实际通过测量的最大批量，`Best` 是精测吞吐最高的批量，`95%` 是精测中达到该峰值 95% 的最小批量。多个角色落在同一批量时合并。入选批量保留已测的粗测、精测和执行变体，因此表中可能有多行。显式批量记录和生产观察可独立保留。

重复运行显式 `-tune` 时，每个全部命中的精调窗口复测原 `Best` 一次；若启用 `find95`，再从已保存的最佳 batch 向下二分。复测沿用其 batch、NTT 形状、Graph 步数、精测组数及原记录的每组目标时长。一次复测包含正常的预热、正式组和末点核对。新 `iter/s` 严格高于记录时更新完整采样，并按已保留批量重算 95% 档；持平或较慢时保留原记录。只通过粗筛的窗口继续复用粗测。生产任务照常直接使用匹配记录。容量变化或计时精度提高时，补测搜索仍缺的候选。限时或中断时，以 tune 文件名加搜索标识及 `.partial` 保存续跑所需的中间测量，同条件搜索完成后清除临时文件。

粗测、精测、最终 Graph 扫描和缓存复测各自在首条实测数据前显示一次普通文本表头。全轮仅复用缓存时省略表头。轮次、计划、NAF 采样与筛选、校准探针和 Graph 扫描的小标题使用亮青色（`#61D6D6`），表头列名使用默认颜色。发布区的 `Single`、`Max`、`Best`、`95%` 四行使用绿色，随后的 `stage1_ntt_length_done` 和 `stage1_ntt_tune` 两行使用蓝色。每轮汇总 `stage1_ntt_tune` 后打印一行 `=` 分隔各轮。各行遵循控制台时间戳设置。蓝色的 `stage1_ntt_length_done` 汇报本轮该长度最高的精测吞吐，只有粗测时标为 `coarse`。复测分两行显示。首行 `stage1_ntt_recheck` 列出参数，次行例如 `258389.438 vs 258160.555 (old)  +0.09%, status=updated`，依次为本次吞吐、历史最优吞吐（均为 iter/s）、相对变化和状态。正号表示超过历史最优，负号表示下降，持平显示 `0.00%`，无有效测量显示 `n/a`。成功写入时以黄色显示 `status=updated`，保留原记录时以红色显示 `status=kept`。有可比的历史 95% 档时，发布区前的 `stage1_ntt_95_compare` 先列参数，再列「本次 batch、吞吐 vs 历史 batch、吞吐 (old)」，百分比按两档吞吐计算。左侧仅从本轮实际精测（含 Best 复测）取数：以本轮实测峰值为基准，选达到 95% 的最小实测 batch；缓存命中不计入。缺少本轮实测或历史基准时省略对比。黄色 `updated` 表示发布的 95% 批量或吞吐已变化，红色 `kept` 表示发布区沿用原记录，即使本轮实测批量或吞吐不同。首次调优直接发布。重定向输出和镜像日志使用纯文本，设置 `NO_COLOR` 可关闭终端强调色。

x-only 的采样池包含 64 个可重现的标量位。原生 Edwards 用指定 B1、w 编码完整 NAF。总长不超过 512 列时，全部列进入采样池。更长时按从高到低的列序等分为 8 段，各取居中连续的 64 列。调优按设备实测速率，从池中选择正式组使用的块长。

一次调优命令仅在首次需要测量时构造 B1 标量。每个 w 编码一次完整 NAF，保留选中的有符号列供整个命令的位宽、变换长度、批量和 Graph 候选复用。日志 `stage1_ntt_naf_sample` 每生成一份采样输出一次。复测使用本次请求的 B1，采样随新纪录一起写入。

Edwards 调优从射影中性点 `(0:u:u)` 开始。u 由固定种子生成，覆盖模数位宽且与模数互素，同一位宽和不同批量共用相同初值。这样首批倍点也处理一般位宽的坐标。代表指数构造曲线时若连续遇因子，调优使用四阶点字典；该输入的吞吐是校准工作量的估计值。

每个候选先在实际 batch 上试跑最短块。x-only 从 4 位起逐档翻倍。Edwards 的最短块约为池中相邻两次点加的平均间距，包含至少一个真实非零列（池中有非零列时）。更长的块按此长度翻倍，另有完整池可选。短块取连续片段，长块从至多 8 个位置取片段，选择时尽量使累计非零列比例接近整个池。相隔的片段各自结束零列 Graph，点状态沿用。

以试跑设备时间估算目标内能完成的列数，选择能容纳的最长档；最短档已超时就保留最短档。若选中更长档，再单独预热该档。设所选块实测为 t 毫秒，每个正式组连续执行 `max(1, round(100 × time / max(t, 0.001)))` 块，并受计步计数器上限约束。组间重置初始点，全部正式组结束后回放一块核对预热末点。每个正式组用一对 CUDA event 计时，建标量、建字典、建 Graph、短块试跑、预热、重置及末点读回均在吞吐计时区间外。

例如 x-only 选中 64 步、窗口为 16 时，每块启动 4 个 Graph。若该块预热实测 0.8 ms，默认每组回放 125 块，即每曲线 8000 步。窗口是每个 Graph 的步数上限。x-only 的正数尾段可独立建图；所选块短于窗口时，测到的是该尾段。原生 NAF 的连续零列使用 1、2、4 等二次幂长度的 Graph，非零列直接执行倍点和点加。例如 186 列含 26 个非零列时，最短块约 7 列。若这 7 列耗时 160 ms，默认正式组只执行一块。100 ms 是每个正式组的软目标，调优命令的总耗时还包含初始化、试跑及核对。

`sample_pool_steps` 是采样池列数，`block_steps` 是一块实际回放的列数，`timed_steps` 是每曲线每个正式组的列数，`repeats` 是正式组数。原生 Edwards 保存完整标量列数 `naf_columns`、一轮的非零列数 `sample_nonzero` 和所有正式组的 CUDA event 总时间 `total_device_ms`。聚合吞吐 `iter_per_s = 1000 × batch × timed_steps × repeats / total_device_ms`。各组的中位时间 `median_ms` 和标准差用于观察波动。控制台实测行在吞吐之后依次列出 dataflow 掩码（十进制数值加 `bit`）、每组实际/目标设备时间（ms）、每条曲线每组步数（`steps/group`）和每条曲线每个回放块的步数（`steps/block`）。两列步数相除即每组回放块数。原生 Edwards 每步对应一列 NAF，x-only 每步对应一个标量位。原生 Edwards 的 `group_ms` 取各组平均，x-only 取中位数。x-only 仍采用 `1000 × batch × timed_steps / median_ms`。`Single`、`Best`、`95%` 分别报告单曲线、峰值及达到峰值 95% 的最小实测批量。[GPU 回放和计时](../../src/ecm/stage1/cuda/ntt/ladder.cu) · [候选和采样](../../src/ecm/stage1/cuda/ntt/tune.cpp)

## Tune 文件

共享文件中的 `[ntt].matrix` 使用格式 17。Stage1 行按 `max_exp`、`length` 和其余决策条件递增排序。第三列 `iter_per_s` 是比较值。决策条件包括 GPU 条件、批量、卷积与执行形状、曲线和 NAF 窗口、进位与数据流以及配置的设备和 NAF 字典预算。设备预算为 0 表示自动，当前可用显存和峰值占用随实测记录保存。旧表仅有实效预算，整 MiB 值按原预算保留，其余按设备可用量处理。完整生产样本还区分目标、有效曲线数与标量构造。相同决策条件只留最高吞吐行。描述区由 `program_version`、`updated_at` 开头，B1、采样指数、计时和显存观测随胜出测量一起更新。相等吞吐沿用原记录。已完成的粗精测组数和目标时间单独用于续测，不拆分决策行。

各列仅在表中有值时输出，`log2_length` 由点数推导。旧文件加载时按长度表补齐上限并合并重复决策条件。显式调优在文件锁内原子写回转换结果，生产只读查表在内存中转换。Stage2 卷积与 CPU、并行等独立表保留各自的测量语义。旧版程序需要使用旧文件副本。

## 生产选型

显式调优记录实际采样指数。生产缺测时在任务的实际 p 上分别调优每个可用类型和长度。生产输入即使落在同一 NTT 长度档，仍需满足下述查表条件。

Edwards 的 `edwards_naf_window_bits=0` 在当前 GPU 的兼容记录中优先比较精测和生产记录，按聚合 `iter/s` 选窗，再按窗口容量选择批量和 NTT 参数。只读模式缺少这些记录时可用粗测结果。直接指定物理批量时只比较该批量，拆批任务按任务规模和内存比较可行批量，随后按剩余曲线数选批。固定正数窗口只查该窗口。已有快照按保存的窗口和游标恢复。

沿用配置中的 `[stage2] tune_runtime_enabled`（默认 true，支持 worker 覆盖）。首次遇到缺少兼容记录的位宽时，CUDA Stage1 NTT 按当前任务的 B1、窗口和批量范围运行同一粗测与精测流程，再开始计算。关闭后只读选型，无匹配 NAF 时自动窗回退到 x-only。显式 `-tune` 可独立填表。

原生 Edwards 的分段采样行标记为 `stage1_naf_stratified`，其中 `b1` 记录采样来源。显式调优、自动选窗、选型和拆批可跨 B1 复用该类记录。仍须匹配 GPU、曲线、NAF 窗口、变换长度、digit 位宽、进位段数、carry 位数、均匀性及执行形状，且当前预算须能容纳批量。显式调优还检查计时方式、已测组数和目标时间，增大 `time` 只补测精度不足的候选。只读生产优先使用执行形状吻合的测量；仅有同长度记录时，按实际指数重新校验长度、执行形状与预算后才用作估计。完整生产样本还须匹配目标和标量构造。x-only 连续回放使用 `stage1_graph_replay`。Stage1 和 Stage2 共用 tune 文件时，两端都需要能读取对应采样字段的版本。

0.72.1 起可直接沿用扩容前的调优表。65,536 点加权和 131,072 点线性或加权的旧记录保留当时的上限 `max_exp=1048576`，包括显式指定的 131,072 点加权计划。格式 17 之前的表若缺少该列，按当时的上限补齐。新位宽的测量使用当前尺寸表的上限，可与旧记录共存。

新采样用 `sample_phase=1` 表示粗测，`sample_phase=2` 表示精测，`repeats` 独立记录组数。共享自适应采样表时，Stage1 和 Stage2 均须支持格式 17（从 0.71.10 起）。生产选型可读取旧版的整块采样记录。显式调优会按当前协议重新测量。0.71.3、0.71.4 和标记为 `0.72.0` 的预览构建写入的兼容旧采样仍可读取，旧行以 3 组识别粗测、5 组识别精测。重跑时匹配阶段和该阶段的组数，例如从 `2:2` 改为 `2:5` 可复用兼容的两组粗测。提高 `ntt_max_batch` 后，容量改变的窗口重新比较，复用仍适用的样本。

跨 B1 复用时，表中吞吐对应来源 B1。目标 B1 的非零列分布和实际访问的字典槽会变化，窗口排名也可能改变。要独立比较指定 B1 的最佳窗口，可将该次显式调优的 `tune_file` 指向单独的空表。

自动拆批优先使用同条件完整生产样本，再参考合成测量，两者均按 `iter_per_s` 在各自组内排名。取达到同类峰值 95% 的最小实测批量。运行时学习开启且剩余量超过容量时可用真实子批试跑，完成的曲线计入任务。生产样本的 `curves_per_s` 包含标量准备到归一化，部分恢复批次不进入完整排名。日志中 `stage1_ntt_runtime_tune` 表示补测，`stage1_ntt_naf_selection` 表示自动选窗，`stage1_ntt_batch_selection` 和 `stage1_ntt_selection` 给出批量和卷积来源。

以活跃批量 B、指数 p、NTT 长度 L 计，主数组需要 `88·B·L + 92·B·ceil(p/32)` 字节，此外还有标量、NTT 常量表和加权表。申请前核算显式分配，Graph 上传后及同步执行后用 `cudaMemGetInfo` 采样空闲显存差；两者较大值写为 `peak_bytes`。观测值以 CUDA 上下文就绪后的空闲显存为基准，受同设备其他进程和驱动分配粒度影响。

#### NTT and transform sizes

线性卷积从 31 到 16 选择最大可用 digit 位宽 `b`，令 `c = ceil(p/b)`，要求 `c·(2^b−1)² < q`，再取覆盖 `2c+1` 的最小二次幂。加权卷积依次检查二次幂与表中的七个混合长度，要求 `N ≤ p`、`b = ceil(p/N) ≤ 31`。保守界为 `2N·(2^b−1)² < q`，原生 Edwards 还能使用规范乘积的 `U(p,N) < q`。这里 `q = 2^64−2^32+1`。长短 digit 的周期随 `gcd(p,N)` 变化，因此个别超出连续上限的指数仍可单独通过系数界。涉及 2XY 频域组合时另查 `4U < q`。[整数系数判定](../../src/ecm/cuda/ntt/shape.cpp#L2) · [2XY 融合条件](../architecture/NTT.md#edwards-2xy-第一层频域融合)

`ntt_convolution="auto"` 通常还会比较线性、加权二次幂及能缩短变换的加权混合候选。原生 NAF 的最短档若依赖收紧界，仍与其余合法计划按 NAF 列吞吐比较。混合长度均可采用 radix-5 分解，PFA 是同一长度的互素分解实现；可比较传统 twiddle 与 PFA 的置换成本。显式长度、digit 位宽或 tile 会改变准入条件。[生产候选](../../src/ecm/stage1/cuda/ntt/tune.cpp) · [radix-5 实现](../../kernels/cuda/stage1_ntt_radix5.cuh)
