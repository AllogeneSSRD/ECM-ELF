# CUDA Stage1 NTT 调优

```text
-tune [ntt][,exp=P|,length=L][,naf=W][,batch=B][,time=N][,repeat=A:B][,find=N][,force] [B1]
```

所有字段均可省略。以下示例中引号把逗号串作为一个参数传给 Windows 程序。省略 `ntt` 时也可直接写第一个字段。末尾的 B1 默认 128，原生 NAF 使用该 B1 的生产标量。

```powershell
.\ecm_cuda.exe -tune
.\ecm_cuda.exe -tune "ntt,exp=65521,repeat=2:5,time=1"
.\ecm_cuda.exe --param e -tune "exp=65521,naf=6-8,batch=1-16,time=2" 4096
.\ecm_cuda.exe -tune "ntt,length=2560-4096,batch=8" -d 1
.\ecm_cuda.exe --param m0 -tune "ntt,exp=8191,batch=1"
```

- `exp` 取 32–5242880。调优器将启用的 linear 和 IBDWT 条目按连续支持上限 `max_exp` 从小到大合并。对于输入区间 `[a,b]`，从首个严格大于 `0.8 × a` 的上限，扫到首个严格大于 `1.2 × b` 的上限，包含两个端点及同上限的所有条目。单值按 `a=b` 处理。上界越过表尾时扫到末项，下界越过表尾时没有候选。每个类型和长度单独粗筛、精调及扫描 Graph，测试指数取该项连续上限，显式 digit 位宽可进一步限制测试指数。例如只测 linear 时，`exp=3554-3560` 选择 256 点（p=3556）和 512 点（p=7140）。
- `length` 按实际点数筛选，支持单值或闭区间。例如默认 auto 下 `length=8192` 分别调优 8,192 点 linear 和 IBDWT。省略 `exp` 和 `length` 时遍历整表。这两个字段互斥。各类型的连续上限见下表。[预计算长度表](../../include/ecm/stage1/ntt_sizes.h)
- `naf` 适用于 Edwards，显式取 2–12 内的单值或闭区间，包含奇数。省略或填 0 时筛选 6、8、10、12，即使生产配置固定了窗口也执行该筛选。命令行 `--naf-w W` 可固定一个窗口。Montgomery PARAM0 按 x-only 测量。
- `batch` 是并行曲线数，接受 1–512 内的单值或闭区间。`[stage1] ntt_max_batch` 默认 512，可设为 1–512，限制调优和生产新批次。例如设为 128 后，`batch=64-256` 在 64–128 内测量，`batch=129` 报错。各长度和 NAF 窗口还要满足设备显存、NAF 字典和主机内存预算。省略 `batch` 时自动搜索可容纳的批量；显式单值只测该批量。`--tune-exhaustive` 逐批精测。只有显式给出非空 `batch=` 才保存全部已测批量。
- `find=N` 在 1–99 之间取整数，二分查找吞吐**严格大于**峰值 N% 的较小批量。省略时只报告常规 95% 档。例如 `-tune "ntt,length=4096,naf=6,find=80"`。
- `force` 或 `force=1` 按当前搜索范围从粗测开始重跑，忽略已有 tune 测量和续跑文件。本轮内相同候选仍可复用。写回时比较历史吞吐和显存需求，保留更优及低显存候选；控制台汇报本轮实测。默认 `force=0` 沿用缓存。例如 `-tune "ntt,length=2560,naf=6,find=95,force"`。
- `repeat=A:B` 指定每个候选粗测 A 组、精测 B 组，默认 `2:2`。两项独立取 1–20 的整数。`repeat=3:5` 可按三组粗测、五组精测。
- `time` 是每组时长的正数倍率，默认 1。目标设备时间为 `100 × time` ms，四舍五入到整数毫秒，最少 1 ms。例如 `time=2,repeat=2:5` 时，每个粗测候选测 2 × 200 ms，精测候选测 5 × 200 ms。`--tune-seconds N` 限制整个命令启动新测量的墙钟预算。正在测的候选会完成并写表。
- `--tune ntt --bits P` 仍可用于单一指数。显式的卷积、长度、tile、outer、Graph 和 profile 设置约束候选。共享表由 `[shared] tune_file` 指定，默认在配置文件旁的 `tune.toml`，支持按 worker 覆盖。

## 采样与吞吐

1. 粗测每个 NAF 窗口和卷积族在最小批量、内部批量、最大批量的吞吐。容量受 NTT 工作区、NAF 字典、主机内存和请求曲线数限制；实际分配失败时，用二分查找缩小上限。混合长度在粗测和精调主循环中固定使用 pfa-coalesced。
2. 自动选窗先汇总 6、8、10、12 的粗测结果。按每个窗口**实际测通的最大批量**分档，每档选在该上限聚合 `iter/s` 最高的窗口，吞吐相同取较小窗口。例如 w12 上限 35、w10 上限 128 时，两者可分别进入精调，搜索范围各自截至 35、128。同一上限的其他窗口保留粗测结果。日志 `stage1_ntt_naf_screen` 给出上限、上限吞吐和是否进入精调。显式 `naf=W`、`naf=A-B` 或 `--tune-exhaustive` 时，精调所有指定且可运行的窗口。
3. 入选窗口精调 tile、outer 和 batch。默认比较倍增批量和峰值邻档。`--tune-exhaustive` 比较区间内每个可行批量。粗测和这一步统一临时用 16 步/Graph，显式 Graph 或 profile 沿用其设定。
4. 若主循环 Best 使用 radix-5，`stage1_ntt_pfa_scan` 固定其 batch、tile、outer 和 Graph，比较 twiddle、pfa-direct、pfa-coalesced。符合前向融合条件时同时试测 `pfa-coalesced+outer`。若最短 digit 至少为 12 位，再对胜出路径比较五点逆变换与去权汇集的融合。已测的基线可直接参加比较。二次幂长度跳过此步。对已有完整记录的长度，使用 `force` 重新扫描。
5. 对胜出布局和批量扫描 Graph，比较 4、8、16、32、64 步，复用已经测过的 16 步。日志 `stage1_ntt_graph_scan` 标出该批量。随后按更新后的峰值计算 95% 批量。显式 Graph 或固定 profile 直接使用指定步数。
6. 指定 `find=N` 时，按本次精测条件复测单曲线、原 Best 批量和最大可用批量，缓存命中时也实测。同一批量只测一次，`Max` 发布最大批量的复测值。以请求范围内最快的复测结果计算门槛，并以最小的已达标端点为上界二分。每次探测中点，达标则缩小上界，否则抬高下界。中点可复用匹配的精测记录，遇到更高吞吐即更新峰值与门槛。吞吐随批量呈单调趋势时可定位最小达标批量，局部波动时可能跳过孤立的达标批量。显式范围从 2 或更大值开始时，单曲线只作参照。日志 `phase=find_anchors` 标记端点复测，`stage1_ntt_find` 标记搜索开始。

默认搜索结束后，每个 GPU、NAF 窗口和同一组 NTT 候选为本轮最多标记四种并行数。日志中的 `Single` 是单曲线，`Max` 是当前预算下实际通过测量的最大批量，`Best` 是精测吞吐最高的批量，`95%` 是精测中达到该峰值 95% 的最小批量。多个角色落在同一批量时合并。入选批量保留已测的粗测、精测和执行变体，因此表中可能有多行。`find=N` 命中的批量也会保留供生产选型使用。其他预算下已发布的批量仍可作为候选。

重复运行显式 `-tune` 时，每个全部命中的精调窗口复测原 `Best` 一次；指定 `find=N` 时改为上述端点复测与搜索。普通 Best 复测沿用其 batch、NTT 形状、Graph 步数、精测组数及原记录的每组目标时长。`find=N` 的端点复测使用本次命令的精测组数和目标时长。一次复测包含正常的预热、正式组和末点核对。新 `iter/s` 严格高于记录时更新完整采样，并按已保留批量重算 95% 档；持平或较慢时保留原记录。只通过粗筛的窗口继续复用粗测。生产任务照常直接使用匹配记录。容量变化或计时精度提高时，补测搜索仍缺的候选。限时或中断时，以 tune 文件名加搜索标识及 `.partial` 保存续跑所需的中间测量，同条件搜索完成后清除临时文件。

粗测、精测、PFA 扫描、Graph 扫描和缓存复测各自在首条实测数据前显示一次普通文本表头。全轮仅复用缓存时省略表头。轮次、计划、NAF 采样与筛选、校准探针和 Graph 扫描的小标题使用亮青色（`#61D6D6`），表头列名使用默认颜色。发布区的 `Single`、`Max`、`Best`、`95%` 四行使用绿色，随后的 `stage1_ntt_length_done` 和 `stage1_ntt_tune` 两行使用蓝色。每轮汇总 `stage1_ntt_tune` 后打印一行 `=` 分隔各轮。各行遵循控制台时间戳设置。蓝色的 `stage1_ntt_length_done` 汇报本轮该长度最高的精测吞吐，只有粗测时标为 `coarse`。复测分两行显示。首行 `stage1_ntt_recheck` 列出参数，次行例如 `258389.438 vs 258160.555 (old)  +0.09%, status=updated`，依次为本次吞吐、历史最优吞吐（均为 iter/s）、相对变化和状态。正号表示超过历史最优，负号表示下降，持平显示 `0.00%`，无有效测量显示 `n/a`。成功写入时以黄色显示 `status=updated`，新增较省显存的候选时显示 `status=retained`，沿用原记录时显示 `status=kept`。有可比的历史 95% 档时，发布区前的 `stage1_ntt_95_compare` 先列参数，再列「本次 batch、吞吐 vs 历史 batch、吞吐 (old)」，百分比按两档吞吐计算。左侧仅从本轮实际精测（含 Best 复测）取数：以本轮实测峰值为基准，选达到 95% 的最小实测 batch；缓存命中不计入。缺少本轮实测或历史基准时省略对比。黄色 `updated` 表示发布的 95% 批量或吞吐已变化，红色 `kept` 表示发布区沿用原记录，即使本轮实测批量或吞吐不同。首次调优直接发布。重定向输出和镜像日志使用纯文本，设置 `NO_COLOR` 可关闭终端强调色。

x-only 的采样池包含 64 个可重现的标量位。原生 Edwards 用指定 B1、w 编码完整 NAF。总长不超过 512 列时，全部列进入采样池。更长时按从高到低的列序等分为 8 段，各取居中连续的 64 列。调优按设备实测速率，从池中选择正式组使用的块长。

一次调优命令仅在首次需要测量时构造 B1 标量。每个 w 编码一次完整 NAF，保留选中的有符号列供整个命令的位宽、变换长度、批量和 Graph 候选复用。日志 `stage1_ntt_naf_sample` 每生成一份采样输出一次。复测使用本次请求的 B1，采样随新纪录一起写入。

Edwards 调优从射影中性点 `(0:u:u)` 开始。u 由固定种子生成，覆盖模数位宽且与模数互素，同一位宽和不同批量共用相同初值。这样首批倍点也处理一般位宽的坐标。代表指数构造曲线时若连续遇因子，调优使用四阶点 (1,0)，按交替出现的 (1,0) 和 (−1,0) 直接填充奇数倍点字典。该输入的吞吐是校准工作量的估计值。

调优器按一条曲线选择 GMP 或 GPU，生成奇数倍点仿射字典，供该轮各批量和 NTT 配置共用。生产与调优共用 `[stage1] ntt_naf_gpu_min_bits`，默认为 `"auto"`。GPU 准备空间超过预算时可改用 GMP。`stage1_ntt_dictionary` 在选择 GPU、大位宽或显式指定门槛时报告条目数、实际构造方式和 `setup_ms`。该耗时包括初值、曲线和字典准备，单独于表中计算 `iter/s` 的 GPU 迭代计时。[生产建表门槛和配置](STAGE1.md#cuda-全宽-ntt)

每个候选先在实际 batch 上试跑最短块。x-only 从 4 位起逐档翻倍。Edwards 的最短块约为池中相邻两次点加的平均间距，包含至少一个真实非零列（池中有非零列时）。更长的块按此长度翻倍，另有完整池可选。短块取连续片段，长块从至多 8 个位置取片段，选择时尽量使累计非零列比例接近整个池。相隔的片段各自结束零列 Graph，点状态沿用。

以试跑设备时间估算目标内能完成的列数，选择能容纳的最长档；最短档已超时就保留最短档。若选中更长档，再单独预热该档。设所选块实测为 t 毫秒，每个正式组连续执行 `max(1, round(100 × time / max(t, 0.001)))` 块，并受计步计数器上限约束。组间重置初始点，全部正式组结束后回放一块核对预热末点。每个正式组用一对 CUDA event 计时，建标量、建字典、建 Graph、短块试跑、预热、重置及末点读回均在吞吐计时区间外。

例如 x-only 选中 64 步、窗口为 16 时，每块启动 4 个 Graph。若该块预热实测 0.8 ms，默认每组回放 125 块，即每曲线 8000 步。窗口是每个 Graph 的步数上限。x-only 的正数尾段可独立建图；所选块短于窗口时，测到的是该尾段。原生 NAF 的连续零列使用 1、2、4 等二次幂长度的 Graph，非零列直接执行倍点和点加。例如 186 列含 26 个非零列时，最短块约 7 列。若这 7 列耗时 160 ms，默认正式组只执行一块。100 ms 是每个正式组的软目标，调优命令的总耗时还包含初始化、试跑及核对。

`sample_pool_steps` 是采样池列数，`block_steps` 是一块实际回放的列数，`timed_steps` 是每曲线每个正式组的列数，`repeats` 是正式组数。原生 Edwards 保存完整标量列数 `naf_columns`、一轮的非零列数 `sample_nonzero` 和所有正式组的 CUDA event 总时间 `total_device_ms`。聚合吞吐 `iter_per_s = 1000 × batch × timed_steps × repeats / total_device_ms`。各组的中位时间 `median_ms` 和标准差用于观察波动。控制台实测行在吞吐之后依次列出 dataflow 掩码（十进制）、每组实际/目标设备时间（ms）、每条曲线每组步数（`steps/group`）和每条曲线每个回放块的步数（`steps/block`）。两列步数相除即每组回放块数。末列 `radix5_layout` 显示混合长度的布局：`twiddle`（旋转因子）、`pfa-direct`（直接 PFA）、`pfa-coalesced`（合并访存 PFA）或 `pfa-coalesced+outer`（同时融合首趟二次幂 outer）。二次幂长度显示 `-`。原生 Edwards 每步对应一列 NAF，x-only 每步对应一个标量位。原生 Edwards 的 `group_ms` 取各组平均，x-only 取中位数。x-only 仍采用 `1000 × batch × timed_steps / median_ms`。`Single`、`Best`、`95%` 分别报告单曲线、峰值及达到峰值 95% 的最小实测批量。[GPU 回放和计时](../../src/ecm/stage1/cuda/ntt/ladder.cu) · [候选和采样](../../src/ecm/stage1/cuda/ntt/tune.cpp)

## Tune 文件

共享文件中的 `[ntt].matrix` 使用格式 18。Stage1 行按 `max_exp`、`length` 和其余决策条件排序。条件包括 GPU、批量、卷积与执行形状、曲线、NAF 窗口和数据流。第三列 `iter_per_s` 记录吞吐。相同条件的测量中，只有另一条记录的吞吐至少一样高、两项显存需求都不高于本条时，才能合并本条。这样，更快但需要更多显存的记录可以和较省显存的记录共存。吞吐与两项用量均相等时沿用先前的测量。

`ntt_memory_bytes` 是该次 NTT 自有设备缓冲总字节数，`naf_memory_bytes` 是其中字典频谱与建表设备工作区的字节数。复用时分别对照当前 NTT 有效预算和显式配置的 NAF 预算。`ntt_memory_mib` 每单位为 1,048,576 字节，`naf_memory_mb` 每单位为 1,000,000 字节。选型仍按当前指数检查形状和容量，实际分配超出预算时可缩小批量重试。旧表的总量取自 `owned_bytes`。旧行缺失的字典用量保持未知，与已知用量的行分别保留。生产与调优统一以 `reference_bits` 记录实测算术位宽，范围复用以 `p ≤ max_exp` 为限。`benchmark_kind` 随胜出测量写在环境列中，不参与决策键或排序。B1、版本和计时也随胜出的测量更新。显式续测仍检查采样协议、已测组数和目标时间。

各列仅在表中有值时输出，`log2_length` 由点数推导。旧文件加载时按长度表补齐上限并合并重复决策条件。显式调优在文件锁内原子写回转换结果，生产只读查表在内存中转换。Stage2 卷积与 CPU、并行等独立表保留各自的测量语义。旧版程序需要使用旧文件副本。

### Stage1 CUDA NTT 的 `dataflow` 默认值与启用条件

`[ntt].matrix` 的 `dataflow` 记录执行计划最终选用的标志，整列参与决策键比较。控制台的 `22112` 表示十进制掩码 22112，用 `(dataflow & 掩码) != 0` 判断某一位。常规 `-tune` 比较完整计划，混合长度还显式比较 radix-5 布局与逆向融合。其他各位随长度、批量和 tile 等条件选择。单独开关某一位的性能差异需要另行对照测量。[标志定义](../../src/ecm/stage1/cuda/ntt/ladder.h) · [调优与布局选择](../../src/ecm/stage1/cuda/ntt/tune.cpp) · [决策键](../../src/ecm/stage2/planning/tune_rows.def)

以下默认值对应常规生产和调优计划。`p` 是算术指数，`N` 是 NTT 点数，`batch` 是物理曲线数，tile 大小均以点计。“默认请求”表示先将该位加入候选掩码，最终置位还须满足本条的条件。内部实验掩码可替换默认请求；显式 radix-5 布局随后覆盖位 7、8，原生 Edwards NAF 随后清除位 0–2。底层调用未传控制对象时，初始请求掩码为 0。[默认请求与最终分派](../../src/ecm/stage1/cuda/ntt/ladder.cu)

#### x-only 阶梯运算

- **位 0 · `FusedMultiplyAdd`（1）**　默认请求。将 BB 并入乘积的逆变换输入，省去单独的 BB + AE 加法。乘积上界加上最大 digit 必须小于 NTT 素数；启用位 1 时按双倍乘积项数检查。
- **位 1 · `LooseDifference`（2）**　默认请求。仅用于加权卷积，在频域构造带模数偏置的 E = AA − BB。双倍项数须通过精确性检查，剩余预算还须容纳 N 个 64 位频谱元素。
- **位 2 · `DirectRoute`（4）**　默认请求。按当前标量位把归约结果直接写入目标 X/Z 槽，省去独立的坐标搬运。

#### 正逆变换与 radix-5 布局

- **位 3 · `PackedForward`（8）**　默认请求。仅在二次幂长度、没有外层 pass 时，将输入打包和整个正变换合在一个 tile 内核中。
- **位 7 · `PfaRadix5`（128）**　默认请求。混合长度使用素因子算法（PFA），通过 CRT 索引连接 radix-5 和二次幂变换。显式选择 twiddle 时清除此位。
- **位 8 · `CoalescedRadix5`（256）**　默认请求。依赖位 7，使用共享内存重排以合并全局访存。混合长度的自动布局默认选 pfa-coalesced；显式选择 pfa-direct 时只保留位 7。
- **位 9 · `InverseWarpInput`（512）**　默认请求。启用 warp 尾层且 tile 至少为 64 点时，在逆变换入口由每个 lane 读取两个系数。
- **位 10 · `ForwardTileInput`（1024）**　按形状自动启用寄存器输入内核。位 3 关闭时要求 tile 至少为 512 点。位 3 开启时要求 batch ≥ 24，同时 tile 为 2 点，或为启用 warp 尾层的 32、64、128 点。
- **位 11 · `ForwardTileCompact`（2048）**　按形状自动限制每块至多 256 个线程。默认要求位 3 开启、batch ≥ 24，且 tile 为 4–16 点或 256–1024 点。紧凑配置生效后，位 10 关闭或 tile 至少为 1024 点时才单独记录位 11。
- **位 13 · `ShortInverseTile`（8192）**　默认请求。使用无需共享内存的短逆 tile，要求二次幂长度、没有外层 pass、启用 warp 尾层且 tile 至多 32 点。多曲线批量均可；单曲线默认只对 N ≤ 8 或加权 N = 32 启用。
- **位 18 · `FixedWideInverse`（262144）**　原生 Edwards NAF 默认请求。加权变换在位 9 开启、tile 为 4096 点、N ≥ 8192 且 batch ≥ 24 时，使用固定大小的逆乘积 tile 内核。
- **位 19 · `FixedWideForward`（524288）**　原生 Edwards NAF 默认请求。加权变换在位 3 关闭、位 10 和 warp 尾层开启、tile 为 1024 点、N ≥ 5120 且 batch ≥ 24 时，使用固定大小的正向 tile 内核。
- **位 21 · `PackedWeightedOuter`（2097152）**　默认请求。加权二次幂变换可将输入打包与首个 radix-2、4 或 8 外层 pass 融合。要求位 10 开启，且满足其一：① N 为 4096、8192 或 32768，恰有一个外层 pass 且位 6 关闭；② N 为 262144，进位段数 > 128 且至少有一个外层 pass。某次输入有待处理段进位时，该次打包走常规路径。
- **位 24 · `Radix5InverseLimbSums`（16777216）**　默认走分离路径。混合长度的最短 digit 至少为 12 位时，精调在 PFA 扫描中试测融合五点逆变换、去权和 limb 汇集。生产可按已有的融合测量选用该路径。融合直接产出 limb 和，后续由现有的进位路径处理，因此替代位 12、14 和 22 所描述的归约。
- **位 25 · `Radix5ForwardOuter`（33554432）**　精调试测。要求原生 Edwards、加权混合长度、`pfa-coalesced`、位 10 开启，且首趟二次幂 outer 为 1–3 层。打包、五点正变换和首趟 outer 共用一块共享内存，支持段进位延迟到 pack。选型按调优记录重放。

#### 归约与进位

实现以 32 位字计数，每 256 个字为一段，末段向上取整。[分段常量](../../kernels/cuda/stage1_ntt_segments.cuh)

- **位 4 · `CachedCarry`（16）**　p ≤ 65536 时默认请求。加权归约在传播进位时缓存 limb 中间值，要求位 5 和位 20 均关闭，每曲线至多 8192 个 32 位字。
- **位 5 · `SegmentedCarry`（32）**　按规模请求分段传播进位。线性卷积在段数 > 32 时请求。加权卷积满足以下任一条件时请求，最终均须有足够显存保存段头。
  - 宽段条件：段数 > 14；或原生 Edwards NAF 且 batch ≥ 32，并满足 N = 8192 且段数 ≥ 13，或 N = 4096 且字数 ≥ 2560。
  - 提前分段：单曲线、p ≥ 53249 且 N 为 2560 或 5120；或任意批量、N = 5120 且 p ≥ 106497。
- **位 6 · `DeferredPack`（64）**　请求位 5 且为混合长度或单曲线时，默认一并请求。位 5 实际开启且位 3 关闭后，可把中间结果的段进位留给下一次打包处理。
- **位 12 · `FusedWeightedCarry`（4096）**　单曲线且满足 N = 2560、p ≥ 53249，或单曲线且满足 N = 5120、p ≥ 106497 时默认请求。实际要求加权卷积和位 5，在同一内核计算 limb 和与段进位信息。位 14 生效也会一并启用位 12。
- **位 14 · `CachedFusedWeightedCarry`（16384）**　原生 Edwards NAF 按长度请求共享内存缓存。N = 5120 时要求 p ≥ 106497 且 batch ≥ 8；其他长度采用位 5 的“宽段条件”。实际要求加权卷积、位 5 开启，且每块所需系数缓存大于 0、至多 16 KiB。
- **位 17 · `TightCarrySpans`（131072）**　原生 Edwards NAF 默认请求。加权卷积在 N ≥ 2560 且取得无符号系数紧上界时，用该上界缩短每个 limb 的系数读取范围。位 15 开启时按四倍上界计算；最终位宽小于 64 才置位。
- **位 20 · `WarpWeightedCarry`（1048576）**　默认请求。加权卷积在位 5 关闭、每曲线至多 32 个 32 位字且 N ≤ 64 时，用一个 warp 完成短归约与进位。
- **位 22 · `FixedCarryOffsets`（4194304）**　默认请求。仅在 N = 5120 且位 14 实际开启时，为缓存融合归约使用该长度专用的系数偏移计算。

#### Edwards 倍点与字典乘法

- **位 15 · `Edwards2XYFrequency`（32768）**　原生 Edwards NAF 默认请求。在频域组合出 2XY，要求加权卷积、位 9 开启、取得的无符号紧上界不超过 (NTT 素数 − 1) / 4，且预算可容纳 N 个 64 位模数频谱元素。
- **位 16 · `Edwards2XYInverseInput`（65536）**　原生 Edwards NAF 默认请求。位 15 开启时可把 2XY 组合直接并入逆 tile 输入。常规计划还要求二次幂长度、没有外层 pass 且 128 ≤ N ≤ 512。
- **位 23 · `DictionaryProductTile`（8388608）**　batch ≥ 8 时默认请求。原生 Edwards NAF 在位 9、21 均开启、tile 为 4096 点且 N 为 32768 或 262144 时，可融合正向 tile、字典频谱点乘和逆向 tile。仅对没有待处理段进位的字典乘法执行该内核。

**解读 radix-5 布局。** 对混合长度取 `dataflow & 384`，即只看位 7 和位 8。结果 0、128、384 分别对应 `twiddle`、`pfa-direct`、`pfa-coalesced`。置位 25 时显示 `pfa-coalesced+outer`。例如 22112、22240、22496 三条记录的其余位相同，分别使用这三种布局。二次幂长度的 `radix5_layout` 显示为 `-`。[布局名称与生产解码](../../src/ecm/stage1/cuda/ntt/tune.cpp)

## 生产选型

显式调优记录实际采样指数。生产缺测时在任务的实际 p 上分别调优每个可用类型和长度。生产输入即使落在同一 NTT 长度档，仍需满足下述查表条件。

Edwards 的 `edwards_naf_window_bits=0` 在当前 GPU 的兼容记录中优先比较精测和生产记录，按聚合 `iter/s` 选窗，再按窗口容量选择批量和 NTT 参数。只读模式缺少这些记录时可用粗测结果。直接指定物理批量时只比较该批量，拆批任务按任务规模和内存比较可行批量，随后按剩余曲线数选批。固定正数窗口只查该窗口。已有快照按保存的窗口和游标恢复。

沿用配置中的 `[stage2] tune_runtime_enabled`（默认 true，支持 worker 覆盖）。首次遇到缺少兼容记录的位宽时，CUDA Stage1 NTT 按当前任务的 B1、窗口和批量范围运行同一粗测与精测流程，再开始计算。关闭后只读选型，无匹配 NAF 时自动窗回退到 x-only。显式 `-tune` 可独立填表。

原生 Edwards 的分段采样行标记为 `stage1_naf_stratified`，其中 `b1` 记录采样来源。显式调优、自动选窗、选型和拆批可跨 B1 复用该类记录。仍须匹配 GPU、曲线、NAF 窗口、变换长度、digit 位宽及执行形状，且当前预算须能容纳批量。显式调优还检查计时方式、已测组数和目标时间，增大 `time` 只补测精度不足的候选。只读生产优先使用执行形状吻合的测量；仅有同长度记录时，按实际指数重新校验长度、执行形状与预算后才用作估计。x-only 连续回放使用 `stage1_graph_replay`。Stage1 和 Stage2 共用 tune 文件时，两端都需要能读取对应采样字段的版本。

0.72.1 起可直接沿用扩容前的调优表。65,536 点加权和 131,072 点线性或加权的旧记录保留当时的上限 `max_exp=1048576`，包括显式指定的 131,072 点加权计划。格式 17 之前的表若缺少该列，按当时的上限补齐。新位宽的测量使用当前尺寸表的上限，可与旧记录共存。

新采样用 `sample_phase=1` 表示粗测，`sample_phase=2` 表示精测，`repeats` 独立记录组数。共享自适应采样表时，Stage1 和 Stage2 均须支持格式 18（从 0.72.13 起）。生产选型可读取旧版的整块采样记录。显式调优会按当前协议重新测量。0.71.3、0.71.4 和标记为 `0.72.0` 的预览构建写入的兼容旧采样仍可读取，旧行以 3 组识别粗测、5 组识别精测。重跑时匹配阶段和该阶段的组数，例如从 `2:2` 改为 `2:5` 可复用兼容的两组粗测。提高 `ntt_max_batch` 后，容量改变的窗口重新比较，复用仍适用的样本。

跨 B1 复用时，表中吞吐对应来源 B1。目标 B1 的非零列分布和实际访问的字典槽会变化，窗口排名也可能改变。要独立比较指定 B1 的最佳窗口，可将该次显式调优的 `tune_file` 指向单独的空表。

自动拆批按当前预算筛选候选，合并比较调优与生产实测的 `iter_per_s`。配置 `[stage1] ntt_batch_target_percent`（1–100，默认 95）选择吞吐**大于等于**可行峰值指定百分比的最小实测批量。设为 100 时只选择峰值，多个批量并列取最小者。只有查表后没有可用记录、已配置调优文件、运行时学习开启且剩余曲线数超过容量时，才按当前容量试跑一个真实子批，完成的曲线计入任务。生产样本的 `curves_per_s` 包含标量准备到归一化，部分恢复批次不进入完整排名。日志中 `stage1_ntt_runtime_tune` 表示补测，`stage1_ntt_naf_selection` 表示自动选窗，`stage1_ntt_batch_selection` 和 `stage1_ntt_selection` 给出批量和卷积来源。

以活跃批量 B、指数 p、NTT 长度 L 计，主数组需要 `88·B·L + 92·B·ceil(p/32)` 字节，此外还有标量、NTT 常量表和加权表。申请前核算显式分配，Graph 上传后及同步执行后用 `cudaMemGetInfo` 采样空闲显存差；两者较大值写为 `peak_bytes`。观测值以 CUDA 上下文就绪后的空闲显存为基准，受同设备其他进程和驱动分配粒度影响。

线性卷积从 31 到 16 选择最大可用 digit 位宽 `b`，令 `c = ceil(p/b)`，要求 `c·(2^b−1)² < q`，再取覆盖 `2c+1` 的最小二次幂。加权卷积依次检查二次幂与表中的七个混合长度，要求 `N ≤ p`、`b = ceil(p/N) ≤ 31`。保守界为 `2N·(2^b−1)² < q`，原生 Edwards 还能使用规范乘积的 `U(p,N) < q`。这里 `q = 2^64−2^32+1`。长短 digit 的周期随 `gcd(p,N)` 变化，因此个别超出连续上限的指数仍可单独通过系数界。涉及 2XY 频域组合时另查 `4U < q`。[整数系数判定](../../src/ecm/cuda/ntt/shape.cpp#L2) · [2XY 融合条件](../architecture/NTT.md#edwards-2xy-第一层频域融合)

`ntt_convolution="auto"` 通常还会比较线性、加权二次幂及能缩短变换的加权混合候选。原生 NAF 的最短档若依赖收紧界，仍与其余合法计划按 NAF 列吞吐比较。混合长度均可采用 radix-5 分解，PFA 是同一长度的互素分解实现；可比较传统 twiddle 与 PFA 的置换成本。显式长度、digit 位宽或 tile 会改变准入条件。[生产候选](../../src/ecm/stage1/cuda/ntt/tune.cpp) · [radix-5 实现](../../kernels/cuda/stage1_ntt_radix5.cuh)
