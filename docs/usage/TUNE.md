# CUDA Stage1 NTT 调优

```text
-tune [ntt][,exp=P|,length=L][,naf=W][,batch=B][,time=N] [B1]
```

所有字段均可省略，字段值留空也使用默认值。以下示例中引号把逗号串作为一个参数传给 Windows 程序。省略 `ntt` 时也可直接写第一个字段。末尾的 B1 默认 128，原生 NAF 使用该 B1 的生产标量。

```powershell
.\ecm_cuda.exe -tune
.\ecm_cuda.exe --param e -tune "exp=65521,naf=6-8,batch=1-16,time=2" 4096
.\ecm_cuda.exe -tune "ntt,length=2560-4096,batch=8" -d 1
.\ecm_cuda.exe --param m0 -tune "ntt,exp=8191,batch=1"
```

- `exp` 是承载指数 p，取 32–1048576。单值按该指数比较所有可用卷积族。给闭区间时，按生产规则枚举区间涉及的线性二次幂、加权二次幂和加权混合长度。每个“卷积族、长度”取区间内首次选中它的 p，在每个指定 NAF 窗口下调优一次。例如固定线性卷积时，`exp=3554-3560` 只调两档：p=3554 的 256 点和 p=3557 的 512 点。省略 `exp` 时按整个支持域挑选代表指数。
- `length` 是变换点数，接受单值或闭区间，仅保留生产规划器选出的匹配长度。支持的二次幂和五档混合长度见下表。`exp` 和 `length` 同时出现会报错。
- `naf` 适用于 Edwards，显式取 2–12 内的单值或闭区间，包含奇数。省略或填 0 时筛选 6、8、10、12，即使生产配置固定了窗口也执行该筛选。命令行 `--naf-w W` 可固定一个窗口。Montgomery PARAM0 按 x-only 测量。
- `batch` 是并行曲线数，取 1–128。单值只测该批量，范围约束粗测、精测和邻档搜索。省略时在全部可容纳的批量中自动搜索。`--tune-exhaustive` 逐批精测所有可用形状。只有显式给出非空 `batch=` 值才保存全部已测批量，包括显式 `batch=1-128`。
- `time` 是正数倍率，默认 1。小数按最接近的毫秒取整，目标至少 1 ms。每个正式组的目标设备时间为 `100 × time` ms。`time=2` 对应粗测 3 × 200 ms、精测 5 × 200 ms。另可用 `--tune-seconds N` 限制整个命令启动新测量的墙钟预算。正在测的候选会完成并写表。
- `--tune ntt --bits P` 仍可用于单一指数。显式的卷积、长度、tile、outer、Graph 和 profile 设置约束候选。共享表由 `[shared] tune_file` 指定，默认在配置文件旁的 `tune.toml`，支持按 worker 覆盖。

## 采样与吞吐

粗测比较允许的最小批量、内部批量和容量上限。实际分配失败时二分缩小容量。单曲线（或指定下界）和总吞吐接近领先者的形状进入精测，比较 tile、outer、每 Graph 4、8、16、32、64 步、倍增批量和峰值邻档。混合长度比较 twiddle radix-5、直接 PFA 和合并访存 PFA。容量同时考虑设备工作区、NAF 字典、主机内存及剩余曲线数。

默认搜索结束后，每个 GPU、NAF 窗口和同一组 NTT 候选最多保存四种并行数。日志中的 `Single` 是单曲线，`Max` 是当前预算下实际通过测量的最大批量，`Best` 是精测吞吐最高的批量，`95%` 是精测中达到该峰值 95% 的最小批量。多个角色落在同一批量时合并。入选批量保留已测的粗测、精测和执行变体，因此表中可能有多行。显式批量记录和生产观察可独立保留。

容量、搜索方式和计时精度满足同一搜索条件时，重跑直接报告已保存的结果。容量变化或要求更高精度时，重新搜索并复用仍适用的候选。完成后原子替换该搜索的自动记录。限时或中断时，以 tune 文件名加搜索标识及 `.partial` 保存续跑所需的中间测量，同条件搜索完成后清除临时文件。旧表缺少自动与显式批量的来源标记，保留原有行。

x-only 使用 64 个可重现的标量位。原生 Edwards 用指定 B1、w 编码完整 NAF，至多采 512 列。总长不超过 512 列时全部执行。更长时按从高到低的列序等分为 8 段，各取居中连续的 64 列，按原顺序回放。连续零列按生产规则走二次幂 Graph，非零列执行倍点和点加。相隔的采样片段各自结束零列 Graph，点状态沿用。

一次调优命令仅在首次需要测量时构造 B1 标量。每个 w 编码一次完整 NAF，保留选中的有符号列供整个命令的位宽、变换长度、批量和 Graph 候选复用。日志 `stage1_ntt_naf_sample` 每生成一份采样输出一次。全部命中已有测量时跳过标量构造和分段。

将选出的所有列合为一轮。预热一轮，测得设备时间 t（ms）。每个正式组连续执行 `max(1, ceil(100 × time / max(t, 0.001)))` 轮，并受计步计数器上限约束。一轮已经超过目标时只做一轮。组内延续点状态，组间重置初始点。粗测 3 组、精测 5 组，最后再执行一轮核对预热末点。每个正式组用一对 CUDA event 计时，建标量、建字典、建 Graph、预热、重置、核对片段和末点读回都在吞吐计时区间外。

例如 x-only 片段长 64 步，窗口为 16，每个片段启动 4 个 Graph。假设预热实测 0.8 ms，默认每组连续运行 125 个片段，即 500 次 Graph 回放、每曲线 8000 步。原生 NAF 的回放数还取决于该片段连续零列的分布。100 ms 是根据预热估算的目标，表里保存实际设备时间。

`block_steps` 是一轮采样列数，`timed_steps` 是每曲线每个正式组的列数，`repeats` 是正式组数。原生 Edwards 保存完整标量列数 `naf_columns`、一轮的非零列数 `sample_nonzero` 和所有正式组的 CUDA event 总时间 `total_device_ms`。聚合吞吐 `iter_per_s = 1000 × batch × timed_steps × repeats / total_device_ms`。各组的中位时间 `median_ms` 和标准差用于观察波动。x-only 仍采用 `1000 × batch × timed_steps / median_ms`。`Single`、`Best`、`95%` 分别报告单曲线、峰值及达到峰值 95% 的最小实测批量。[GPU 回放和计时](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu) · [候选和采样](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp)

## 生产选型

范围调优的记录保存实际测量的代表指数。生产输入即使落在同一 NTT 长度档，仍需满足下述查表条件。要比较某个 p 的所有候选或补齐它的记录，可指定单值 `exp=P`。

Edwards 的 `edwards_naf_window_bits=0` 在当前 GPU 上取兼容记录中聚合 `iter/s` 最高的 NAF 窗口，然后按该窗口的容量选择批量和 NTT 参数。直接指定物理批量时只比较该批量，拆批任务按任务规模和内存比较可行批量，随后按剩余曲线数选批。固定正数窗口只查该窗口。已有快照按保存的窗口和游标恢复。

沿用配置中的 `[stage2] tune_runtime_enabled`（默认 true，支持 worker 覆盖）。首次遇到缺少兼容记录的位宽时，CUDA Stage1 NTT 按当前任务的 B1、窗口和批量范围运行同一粗测与精测流程，再开始计算。关闭后只读选型，无匹配 NAF 时自动窗回退到 x-only。显式 `-tune` 可独立填表。

原生 Edwards 的分段采样行标记为 `stage1_naf_stratified`，其中 `b1` 记录采样来源。显式调优、自动选窗、选型和拆批可跨 B1 复用该类记录。仍须匹配 GPU、曲线、NAF 窗口、4096 位区间、变换长度、digit 位宽、进位段数、carry 位数、均匀性及执行形状，且当前预算须能容纳批量。显式调优还匹配程序版本、计时方式、组数和目标时间，增大 `time` 只补测精度不足的候选。旧的原生单片段合成记录和完整生产样本仍按原 B1 参与生产选型。x-only 连续回放使用 `stage1_graph_replay`。Stage1 和 Stage2 共用 tune 文件时，两端都需要能读取对应采样字段的版本。

跨 B1 复用时，表中吞吐对应来源 B1。目标 B1 的非零列分布和实际访问的字典槽会变化，窗口排名也可能改变。要独立比较指定 B1 的最佳窗口，可将该次显式调优的 `tune_file` 指向单独的空表。

自动拆批优先使用同条件完整生产样本的 `curves_per_s`，再参考合成 `iter_per_s`。取达到同类峰值 95% 的最小实测批量。运行时学习开启且剩余量超过容量时可用真实子批试跑，完成的曲线计入任务。生产样本的 `curves_per_s` 包含标量准备到归一化，部分恢复批次不进入完整排名。日志中 `stage1_ntt_runtime_tune` 表示补测，`stage1_ntt_naf_selection` 表示自动选窗，`stage1_ntt_batch_selection` 和 `stage1_ntt_selection` 给出批量和卷积来源。

以活跃批量 B、指数 p、NTT 长度 L 计，主数组需要 `88·B·L + 92·B·ceil(p/32)` 字节，此外还有标量、NTT 常量表和加权表。申请前核算显式分配，Graph 上传后及同步执行后用 `cudaMemGetInfo` 采样空闲显存差；两者较大值写为 `peak_bytes`。观测值以 CUDA 上下文就绪后的空闲显存为基准，受同设备其他进程和驱动分配粒度影响。

线性卷积从 31 到 16 选择最大可用 digit 位宽 `b`，令 `c = ceil(p/b)`，要求 `c·(2^b−1)² < q`，再取覆盖 `2c+1` 的最小二次幂。加权卷积依次检查二次幂与表中的五个混合长度，要求 `N ≤ p`、`b = ceil(p/N) ≤ 31`。保守界为 `2N·(2^b−1)² < q`，原生 Edwards 还能使用规范乘积的 `U(p,N) < q`。这里 `q = 2^64−2^32+1`。长短 digit 的周期随 `gcd(p,N)` 变化，因此表中保留单点。涉及 2XY 频域组合时另查 `4U < q`。[整数系数判定](../../src/ecm/cuda/ntt/shape.cpp#L2) · [2XY 融合条件](../architecture/NTT.md#edwards-2xy-第一层频域融合)

`ntt_convolution="auto"` 通常还会比较线性、加权二次幂及能缩短变换的加权混合候选。原生 NAF 的最短档若依赖收紧界，仍与其余合法计划按 NAF 列吞吐比较。混合长度均可采用 radix-5 分解，PFA 是同一长度的互素分解实现；可比较传统 twiddle 与 PFA 的置换成本。显式长度、digit 位宽或 tile 会改变准入条件。[生产候选](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp) · [radix-5 实现](../../kernels/cuda/stage1_ntt_radix5.cuh)
