# GUI v2

GUI v2 是独立的 Windows / C++ / Dear ImGui 前端，当前候选版本0.51.5，默认使用DX11，Vulkan仅保留为显式选择的诊断后端。两种后端共用同一套现代布局、控件、图表、语言与宠物。原GUI的源码、默认值、二进制和构建入口保留。阶段证据与限制见 [实施草稿](../development/GUI_MODERNIZATION_DRAFT.md) 和 [离线 HTML](../web/gui-v2-vulkan-plan-20261021.html)。

## 构建与启动

运行 `tools\build\build_gui_v2.bat`，默认生成 `build_gui_v2_local/ecm_gui_v2.exe`、群阶分析助手 `ecm_group_order_ui.exe` 及其 `gmp-10.dll`。测试入口 `tools/build/test/build_gui_v2.ps1 -BuildDir <独立目录> -TestHelpers`；测试夹具不进入默认交付目标。根开关 `ECM_BUILD_GUI_V2` 默认 OFF，与旧 GUI 独立。需要 MSVC/CMake、GMP 及仓库固定源码，构建无需开发 Vulkan SDK、CUDA 或浏览器运行时。独立 helper 默认复用 `third_party/gmp-zen3/dist`；本机候选的 Zen3/BMI2 DLL 不能据此声明适用于所有 x64 CPU，依赖和源码交付见 [说明](../../src/ecm/application/gui_v2/GROUP_ORDER_DEPENDENCY.md)。

运行要求Windows 10 1903+ / Windows 11 x64、匹配的Microsoft Visual C++ x64 runtime和DX11驱动；硬件不支持时尝试系统WARP。默认启动不初始化Vulkan、不加载Vulkan loader，也不需要Vulkan SDK。构建仍携带可选后端的固定头文件与Volk。

未传`--config`时，自动查找并载入`ecm_gui_v2.exe`同目录的`ecm.toml`，不受快捷方式“起始位置”或当前工作目录影响。不存在时保持GUI打开并提示选择工作流；存在但内容有误时显示加载错误。显式`--config`优先，指定文件失效时不会退回旁边的另一份配置。工作流路径确定后再选择对应的UI侧车，自动发现和显式打开同一配置使用相同身份。按该配置的`workers.N.autostart`执行自动启动。

常用参数：

- `--config <工作流.toml>`：打开已有业务配置；设置中也可选择。autostart 经过能力与拥有权检查后执行。
- `--ui-state <侧车.toml>`：默认 `%LOCALAPPDATA%/ECM-ELF/gui-v2/<配置身份>.toml`；按启动配置身份隔离，与业务文件分离，非法侧车保留并禁止覆盖。
- `--theme dark|light`、`--language en|zh`、`--ui-scale 1|1.25|1.5|2`：初始外观；设置可选自动 DPI。
- `--pet` / `--no-pet`、`--pet-static`：宠物及动画覆盖，默认关闭。
- `--pet-skin classic|miss_pink_elf|herrscher_of_human_ego|hi_love_elf`：初始ELY皮肤覆盖；配合`--pet`启用，默认保持Classic ELY。
- `--no-nvml`：关闭可选的 500ms 后台 GPU 监控。
- `--renderer dx11|vulkan`：默认dx11；仅显式选择vulkan时要求系统Vulkan 1.1 loader、graphics/present与swapchain驱动。
- `--single-viewport`：保持所有 ImGui 面板在主窗口内，当前默认模式。
- `--multi-viewport`：显式启用可移出主窗口的原生独立面板；设置中也可启用，重启生效。
- `--renderer vulkan --trace-render --diagnostics <文件>`：可选记录Vulkan等待/提交/呈现的进入和返回、单调时钟与UTC对应；逐调用写盘有额外开销，不用于性能门禁。
- `--diagnostics <文件>`、`--version`：诊断路径与独立前端版本。

设置从导航底部的固定齿轮入口、顶栏“设置”或`Ctrl+,`打开，不替换当前中央页面，不参与页面拖动排序或右侧标签。它是主窗口内独立的非停靠ImGui弹窗，保持DX11单窗口默认模式；可拖动、调整尺寸、最大化/还原，通过右上角关闭、“完成”或非文本输入时的Esc关闭。弹窗位置和大小在会话中保留，重新启动不自动打开；读取旧侧车的页面5时兼容打开弹窗并回到实际中央页，旧右侧设置位自动移除。

弹窗左侧按“外观、布局与交互、监控、ELY宠物、工作流与引擎、计算设置”分为六组，右侧单独滚动；窄窗口或大字号时改为顶部分类选择，避免两栏挤压。分类和页面按钮使用同一套线性图标、圆角、悬停与选中样式。图标由程序绘制，无图片、图标字体或浏览器依赖。外观提供现有深色/浅色两张主题预览卡片，保留当前两种主题，不增加截图中的其他配色包。

控件按下与选中底色略提亮：暗色active由`#3f3f3f`调整为`#4a4a4a`，亮色由`#e9e7e5`调整为`#ebe9e7`；主按钮按下时在自身强调色上小幅提亮，保持原有文字配色。

[离线图标图鉴](../web/gui-v2-icons.html)展示当前`Icon / line_icon`的全部17种图案及`None`，支持名称/用途搜索、分类、选择、尺寸与明暗预览、复制标识；选择仅用于预览与沟通，不修改程序映射或配置。图形源码位于`src/ecm/application/gui_v2/ui/icons.h`，通过`ImDrawList`组合线段、圆角矩形、16段圆、三角形与三次贝塞尔曲线；24×24坐标、线宽为显示尺寸的1.6/24。图鉴由`tools/gen/render_gui_v2_icons.py`执行同一C++绘制函数并记录SVG，`--check`检查同步，生成需要MSVC，浏览不需要。浏览器抗锯齿与圆角实现不等同于原生像素；组件样本中的旧`ui::icon`绘制及固定窗口控制图形不属于该可选集合。

“开始”和“全部开始”共用`Icon::Play`圆角空心三角形，通过连续闭合路径及三处贝塞尔曲线形成圆角，保持统一描边并随DPI缩放；网页图鉴同步导出同一形状。

外观中的语言使用按实际XML文件名显示（省略.xml后缀）的下拉列表，DPI比例使用可点击标签；“字体大小”支持10–30逻辑像素，即时生效，默认15。正文和日志共用基准字号，标题按22/15比例调整，DPI独立。主按钮偏移0到+6、默认+1，辅助文字偏移-6到0、默认-2，实际字号至少8逻辑像素；不会重复载入字体文件。中文字体不可用时回退英文。布局与交互中设置平滑滚动、外部面板、标题栏和Toast；监控组设置GPU图表时间范围；ELY宠物组设置开关、动画及皮肤。底部“保存界面偏好”在各分类共用，正常退出同样保存，关闭弹窗只隐藏设置，不丢失会话中的修改。

工作流与引擎组提供工作流打开/重载、worker程序路径及数量，数量0跟随工作流；相对程序路径优先工作流目录，其次前端目录。计算组支持按配置键或英中说明搜索、按共用/Stage1/Stage2/Worker筛选，显示匹配、空状态以及准确分区的类型与范围。布尔及0/1开关使用复选框，其他数值保留精确文本输入。暂存、保存、重载分开；计算修改须显式“保存工作流”或使用“视图 → 保存布局与配置”，复核文件指纹并保留未改行/注释，外部修改须重载。运行中禁用编辑，未保存编辑禁止启动。切换分类或关闭弹窗不会自动保存、丢弃业务草稿；UI保存不改旧`[gui]`。


界面文案使用与原版相同格式的外部XML，固定从exe旁`localization/v2/`载入。设置和顶栏语言菜单扫描该目录，按实际XML文件名列出，展示时省略末尾.xml后缀，不限定为两个语言开关；重新打开列表会发现新增和删除的文件。可复制现有界面XML为新文件名后修改，在列表中选择即可应用，无需编译；选择仍以含.xml后缀的完整文件名保存于`ui.language_file`，重启恢复，旧侧车空值按`ui.language`的en/zh迁移。编辑当前文件后用“重新载入语言文件”应用；缺项回退英文基线，非法格式参数、重复键、非界面XML或路径越界拒绝替换当前词典。启动时所选文件损坏则使用英文并提示，原选择保留供修复。`english.xml`与`options.english.xml`是必要基线，其他语言可配套`options.<界面文件名>`，缺配套说明时使用英文计算说明。`options.*.xml`不会出现在界面语言选择中，现有两份由配置schema生成，不手动修改。默认界面键使用可读名称，如`action.start`、`worker.progress`、`message.workflow_opened`，不使用哈希后缀或数字消息编号；已有旧键词典通过别名兼容，无需重写。旧键与新键同时指向同一项会按重复键拒绝，格式保护同样有效。非英文文件使用现有CJK字体路径，字体缺失时仍回退英文并提示。格式、回退及两种语言的范围见[语言资源说明](../../src/ecm/application/gui_v2/localization/README.md)。旧GUI的语言文件保持独立，原始计算日志不翻译。

系统标题栏默认隐藏，最小化、最大化/还原和关闭按钮位于应用顶栏右侧，顶部空白区域可拖动窗口，边缘仍可缩放；关闭仍走原有安全停止流程。可在“视图 → 系统标题栏”或“设置 → 显示系统标题栏”恢复原生标题栏。选择保存在独立侧车的`window.title_bar`，正常退出或保存界面偏好后恢复；保留已有显式选择，旧侧车缺少此项时使用新的隐藏默认值。

## 导航与布局

导航按钮带统一的18逻辑单位线性图标，最小高度40逻辑单位、纵向间距8、圆角8，悬停和选中均显示圆角矩形背景，尺寸随字号和DPI缩放。导航栏侧边留白为8逻辑像素，禁用横向和纵向滚动及滚动条；鼠标滚轮、触控板和旧布局的滚动偏移不会移动导航内容。按钮宽度限制在栏内，长名称按实际字体省略，悬停显示完整名称；矮窗口收紧行高和间距、隐藏辅助说明，底部设置入口保持固定。按住页面至少约0.32秒后拖到另一项上方或下方可排序，插入线提示位置；快速点击或拖划不会启动排序。六个实际页面的顺序保存为`ui.nav_order`；为兼容旧侧车，仍存七个编号的排列，设置编号5保留但不参与排序，移到右侧的页面仍保留在顺序中，关闭返回时按该位置排列；非法或重复页面编号不会覆盖侧车。

导航项右键选择“移到右侧标签页”，或长按后拖到导航底部的“右侧标签页 >”按钮。移入的页面从左侧导航移除，直接在右侧停靠区显示内容；多个页面共用原生横排标签，可点击切换、逐页关闭。关闭标签会自动回到左侧导航，保留当前中央页面；移动与返回只调整对应的原生停靠窗口，不重建整个布局，保留导航宽度及其他区域的手动尺寸。最后一个右侧页关闭时，空停靠区可自然合并。没有额外的“工具”总窗口、“移回导航”按钮或左下返回按钮。至少保留一个实际中央页面，中央与右侧不会同时编辑同一页。右侧页面仍可通过原生停靠标签重新停靠或浮动，窄区域的内容可滚动。

设置“布局与交互”组中的“导航与右侧标签页”区域也可选择页面位置、恢复默认停靠布局。原“显示工具栏”开关移除；旧侧车`ui.right_visible`仅为读取兼容保留，移到右侧的页面直接显示。含旧工具容器的保存布局会重建为页面原生标签。拖动面板标题或标签可以在主窗口内重新停靠、调整分栏或浮动；中央切页回到顶部，右侧每个页面保留各自的会话滚动位置。

默认使用DX11，首次布局将面板保留在主窗口内部；在“允许面板移到应用窗口外（重启生效）”或命令行显式启用后，可跨显示器浮动。RTX4070 Ti双屏环境的一轮DX11内部/独立面板图表拖动、缩放和最小化恢复检查通过，用户确认该轮未观察到冻结；不能据一次短测承诺长期稳定性。

可选Vulkan路径尚有未解决的桌面画面冻结：外屏与内屏同时停止更新、鼠标仍可移动、时钟停走，恢复后输入体现效果；曾捕获547ms和1000ms的present等待，根因未确定。该路径未通过冻结验收，已停止在受影响桌面反复拖动复测。CPU帧耗时或API验证均不能替代实际桌面刷新判断；DX11路径不据此宣称Vulkan已修复。

视图菜单提供检查区、日志、保持日志页面可见和系统标题栏开关；底部用横线分隔“保存布局与配置”，不提供重置布局入口。日志显隐不重建全局布局，保留导航宽度、中央页面和右侧标签停靠；隐藏释放日志区域，重显时优先恢复仍存在的停靠节点，原节点已折叠则只在工作区下方重建日志区域，原浮动日志保持浮动。

日志默认跟随可见的Workers管理页：中央Workers页或右侧当前显示Workers时显示，切换到其他视图自动隐藏。自动隐藏不改变保存的`ui.logs`启用偏好，也不停止日志收集或计算控制。在其他视图手动打开日志仅对当前视图停留生效，换页恢复自动规则；在Workers管理页手动关闭则保留关闭偏好。“视图”及“设置 → 布局与交互”提供“保持日志页面可见”，开启后已启用日志跨页可见，该选择保存为`ui.logs_keep_visible`。

导航、工作区和右侧停靠区的原生“Hide tab bar”分别保存为`ui.nav_hide_tab_bar`、`ui.workspace_hide_tab_bar`、`ui.right_hide_tab_bar`。正常退出或显式保存后重启恢复；日志收起/展开和响应式布局重建继续沿用对应区域偏好。右侧有多个标签时保留原生横排标签栏，恢复单标签后重新使用原隐藏选择。旧侧车未提供这些字段时，第一次从已载入的原生布局读取选择；不覆盖原有隐藏状态。

界面偏好文件保存导航顺序、页面位置、右侧选中项和 ImGui 布局；正常退出保存，也可显式“保存界面偏好”或“视图 → 保存布局与配置”。显式保存记录当前窗口位置、尺寸和最大化状态，最小化时保留先前正常尺寸。后一入口还保存已暂存的计算配置，沿用停止状态和外部文件指纹校验；没有计算修改时不改写工作流。计算保存失败则不继续覆盖侧车；两个文件分别保存，侧车后续写入失败会显示错误，不将已成功保存的计算文件回滚。计算设置与原 GUI 配置独立。旧侧车缺少新增字段时沿用默认值；非法侧车继续保留原文件并禁止覆盖。

退出沿用工作流的`exit_confirm`和`graceful_stop_ms`：无运行任务时直接退出；ask居中确认，支持取消按钮/Esc和停止并退出/Enter；stop直接进入等待；kill按显式配置立即终止。等待窗口区分Stage1检查点与Stage2当前曲线完成，显示剩余秒数、逐worker状态及超时终止提示；强退按钮/Esc不再等待新检查点。重复关闭或重复停止退出不会延长既定截止时间。最小化窗口收到关闭请求后，仍需确认或等待时恢复窗口显示进度。共享Controller及旧GUI实现不改。

## 队列、页面与宠物

即将执行的计算worker须支持队列协议：`--gui-queue-protocol`返回`ECM_QUEUE_OWNER=1`。纯Stage2任务不要求未使用的Stage1同时升级，反之亦然；自动切换阶段时，在下一套引擎启动前检查其协议，不支持则停留在已停止状态并提示具体路径，GUI继续工作。协议查询只确认worker声明支持的版本；实际互斥由运行期间持有的文件锁完成，防止重复计算同一分区和并发争用检查点/完成记录。共用入口的进程级文件区间锁覆盖 worker 生命周期，同一队列的相同分区拒绝重复运行，不同分区可并行；全队列与各分区互斥。崩溃由系统释放锁，持久锁文件不能手工删除绕过占用。原 GUI 必须指向更新 worker 才能参与保护；任意旧计算二进制不遵守新锁，v2 会拒绝启动。算法、曲线、param、sigma 及工作流格式不变。

任务表按编号（#）、操作、名称、状态、设备/引擎、任务进度、每曲线耗时、ETA、完成/命中组织九列；编号独立放在最左侧，名称列只显示工作流中的名称，不再拼接编号。单个worker的圆角启停按钮位于编号右侧；标题与全部开始/安全停止组成紧凑工具行，两按钮按两种字体及本地化文字中较大尺寸统一宽高，保留主次配色和字号，配置路径可悬停标题查看。默认15字号、100%比例时，任务按钮高24、主数据行高约36逻辑单位；全部与单任务的开始/停止按钮分别带播放三角和停止方块线性图标，图标与文字作为一组居中，窄单元格内省略文字且保留完整提示；大字号自动扩展。设备/引擎在所属单元格内单行显示，如`GPU0 / S1`、`CPU / S2`，完整引擎/设备/曲线信息与重复GPU提示可悬停查看。状态使用色标，文字和按钮保留单元格内外留白。任务摘要独占下一整行，以不透明背景覆盖列网格；Stage2说明固定为三条逻辑行：第一行为任务及已知因子标记；第二行为曲线名称、适用时的param、B1、B2及sigma；第三行只显示当前阶段。Montgomery显示已知param，Edwards省略param；缺失数值显示`--`。已应用配置中的非零`b2_ratio`与实际B1/B2乘积一致时，第二行展开为`B2=5000*B1=1300000000000`；未使用ratio、结果不匹配或尚未取得完整数值时直接显示`B2=数值`，不从B1/B2的整除关系反推ratio。ratio读取与worker相同的配置覆盖投影，只影响显示。较窄区域可换行，表格预留高度使用同一说明文本计算，保持整行覆盖网格。进度保留完成/总曲线数与百分比，恢复状态明确标注；表格ETA只显示秒数，如`150 s`。未取得耗时样本时显示`--`，不伪造零耗时和零ETA。表格按全部行与摘要的完整高度撑开，不按剩余视口截短，不再提供内部纵向滚动；始终采用单行九列信息＋下属整行文字说明，窄窗口也不拆为卡片或多行字段。宽度充足时保留各信息列的优先宽度，由进度列填充剩余空间；宽度不足时编号保留固定宽度，其余列按比例伸缩并减小水平留白，不引入内部横向滚动。长名称、状态、进度或数值在各自单元格内省略，悬停可查看完整值；下属任务与阶段说明允许按整行宽度换行。启停按钮保持紧凑，不随列宽填满整格。窗口放不下全部内容时，统一滚动整个工作区。停止过程中禁用重复操作。

曲线耗时图位于任务工作区的表格下方，区域右上角的线性图标按钮可切换列表（一行一图）与双列（一行两图），始终按worker顺序显示全部图表，包含名称和阶段，不依赖选中任务或日志页签。选择保存在独立侧车`ui.worker_chart_columns`，默认列表；工作区宽度不足360个随正文字号缩放的逻辑单位时临时使用单列，放宽后恢复保存的双列选择。图表基础高度88逻辑单位，较窄时图例可增加一行；保留横轴采样序号及整数刻度，单位秒/曲线，悬停显示采样值。使用各worker已有的耗时历史，无样本时保留标题和等待说明；图表较多时在工作区滚动查看，不额外采集数据。

日志以“管理器”和每个Worker的原生停靠窗口并列显示，不再包含第二层日志页签；页签可拖动停靠，旧日志区域的稳定窗口ID继续保留。任务表选择与日志/检查区联动；页签显示当前任务、进度、每曲线耗时与ETA，ETA同时显示秒数和约化时间，如`150 s (2 m 30 s)`。Stage2用单行显示已解析的`B1=…  B2=…  S=… bits  D=…  P=…`，缺失数据为`--`。Stage2第三行只显示阶段，附批次与阶段剩余秒数，不重复首行曲线计数；第四行常驻当前曲线的分阶段进度条，铺满上层容器可用宽度，随面板伸缩保持区段比例。停止请求说明将等待当前曲线完成。日志不再放置耗时图。工具行提供日志目录入口，空间允许时显示文件名，完整路径可悬停查看。各Worker的原始输出、跟随及滚动位置在会话内独立；既有侧车`ui.raw_log`/`ui.follow_log`记录最后一次选择，作为新页签及下次启动的默认值。开启跟随时停靠在底部；手动向上翻阅不会被强制拉回，返回底部后继续跟随。日志正文与UI正文使用相同字体族、字号和DPI比例，避免同一数值字号下的字面差异；日志行间距为2逻辑单位，时间戳弱化，检查点/队列信息、Stage1、Stage2、成功/因子、警告、错误分别使用主题语义色；只绘制可见行，颜色同时适配明暗主题。原始输出的进度行可附加约化ETA，磁盘日志和worker输出字节不改写。

Stage2区段按子阶段时长归一化，监控设置提供自动（上次运行 > tune）、仅上次运行、仅tune三种来源，对应侧车`ui.stage2_timing_source`。上次完成曲线的`stage2_phase: … previous=…`记录逐阶段覆盖tune；按工作流侧车、引擎路径/文件时间、设备（可取得时含UUID）、曲线类型/param及位宽/D/B1/B2区分，sigma不同不阻止同条件复用。仅保存已完成曲线，未完整捕获的日志不更新；数据存于UI侧车旁的`.stage2-timing.json`，损坏原文件保留并停止覆盖。GPU UUID不可用时，上次记录仅按设备序号区分，不能确认换卡后的同设备身份。

`tune`路径可在监控设置填写`ui.stage2_tune_file`；留空使用worker的`stage2_tune_profile`覆盖或全局同名项，再查找工作流/worker目录的`tune.toml`、`stage2_ecm_tune.toml`。显式路径不回退到其他文件，相对路径基于工作流目录。读取仓库format 3–8的标量/矩阵摘要子集，要求`full_stage2`和`exclusive_engine_v1`，按同GPU UUID、D、B2匹配，再取最近运算位宽；缺失UUID时不使用tune。独占引擎计时中的shape/setup合并到规划，main_setup/inverse_setup合并到求逆，其余按对应阶段展示；不重复相加嵌套计时。该只读适配仅供界面估计，不授予算法标定资格。解析在后台执行，渲染时不读取文件。

悬停进度条可查看各阶段时长、占比、来源及读取错误。没有任何时长时显示等宽占位并明确提示；部分阶段缺失时标为未知，不编造时长比例。batch报告提供已确认进度，运行期间按剩余秒数或已知阶段时长推算推进，等待里程碑确认；未确认阶段内估计最多95%（batch估计最多99%），当前曲线完成后才到100%，切换新曲线归零。整个条标注“估计”，不等于队列总完成率或精确ETA。

工作台/检查区区分 Stage2 任务曲线进度与阶段/批次，保留 worker 版本、命令、Prime95 提示、事件/原始日志和安全停止。关闭日志或切页仍推进 Controller。结果支持 F/NF、阶段、来源与搜索，复制原始 JSON/checksum；筛选或文件更新清理失效选择。生成器按目标 worker 分区，输入或选项变化使预览失效，追加前复核文件并锁定队列；CPU 拒绝不支持组合。生成器与概率页共用两组曲线按钮：第一组 Edwards，第二组 Montgomery。生成器仅列出可生成的 Z2 x Z8 (Prime95)、param 0 (Suyama)、param 2、param 3；不展示尚未实现的 Z12、Z2 x Z4、Z4 或 param 1。两页短输入框在宽面板中一行两个，窄面板或大字号时自动改为单列；说明始终在输入框左侧，相关开关在右侧。同一表单先按最长关联开关测量右侧预留区，短输入框保持等宽、同列左右边缘一致，右侧开关从固定位置开始；没有关联开关的字段同样保留空白预留区，不拉长输入框。高级筛选与绘图范围使用相同规则；很窄的区域优先保留输入宽度，开关文字省略并提供完整悬停提示。保存命名模板保留整行宽度。

概率页分为“参数”和“图表与快照”；显式计算后转到图表视图。概率输入、摘要、图表和悬停以0–100%显示，B1/B2、曲线数与范围等输入去除无意义小数；D_eff、比率及非整数解保留有效精度。模型与CSV概率仍使用0–1。概率正反算、图表、CSV 对应同一输入快照；参数修改后提示重新计算，已有图表和 CSV 保留其原快照。挠群阶 T 不等于 D_eff。Edwards Z2xZ8 的已有 Stage1 经验代表值为 26.4081（B1=256、15–25 bit 点口径）；按 Edwards/Suyama 相对收益归一到 GMP 基线约 29.0，作为联合模型启发预设，未经直接 Stage2 标定。概率页的 Edwards 按经验 D_eff 递减依次显示 Z2 x Z8 (Prime95)、Z12、Z2 x Z4、Z4；Montgomery 依次显示 param 0 (Suyama)、param 1、param 2、param 3。所有经验值逐项取自 `tools/ecm_prob/out/d_eff_representative.json` 的现有代表数据，param 0 与 param 2 分别为20.902115和20.156674，不再合并为同一经验预设。Montgomery 联合模型沿用 `tools/ecm_prob/model.py::THEORETICAL_D`，Edwards 联合预设仍按相对 Suyama 比值归一；按钮悬停可查看来源键与两种 D_eff。可选择经验口径或直接编辑 D_eff 自定义，不把挠群阶当完整 Edwards 预设。数学模型本身和旧概率页不改。依据见 [参数化参考](../reference/ECM_PARAMETERIZATIONS.md) 与 `tools/ecm_prob/README.md`。

GUI v2复选框使用统一的小尺寸圆角方框与细勾线；默认15字号下方框17px、勾线1.1px，按当前字号/DPI缩放。点击方框或标签、键盘空格切换、禁用与混合状态继续使用ImGui原生交互；组件页、设置、结果选择及概率图图例共用该控件。常用筛选使用点击标签；滚轮短暂提升刷新频率以平滑滚动，静止恢复 10Hz。Toast 不抢焦点；启动、安全停止、配置/生成器反馈保留详细日志。GPU 未知样本不伪造零值，容量单位为MiB，另有百分比、MHz、W与摄氏度。GPU核心频率、显存频率分项显示；显存占用是 `nvmlDeviceGetMemoryInfo` 已用/总容量，区分于 `nvmlUtilization_t.memory` 的读写活跃时间比例。[NVIDIA 指标说明](https://nvidia.custhelp.com/app/answers/detail/a_id/3751/kw/command)。概率图叠加 S1 / 联合 / 条件概率，统一明暗主题、网格、实际横坐标、坐标单位、淡色面积和悬停采样读数，图例可隐藏曲线。因子横轴直接使用快照的 bit / 十进制位数，不重复换算。GPU 曲线使用实际采样时间，设置“监控”组中的“GPU 图表时间范围”支持15/30/60/120秒，默认60秒，所有设备共用；保存到侧车`ui.gpu_history_seconds`，正常退出或保存界面偏好后恢复，不改变500ms采样间隔。GPU页不再显示时间选择控件。GPU图例按最大读数模式预留宽度，并使用当前字体最宽数字计算排布；百分比预留100.0%，频率预留五位MHz，功耗按有效功耗上限的三倍范围预留。换行高度同样使用预留文本计算，99与100、已知与未知切换不会改变图表高度；窗口或字号变化仍可正常重排。利用率/显存占用、功耗与频率分图，缺失值断线。GPU横向范围固定对应所选时间窗，固定刻度文字与垂直网格线隐藏，悬停统一显示一个实际采样时间（一位小数）及各指标，不重复x值。任务工作区下方依次提供所有worker的每曲线耗时图；横轴为采样序号，不假定为时间。标题右侧的列表/双列切换旁新增滑杆图标，开启后按各图当前保留的有效样本自动计算Y轴最小值、最大值及边距；关闭后从0开始。当前工作区显示worker已保留的最多600个样本，较旧样本被移出后不参与范围计算；恒定值仍留出范围，空窗口或无效值使用0–1占位范围，不造假样本。横轴仍为采样序号，悬停保留真实s/curve数值，GPU和概率图沿用各自范围规则。开关保存为`ui.worker_chart_auto_y`，默认关闭。概率图的图例开关为会话状态。

GPU页每设备提供可折叠卡片，顶部以辅助字号显示一行显存已用/总量与温度。利用率、显存占用、功耗、核心及显存频率直接在对应曲线图例旁显示当前值，避免重复摘要。指标使用` | `分隔，当前值与上限/总量使用两侧留空的` / `，如`GPU 50 / 100% | VRAM 25.0 / 100%`、`160.0 / 285 W`、`核心 2610 MHz | 显存 10251 MHz`；不显示“上限”文字，功耗上限来自NVML，未知时显示`--`。功耗沿用原GUI的3倍上限过滤规则：每个历史样本使用其自身的NVML功耗上限，超过3倍的值不进入功耗曲线、纵轴范围或悬停；恰好3倍保留。异常当前值显示`-- / 55 W`等格式，不用旧值或上限替代；异常时间点保留为断线，其他可用指标继续显示。负数、非有限值或无效采样同样显示未知；上限缺失时不猜测阈值，仍显示有限且非负的功耗。过滤只在v2展示层进行，不修改NVML原始历史或原GUI。GPU折线固定显示，不提供图例勾选框；三图默认直接显示，频率没有独立折叠栏。基础卡片高度64逻辑单位，图例使用辅助字号、数值使用正文字号；窄区域允许图例换行并增加卡片高度，保留至少28逻辑单位的绘图区。曲线基础粗细1.15、面积填充不透明度0.12，随字体比例缩放。GPU图不显示Y刻度、垂直网格线和X轴时间刻度，保留水平网格及一位小数的真实采样时间悬停读数。概率图和任务耗时图保留各自坐标，曲线同步使用较细描边与淡色填充。

悬停设备折叠栏，按型号、驱动/CUDA版本、SM规格/数量及CUDA核心数、显存总量、`NVML / 500 ms`的顺序显示详情。CUDA版本是驱动支持版本，见[NVML系统查询](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlSystemQueries.html)，不是本机Toolkit版本。规格与核心数使用NVML报告值；SM数量通过[CUDA Driver设备查询](https://docs.nvidia.com/cuda/cuda-driver-api/cuda_driver_api/group__CUDA__DEVICE.html)取得，按物理UUID匹配设备，不混用CUDA与NVML枚举序号。v2启动后在后台读取一次并发布缓存，不在悬停时调用驱动，不创建CUDA上下文或启动计算。驱动API不可用、UUID无法匹配或查询失败的字段显示`--`；缺少补充信息不影响已有监控或DX11运行。

每张GPU卡片在VRAM小字右侧提供齿轮按钮，打开点击外部即可关闭的悬浮设置窗。双端滑块共用一条水平MHz坐标轴，支持最小值等于最大值，例如2600 / 2600；左/右半区选择靠近的端点，重叠时从左/右选择最小/最大端。数值框支持精确输入。关闭、切换页面和修改滑块都保留会话草稿，只有“应用”才将该范围及自动选项用于当前GPU。“恢复默认频率”执行锁频策略重置并关闭本次会话自动应用，保留草稿；退出管理器不会擅自重置硬件。

“保存到ecm.toml”独立保存当前GPU的草稿及自动选项，保持其他设备记录、注释和未修改配置；不立即修改硬件，不提交尚未保存的计算配置。配置被外部修改时拒绝覆盖。保存位置是当前打开的业务TOML，不是UI侧车；键为`[gui] gpu_clock_ranges`，按物理UUID匹配，格式`GPU-<UUID>:minMHz-maxMHz[:auto]`，多卡以分号分隔。普通记录下次启动只载入草稿；带`:auto`的记录授权自动应用。当前0.49.10计算程序跳过`[gui]`和`[workers.N]`中的纯界面设置，不执行锁频；对未知GUI键给出警告。`gui.NumWorkers`仍保留并校验，供Stage1在目标队列没有分区时作为分发后备数量。未知计算键/分区、计算值类型错误、重复键及TOML语法错误仍拒绝，GUI自身继续严格校验。兼容范围不包括任意未知分区或尚不支持的TOML值语法，详见[配置参考](../ECM_TOML_REFERENCE.md)。旧计算程序仍需更新一次才能获得这个兼容边界。未使用保存功能时原配置文件不增加此项。

勾选“自动应用”后点击“应用”，启用当前会话的已提交范围；保存该选项则在下次启动、首次载入有效工作流后应用一次；当前会话重新载入配置不会重复执行启动应用。之后每个本地整点无条件应用一次；现有500ms监控采样的核心频率连续高于上限或低于下限满5秒时，也立即重设一次，并在管理器消息记录预期外异常。检测与折线图共用同一批`GpuMonitor`数据，不新增驱动频率轮询。无效、未知、过期超过1.5秒或采样间隔超过1.5秒中断连续计时；同一次连续越界只触发一次，恢复到范围内后重新计时，避免持续受限时重复刷写。自动操作仍使用已提交范围，不读取尚未应用的草稿。应用成功或失败均显示Toast；用户关闭Toast时尊重其偏好，消息仍保留。

支持范围来自NVML支持的显存/图形频率组合，必要时回退到驱动提供的性能状态范围；两种DLL查询均失败时，后台调用系统目录的nvidia-smi，以同一UUID读取支持频率列表，界面明确标出该来源。命令查询超时5秒、非零退出码或无效输出均拒绝作为上下限，不猜测硬件范围；该回退只查支持范围，不承担实时频率采样或设置。读写均在专用后台线程串行执行，按UUID重新定位设备，写入前再次核对驱动范围。设置和恢复分别使用`nvmlDeviceSetGpuLockedClocks`、`nvmlDeviceResetGpuLockedClocks`，对应`nvidia-smi -lgc`及`-rgc`。API缺失、硬件不支持、设备丢失或权限不足会给出明确反馈；不会自动提权或改用其他驱动写入手段。已有锁频策略没有可靠读取值时显示未知，图表仍显示实际采样；驱动接受请求不保证采样始终等于设定值，负载、功耗和温度限制仍生效。接口依据见[NVML设备命令](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceCommands.html)、[NVML设备查询](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html)及[nvidia-smi锁频说明](https://docs.nvidia.com/deploy/nvidia-smi/index.html)。

## 群阶分解 / Group Order Factor

导航中的“群阶分解”使用与ECM概率页相同的两行曲线按钮：Edwards 和 Montgomery param 0/1/2/3。当前重建后端支持 Atkin–Morain Edwards（Z2 x Z8），其他 Edwards 概率模型按钮禁用并显示说明。输入十进制素因子 p 与完整 uint64 sigma；sigma默认留空，空输入框按所选构造显示范围：Suyama为`6 ~ 2^64 - 1`，其余已支持构造为`1 ~ 2^64 - 1`。范围提示来自外部XML；计算前需要手动填写或从结果文件导入sigma。范围内仍可能因当前素域上的退化构造被拒绝；2^53是部分随机生成路径的界限，不作为群阶分析上限。曲线、param、sigma 共同确定数学身份。计算的是该素域上的完整群阶和**原始构造点的点阶**，不包含计算 worker 后续施加的 choose12 / 48LCM 标量；二者不能与“有效点阶”混用。算法、证明资格和预算定义统一见 [群阶模块](../architecture/GROUP_ORDER.md)。

页面中的GP设置是一行：`GP [路径] [浏览] [保存] [算法: Auto / PARI/GP / 本地CPU/GMP]`。载入工作流后，已保存的GP路径优先；为空时按当前进程PATH顺序查找`gp.exe`并将完整路径填入输入框，未找到时显示“选择GP”。不扫描其他安装目录，不自动保存发现结果。路径细节与相对路径规则放在悬停提示中，常驻设置不再占用多行。

`Auto`先直接启动GP；GP缺失、无法启动、超时或协议不可用时才启动本地助手。显式`PARI/GP`只使用GP，失败不转本地；显式`本地CPU/GMP`才直接检查和调用`ecm_group_order_ui.exe`。GP正常时无需助手或GMP DLL。助手缺失的报错会给出完整文件路径和Windows错误码；界面打开和算法下拉选择本身不启动分析。GP默认等待30秒，本地单次预算2秒，整个请求截止45秒；取消或退出结束当前GP/助手进程作业。运算不阻塞主界面，大素域在本地预算内可能未完成。

GP证明模数及分解因子素性，检查点消去及最小性；GUI独立检查协议完成、分解乘积、点阶因子包含关系和Hasse界。数学错误不会伪装为GP不可用而自动回退。结果保留输入快照、实际后端、状态及未完成原因；未执行素性检查时明确显示“未检查”，部分分解显示剩余余因子。`complete`与全部素性已证明是不同条件，CPU大整数的概率素性仍明确标为未证明。状态、实际后端与整体证明资格合并为一行，模数素性及GP回退原因在该行悬停查看。群阶与点阶各用两行：`群阶 #E(F_p): 数值` / `点阶 ord(P): 数值`，下一行缩进显示`= 2^2 × 3 × 83`等乘法分解式；省略指数1，不逐项标注素性。`[n]`表示尚未分解的余因子，不能当作素数。群阶与点阶共用无边框、透明背景的只读文本区，支持鼠标跨行选择和Ctrl+C复制选中部分；输入不能改写结果，整块高度按正文和自动换行计算，长整数与分解式随容器换行。复制结果为输入快照、状态/后端和两组数学表达式的纯文本，不包含逐因子素性或内部JSON字段；完整证明元数据仍保留在内部分析结果。每次计算结束独立弹出Toast，重复计算也提示；部分完成、资源限制、非法输入和启动失败均提示未完成，取消单独提示。群阶导航与计算按钮使用无外框、两行排列加减乘等号的运算图标，可在图标图鉴预览。

“保存”只将`[gui] group_order_gp`写入当前工作流`ecm.toml`，保留注释及其他未改字段；未保存的计算配置仍保持草稿，外部文件发生变化时拒绝覆盖。相对目录路径以当前工作流目录解释，空值在计算时重试PATH。该字段只供GUI使用，Stage1/Stage2的GP设置保持独立。未保存的路径也可立即用于本页计算；选择后端和数学输入属于会话状态。

页面自动扫描当前工作流目录中的`*result*.txt`，并纳入工作流已配置的结果文件；未载入工作流时扫描GUI程序目录。因此`results.json.txt`和`results.json_2.txt`会分别出现在来源下拉列表；也可用“选择结果文件”打开其他目录的TXT/JSON/JSONL，再用“重新扫描”刷新。每行必须是独立JSON对象，只导入`status=F`、`worktype=ECM`且包含可识别sigma的因子；支持普通Montgomery的顶层sigma/param、`Edwards.sigma`及`GMP-ECM-param3.sigma`，每个因子分别列出。点击记录填入p、sigma和算法，不会自动开始计算或改写来源。NF、缺失/越界sigma、冲突曲线标记和不支持的构造会跳过并显示计数；该导入不验证结果CRC或代替因子证明。单文件上限32MiB、20000个因子。

本地分解或Auto回退需要将`ecm_group_order_ui.exe`与匹配的`gmp-10.dll`放在GUI旁；仅使用GP可以省略这两个文件。PARI/GP不随候选包分发，用户单独安装并指定路径或加入PATH。两条分析路线都不启动计算worker、不写队列、不修改GPU频率。专项验证入口为`tools/test/gui_v2/test_group_order.py`（`--gp-only`检查无助手/GMP的GUI）、`test_group_order_backend.py`及`ecm_gui_v2_group_order_test.exe <helper> <故障GP fixture> <新的输出目录> <真实GP>`。

## 安装与替换皮肤

皮肤PNG是外部资源，不嵌入exe，也不要求加入Git。程序固定从 **`ecm_gui_v2.exe` 同目录的 `assets` 文件夹**读取，与启动时的工作目录无关。三套新增皮肤的安装文件名为：

- `assets/pet_ely_miss_pink_elf.png`
- `assets/pet_ely_herrscher_of_human_ego.png`
- `assets/pet_ely_hi_love_elf.png`

将需要的PNG复制到该位置，启动GUI v2，在“设置”中启用ELY宠物，再点击“ELY皮肤”中的对应名称。也可运行 `ecm_gui_v2.exe --pet --pet-skin hi_love_elf`，其余两套使用对应ID。开发构建的目标目录为 `build_gui_v2_local/assets/`；本仓库资源源目录为 `assets/gui_v2/`，构建步骤仅将PNG复制到程序旁，不把它们链接进exe。

替换已登记皮肤的图案无需编译：退出程序，保留文件名并替换PNG，再启动。图片必须是1792×1736的透明RGBA动画图集，单帧224×248，8列×7行；各行依次是待机、工作、等待、异常、完成、睡觉、眨眼。文件不得超过8MiB。普通立绘或单帧PNG不能直接使用。当前运行时不读取同名JSON、SVG或`skins/manifest.json`，这些文件用于制作、来源记录与构建校验。缺少选中的PNG时仅关闭宠物并提示路径，主界面继续工作。

目前只有Classic ELY与上述三个ID，尚无文件选择式导入或自动扫描。添加一个全新的皮肤名称/ID仍须更新注册表、配置允许值及相应生成物并重新编译；仅把额外PNG放进`assets`不会增加列表项。同名PNG替换也不会实时监测文件变化，重启后加载新图。

新增PNG、SVG和素材清单仅保存在本机，按用户要求不提交Git。Git忽略规则精确放行原版`pet_ely.png`、`pet_ely.json`、[来源与生成说明](../../assets/gui_v2/CLASSIC-ELY-NOTICE.md)、[上游完整MIT许可证](../../assets/gui_v2/ELYTerminal-LICENSE.txt)及`third_party/gui_v2_pet/`中的固定源码、许可和说明；其他新增皮肤继续忽略。原版说明与许可随构建资源和候选包一同复制。运行时可按需单独安装皮肤PNG；当前开发构建及完整候选包仍校验全部本地图集/配方，新克隆工作区须先恢复这些本地资源才能通过构建。图片可通过本地备份或独立资源包保存，避免增加Git历史体积。

[网页画廊](../web/ely-skins-20261022.html)另提供三套中空浅色菱形瞳孔变体，以及现有版本切换和静态双眼放大。菱形仅绘制轮廓，中心保留虹膜底色，不使用实心填充。变体位于被忽略的`assets/web/ely_variants/`，只用于Web演示，不加入程序皮肤列表、原生资源目录、配置或程序分发包；程序仍使用现有三套图集。

## 一键 DX11 测试

双击 `tools\test\gui_v2\run_all.bat`，默认测试 `build_gui_v2_local\ecm_gui_v2.exe`。需要 Windows、Python 3.11+，以及同目录的 `ecm_gui_v2_state_test.exe`、`ecm_gui_v2_app_test.exe`、`ecm_gui_v2_owner_probe.exe`、`ecm_gui_v2_fake_worker.exe`；缺少时入口会列出文件及测试 helper 构建命令，不自动重建程序。

流程按顺序执行状态、App、队列拥有权、启动分派、DX11窗口、全部页面、交互、易用性、独立面板、中文/英文与明暗主题的任务及日志展示、宠物定位/皮肤、单窗口/独立面板图表拖动和最小化采样，共18项。只使用DX11，不运行Vulkan专项；旧GUI回归、真实计算/性能对照、打包及浏览器素材测试仍使用各自专项入口，不包含在此流程。

每轮复制所选二进制、相邻DLL及assets到新的 `data/experiments/gui_v2/dx11_suite_<时间>_<标识>/bin`，避免自动发现用户程序旁的业务配置。测试使用各自的临时工作流和UI侧车；记录原EXE路径及SHA256，逐项保存日志与截图，写入 `summary.json`。失败后继续下一项，默认单项超时300秒；每项结束关闭该测试的Windows进程作业，清理残留窗口及模拟worker。测试会控制真实窗口，运行期间保持桌面空闲。BAT结束后暂停显示结果；全部通过返回0，测试失败返回1，输入/依赖错误返回2。

命令行可用 `run_all.bat --list --no-pause` 查看列表，`run_all.bat --only "presentation-*" --no-pause` 只跑展示测试；`--exe <路径>` 指定程序，`--out <不存在的新目录>` 指定证据目录，`--timeout <秒>` 调整单项超时。默认输出不覆盖既有证据。

## 验证边界

已有同为144 DPI的两块物理显示器、窗口几何及合成输入记录；DX11本轮有用户观察确认，Vulkan多屏拖动仍未通过。不同物理DPI、真实IME、总GPU驻留、受控功耗/计算并行、长期运行与独立干净机器仍需专项资格。系统Segoe UI / 微软雅黑 / Consolas不随包分发，缺中文字体退回英文。可选Vulkan路径遇HDR/显示格式改变导致render pass不兼容时要求重启。

`--validation`、`--no-loader`、`--inject-failure`和`--trace-render`仅适用于显式Vulkan模式；DX11拒绝这些组合，不伪造Vulkan验证通过。`--frames`、`--audit-ui`、`--audit-app`、`--simulate-missing-cjk`是公共测试入口。显式Vulkan分配只计VkDeviceMemory，DX11日志明确标注该统计不提供D3D显存数据；两者均不是进程总显存，不能据API名称声明更低占用。验证脚本位于 `tools/test/gui_v2/`，证据存忽略目录 `data/experiments/gui_v2/`。

## 独立候选包

先用独立构建入口生成程序，再运行 `tools/build/package_gui_v2.ps1 -BuildDir build_gui_v2_local -Output <新的目录>`；可用 `-Python` 指定解释器。包包含GUI、群阶分析助手及匹配GMP DLL、宠物资产、使用/侧车说明、许可、逐文件SHA256、构建源目录快照及ZIP校验，不覆盖旧版。源码包包含助手所用的本地GMP源码、构建配置及安装文件，DLL可替换；本机Zen3/BMI2依赖的跨CPU兼容性尚未验证。不包含计算worker、PARI/GP、系统字体、Vulkan loader、开发层或Microsoft runtime；更新worker另行安装，1024-bit专用验收worker不能作为完整发布替代。

v2 自带 UTF-8 进程 manifest，使复用的窄字符文件接口在支持的 Windows 版本上处理中文路径；不改变系统代码页或旧 GUI。依据：[Microsoft 进程 UTF-8 文档](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page)。计算 worker 的非 ASCII 路径兼容性须按其自身构建单独确认。

P5未完成默认DX11后端的完整性能矩阵；历史Vulkan矩阵的最小化CPU中位数1.031% > 1%失败及桌面冻结结论保留，不转记为DX11测量。P6是独立分发准备，不表示已获得全部生产资格；未放宽门限。具体输入、设备、二进制、样本及时间边界见实施草稿，原始失败证据保留。可显式使用`--no-nvml`关闭监控，但不据此改判默认监控条件下的门禁。
