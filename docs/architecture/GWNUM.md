# GWNUM FFT 实现

ECM-ELF 的 Windows x64 CPU 插件链接 Prime95 31.6 build 1 的 `gwnum64.lib`。Montgomery CPU Stage1 通过 GWNUM 做模算术，CPU Stage2 的 `gwpoly` 使用 GWNUM 处理整数系数，并通过 `polymult64.lib` 处理多项式。两处均将单个 GWNUM handle 配置为一线程，并关闭 GWNUM 的 benchmark 选型。本文的 kernel 指这一库中的 CPU 汇编例程。 [构建入口](../../tools/build/gwnum/CMakeLists.txt#L9) · [Stage1 插件](../../src/ecm/stage1/montgomery/cpu/gwnum_plugin.cpp#L130) · [Stage2 初始化](../../src/ecm/stage2/cpu/gwpoly.cpp#L87) · [上游 31.6 build 1](https://www.mersenne.org/download/software/v31/31.06/)

## FFT 类型和选型

GWNUM 以 `FFTLEN` 个双精度实数槽保存一个变换操作数。复数路径将实部和虚部配对，具体访存顺序、填缝和中间缓冲由计划决定。对形如 \(k b^n+c\) 的模数，IBDWT 将字宽和权重并入 FFT。以 \(b^n+c\) 为例，第 \(j\) 个字从 \(\lceil jn / \mathrm{FFTLEN} \rceil\) 次幂开始。相邻字的起点之差决定 big/little word 的宽度。位宽均匀时可选 rational 分支。\(2^p-1\) 对应循环卷积，\(2^p+1\) 对应负循环卷积。前者的 AVX-512 Pass2 首块走 real 分支，其余走 complex 分支。后者全部走 complex 分支。 [FFT 元数据](../../.refactor/p95v3106b01.source/gwnum/gwnum.h#L974) · [字址与权重](../../.refactor/p95v3106b01.source/gwnum/gwdbldbl.cpp#L1263) · [AVX-512 Pass2 入口](../../.refactor/p95v3106b01.source/gwnum/zmult.mac#L946)

- **Zero padding** 将输入的高半区清零，复用循环表，并在归一化阶段处理 \(k,c\)。对于支持的特殊模数，选型会比较 zero-padded 和 IBDWT 方案。表里的 `max_exp` 是计算安全上限的基准，实际决策还考虑 CPU、最小长度、浮点安全余量、字宽分布和实现可用性。 [选型与长度上限](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L945)
- **一般模数** 先尝试识别可使用特殊形式的数。一般奇模数可选 MMGW Montgomery reduction，建立同长度的循环与负循环子计划。较小、偶数或显式指定的模数可走 Barrett 路径。以本机 3,608,153-bit 一般奇模数样本为例，MMGW 使用两个长度 196,608 的子计划，探针强制 Barrett 时使用长度 368,640，拆分为 960 × 384。 [一般模数入口](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L2526)
- **`FFT_TYPE`** 标记实现族。0 是 Home Grown，1 是 Radix-4，2 是 Radix-4 Delayed，3 是带 partial normalization 的 Radix-4 DWPN。31.6 x64 的六张表实际使用 0、1、3。混合长度会在 Radix-4 族内调用定制蝶形，例如 192K 的 AVX-512 Pass1 同时用到 radix-8、12、16 蝶形。 [类型定义](../../.refactor/p95v3106b01.source/gwnum/gwnum.h#L934) · [3072 点宏](../../.refactor/p95v3106b01.source/gwnum/zr4dwpnpass1sc.mac#L9238)

## Pass 分解与 kernel 调度

| 布局 | 运行时识别 | 数据流及入口 |
|---|---|---|
| 直接 one-pass | `PASS1_SIZE=0`，`PASS2_SIZE=0` | 主入口做首尾级，按运算模式调用或跳入共享的中间蝶形，然后在需要时归一化。 |
| AVX-512 one-pass 包装器 | 表中分解为 `2 × PASS2_SIZE`，运行时将 `PASS1_SIZE` 归零 | 主入口使用一小段专用包装逻辑组织数据，调用标准 DWPN Pass2。12,800 点样本的共享入口是 `zpass2_r4dwpn_6400_SKX`。 |
| 真正 two-pass | `PASS1_SIZE × PASS2_SIZE = FFTLEN`，且 `PASS1_SIZE > 2` | 正向 Pass1 按块做跨距蝶形、权重与重排。Pass2 将块送入末级 FFT，平方或乘法紧接频域点乘和逆变换初段。逆向 Pass1 做其余逆级、写回、归一化与进位。 |

Pass1 的维度按实数槽计，Pass2 的维度按复数值计，列出的分解使用库自己的单位。选型从记录中解码 `PASS1_CACHE_LINES`，AVX-512 用 `8 × clm`，AVX/FMA3 用 `4 × clm`，SSE2 用 `2 × clm`。AVX-512 的 Pass1 以实部与虚部各 64 B 组成的 128 B 双缓存行为布局单位，按计划加入间隔，并用 scratch 做重排。AVX-512 生成器以 1 MiB L2 为设计目标，Pass1 达到 1,024 时省去 `clm=4`，达到 2,048 时也省去 `clm=2`。Pass2 按自己的步长遍历。两趟的 C 回调分配工作块，进位阶段单独处理块边界。 [字段解码](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L1652) · [AVX-512 Pass1 生成与归一化](../../.refactor/p95v3106b01.source/gwnum/zmult.mac#L150) · [Pass1 的块与进位调度](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L5946) · [Pass2 的块调度](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L6423)

主入口从 `GWPROCPTRS[0]` 进入。YMM/ZMM 共享 Pass2 各自通过 `YMM_PASS2_ROUTINE`、`ZMM_PASS2_ROUTINE` 调用。逆向 Pass1 使用选定的归一化例程，再通过 carry 例程处理跨块边界。以 192K 循环 AVX-512 为例，执行的主入口、Pass2、归一化和进位依次对应 `zfft_r4dwpn_3072_1_SKX`、`zpass2_r4dwpn_64_SKX`、`zi3SKX`、`zgw_carries_wpn3`。负循环用 `zfft_r4dwpn_3072_ac_1_SKX`，共享同一个 Pass2 入口。 [汇编入口和共享函数绑定](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L1633) · [归一化派发](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L5115) · [Pass2 64 点 real/complex 分支](../../.refactor/p95v3106b01.source/gwnum/zr4dwpnpass2.mac#L33)

### 同一 FFT 入口的四种运算模式

汇编字段 `ffttype` 按当前操作选择分支，与计划的 `FFT_TYPE` 分开。

| `ffttype` | 入口条件 | 计算范围 |
|---:|---|---|
| 1 | `gwfft` 需要执行正变换 | 正向 Pass1 和 Pass2，或直接 one-pass 正变换。 |
| 2 | 同一操作数平方，输入尚未完整变换 | 完成输入的正变换，频域平方，逆变换与归一化。 |
| 3 | 乘法中一侧已完整变换 | 完成其余一侧的正变换并做频域乘法和逆变换。两个输入均未变换时，C 层可先对一侧另跑一次 type 1。 |
| 4 | 输入均已完整变换，或平方的唯一输入已完整变换 | 从频域点乘或平方进入逆变换与归一化。 |

`GWMUL_STARTNEXTFFT` 可在真正 two-pass 的结果归一化后对同一块启动下一次正向 Pass1，输出为 `PARTIALLY_FFTed`。下游可直接从 Pass2 继续。输入别名、保留源操作数、是否同时保存 FFT 结果，以及模数路径都会影响实际执行的分支。 [输入状态与乘法派发](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L10362) · [正变换 API](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L11497) · [归一化后启动下次 FFT](../../.refactor/p95v3106b01.source/gwnum/gwnum.c#L6050)

### 蝶形宏的浮点指令

`zr4_4c_djbfft_cmn` 和 `zr4_4c_djbunfft_cmn` 都是带 twiddle 的 AVX-512 4-complex 蝶形。按一套四个复数向量输入计，展开奇数分支的单次蝶形，或把偶数分支的双展开除以二，得到以下浮点算术计数。每个 512-bit packed-double 算术指令处理 8 个 lane，每 lane 各做同一蝶形。表格只统计浮点 ADD/SUB、MUL 和 FMA。 [正向蝶形](../../.refactor/p95v3106b01.source/gwnum/zr4.mac#L62) · [逆向蝶形](../../.refactor/p95v3106b01.source/gwnum/zr4.mac#L326)

| 正向，带 twiddle | 12 | 4 | 10 | 26 |

### 复核口径

实验使用本地上游 `gwnum64.lib`，SHA-256 为 `4287d02fe0a30dbc93ebe02a5222ee2fb4fe94978c638f278e90a054cd256eb7`。用 MSVC 14.51 链接探针，依据链接器 MAP 和 PE 的 `_GWDATA` 解析跳表。按 `dumpbin /DISASM:NOBYTES` 的指令地址分类，并用 x86 Trap Flag 的单步回调累计运行次数。路径只在支持 AVX-512 的同一台 CPU 上观测，FMA3 与 SSE2 由探针屏蔽较新的 ISA 选择。单步统计没有耗时或功耗指标。指令条数和显式访存条数也不等于微操作数、缓存流量或周期数。

本机证据目录为 `data/experiments/gwnum_316_inventory/`。其中 `build.cmd`、`probe.cpp`、`run.py` 和 `inventory.py` 可重放实验，`binary-table.tsv` 为逐候选记录，`static-routines.tsv`、`trace-summary.tsv`、`trace-routines.tsv`、`trace-phases.tsv` 保留完整的助记符计数。原始轨迹、MAP 和证据随本地实验目录保存。

## Stage2 的第二层 FFT

Stage2 外层 `polymult` 将 GWNUM 系数按频域 line 读取，再沿多项式的系数索引做另一层 FFT。`polymult_fft_size` 从 \(2^k \times \{40,45,48,50,54,60,64,72,75\}\) 中选够用的长度，跳过需要独立 radix-2 级的偶数长度。`pick_pass_sizes` 根据 L2、向量宽度和分解选择 one-pass 或 two-pass。two-pass 的 Pass2 选接近平方根且受缓存容量约束的二次幂，奇数因子留在 Pass1。该层有 AVX-512、FMA3、AVX、SSE2 和标量版 `fft_line_pass`，包含 radix-3、4、5 蝶形和部分 radix-8 路径。本文的 8,128 条候选与指令表均统计内层整数算术。 [外层 FFT 长度与分解](../../.refactor/p95v3106b01.source/gwnum/polymult.c#L410) · [外层 SIMD 例程](../../.refactor/p95v3106b01.source/gwnum/polymult.c#L170) · [外层 FFT 执行](../../.refactor/p95v3106b01.source/gwnum/polymult.c#L3899) · [polymult 固定参考](../reference/GWNUM_POLYMULT.md)

## 对 GPU NTT 的参考

- 选型时将 **分解方式与中间布局** 当成独立参数。本机 192K 的 256 × 768、768 × 256、3,072 × 64 对应不同缓存与 SIMD 约束。GPU NTT 的候选可按 `length`、分解、共享内存布局和曲线并行度分别记录，观察资源约束如何改变最优点。
- 优先验证 **正变换末级 + 点乘或平方 + 逆变换首级** 的融合。GWNUM 通过这一边界保持局部数据。GPU 上可用成对 kernel 的全局内存读写、寄存器和共享内存占用，以及完整 Stage1 的 `iter/s` 验证收益。
- 分开记录 **模运算与数据移动的代价**。GPU NTT 可分别统计模乘约减、twiddle 访问、搬运、重排和跨块同步，再结合 tune 的单曲线和最佳并行测量。 [GPU NTT 调优口径](../usage/TUNE.md)
