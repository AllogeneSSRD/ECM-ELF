# Edwards GPU Stage2 性能与 CPU 参考

本页分别维护可选 relocation、Edwards/PARAM0 固定 D 优化对照，以及独立冻结的 Prime95、GPU 普通/承载和 CPU 参考矩阵。不同矩阵不合并统计，不按 B2、时钟或线程数换算时间。GPU 管线见 [Stage2 架构](../architecture/STAGE2.md)。

## 可选 relocation：相同 B2 的 Edwards 对照

0.36.0 增加默认关闭的保守后缀 relocation；完整范围、目标 N 非单位与 gcd=N 重放、短尾分块规则集中见 [Stage2 架构](../architecture/STAGE2.md#可选-relocation)。本节只比较 Edwards，同一个生产二进制交替使用 `--relocation 0/1`，不与下节不同版本的旧数据混合。

### 输入、计时与构建

四个普通模数 NF 条件复用下节已验证的 Edwards Stage1 末点：实际 N 为383/10232/16272位，B1=50000、sigma26；低档 B2=27015978990、D=180180，高档仅10232位、B2=273142759890、D=570570。B2和D在两侧完全相同，不上扩边界。两份独立构造的 F 余因子分别为10252/10246位，B1=20、B2=100000000、D=30030，输入准备不计时。后缀命中样本的小因子1000367上，剩余点阶20873经独立有限域BSGS及直接点乘验证，大于 baby 上界15015和 giant 终点3332；另一F样本在baby归一化发现非单位，直接走原区间。

预算 arena6300/owner640/batch256 MiB，普通目标 N、不使用梅森承载、factor-only、NTT计数开启、关闭短标定/runtime tune。正式样本不启用额外诊断；必须保留原生算术检查及其排空。每格两侧各一次预热、三次正式调用，交替侧顺序，全部调用保留。图表用正式三次的中位数和min/max，不丢弃首个正式样本，不从预热推导结论。

完整引擎指标仍为 `stage2_full_wall.total=init+main`：包含一次共享 baby/F 初始化、后缀试算、必要的原区间重放、GCD及检查收尾；Stage1、外层选D、计时前Montgomery/xADD预检和进程启动另计。shape已在init内；probe/replay已在main内，不能再加到总时间。进程墙钟单独保留，含最多200ms退出检测延迟。NTT计数包含实际probe与replay，不含底层独立算术自检。

实测构建为0.36.0、sm89、CUDA13.3.73、MSVC14.51.36231、PTX3/addsub1、GMP Zen3；EXE SHA256为 `5f3628ec2c848a3829e5b91120e1c91406ce5fb8112eca9259bc9f3912a9314d`。81份编译依赖、GMP、构建清单、采集器及辅助脚本随研究冻结。本机 `build_cuda_cmake/local_stage2_0_36_0/ecm_cuda_stage2.exe` 经正式构建入口核验签名，复用同一EXE，未改写已冻结的候选或原始证据。本任务的编译及GPU诊断不与正式计时并行。

### 正确性与范围

`data/experiments/gpu_stage2_relocation_20261018/gates05/` 包含27项外层门禁，其中baby目标零子门禁另执行4条曲线。纯整数规划157752项检查通过；独立仿射完整目标叶、普通/承载、单G及非满尾、因子10007、gcd=N反例因子1186519与原算法一致；宽位数18827点和重分后的141121点均与独立ladder逐点一致。目标零baby在正常设备及主机回退两侧均跳过probe，并与原算法最终完整叶一致。开关两种算法的NF叶通常不同，各自对照独立参考；重放最终叶必须匹配原算法。

命中时原区间完整重放是兼容成本。F耗时只对应本节B2=100000000的两个构造样本，不能直接用作NF大界限条件的重放时间估计。这个版本的选D/Auto B2/内存准入仍按原区间估算，不将旧ECM时间模型当成后缀成本；不采集旧ECM调优样本，显式完整ECM tune拒绝。新测量只覆盖本节的Edwards条件，不能推广为所有D/B2、位宽、承载模式、设备或多曲线吞吐的性能保证。复现入口见 [测量工具](../../tools/bench/README_EDWARDS_STAGE2_RELOCATION.md)。

## 固定 D 的 Edwards / PARAM0 优化对照

0.34.1 对宽位数 giant 尾块使用已有差分 chain，适用范围和非单位 ladder 回退见 [点生成与归一化](../architecture/STAGE2.md#点生成与归一化)。两种曲线在 Stage1 末点接入后共用主要 Stage2 管线，本次优化同时作用于 Edwards 与 Montgomery PARAM0；模型身份、sigma 和覆盖范围保持各自合同。

### 条件与统计

目标是剥离已知因子后的精确余因子 N，实际位宽为 383、10232、16272。全部使用 sigma26、B1=50000；Edwards save 复用已独立验证的 CPU Edwards `48·LCM` 末点，PARAM0 save 由原生 GMP-ECM 为相同 N/B1/sigma 生成。输入准备不计入 Stage2。相同 sigma 在不同曲线族下不表示同一曲线，本表只比较实现成本。

每格固定实际 N、B1/B2、D 和承载模式。低档 B2=27,015,978,990、D=180180；高档仅测 10232-bit 普通余因子，B2=273,142,759,890、D=570570。承载分别使用原始指数 10267、16319，并验证 N 整除相应梅森数。固定 D 用于控制比较条件，不代表各模式的最优 D。arena6300/owner640/batch256 MiB，关闭短标定和运行时 tune。

每次为独立进程中的单曲线完整 NF。六格×两模型×两构建，每侧预热一次、正式三次，共 24 条预热和 72 条正式样本；所有声明的样本保留，统计不含预热。17 条预热从相同设备、二进制、输入和预算的冻结采集导入，逐项核对来源及文件哈希；未入账调用和独立诊断保存在各自证据目录。正式三轮循环变换四侧执行顺序，本任务的其他 GPU 诊断及编译不与采样并发。

主指标为 `stage2_full_wall.total=init+main`：包含 baby 集合枚举、引擎内 NTT/S4 检查、树初始化、主计算、GCD 和检查收尾。日志中的 shape 已计入 init，不能再加。Stage1、进程启动、外层 D 选型及计时前的 Montgomery/xADD 预检另计。CSV 同时保留进程墙钟中位数和范围，包含最多一个 200 ms 退出轮询周期；不能据此精确相减得到启动成本。图中误差线是三次实测 min/max，不是置信区间；阶段图堆叠互斥 init/main 均值，在日志精度内等于总均值。

GPU1 为 RTX4060 Laptop，驱动610.88，程序未修改频率或功耗。正式样本 GPU 利用率≥50% 的 16300 个采样点中，SM 时钟1425–1500 MHz、中位1500 MHz；设备功率8.876–54.955 W、中位32.814 W；温度54–65°C、中位60°C。遥测是整卡观察值，不能当作进程显存峰值或恒定功耗。主机沿用 Ryzen AI 9 HX 370、用户确认固定4 GHz的条件，没有采集有效CPU频率计数器。

两个生产构建均为 sm89、CUDA13.3.73、MSVC14.51.36231、PTX3/addsub1、GMP Zen3，冻结 EXE SHA256 分别为：

## Prime95 与 CPU 参考：冻结矩阵

本节保留 Edwards 大余因子 GPU Stage2 的独立性能参照：普通余因子、梅森承载各 26 个条件，每格三次，共 156 次完整 NF 运行。CPU NTT/plain 仅保留已完成的 32 次单线程样本作为参考，采集已停止，不要求补齐 CPU 后才生成 GPU 结果。计算入口及后端选择见 [CPU Stage2 使用](../usage/EDWARDS_CPU_STAGE2.md)。小位宽、B2=10^12 的既有 CPU 测量仍在使用页，使用其独立冻结版本和条件，不混入本矩阵。

GWNUM/polymult 多线程 CPU 后端有独立的 [4 GHz 精确输入实测](CPU_GWPOLY_STAGE2.md)；不改写本页的 libecm 冻结样本，也不补齐已停止的旧 CPU 矩阵。

### 输入与统计口径

输入来自用户提供的 Prime95 31.4b05 `4Core@4GHz` 四份完整屏幕日志：Edwards/Montgomery 各有请求 B2=2.6×10^10、2.6×10^11 两档，Edwards 的 B1=50000，Montgomery 的 B1=20。每个模型 13 个目标、26 个条件，每格历史样本 n=1。Montgomery 是独立曲线族且 B1 不同的参考，不能当作相同 Edwards 末点或相同 B1 的实现对照。

M 指数对应的实际模数是剥离已知因子的余因子：

\[
N=(2^p-1)/\prod_i f_i.
\]

恢复工具利用正式结果的完成记录关联和 known-factors 精确整除核对 N。新测量必须同时匹配 N、Edwards sigma、B1 和日志中的调整后 B2；不按指数标签或近似位宽配对，不按 B2 比例缩放耗时。除 M2003 使用 sigma27 外，Edwards 均为 sigma26。

低档调整后 B2 通常为 27,015,978,990，M6011 为 27,567,389,850；高档 M503–M3001 为 278,982,814,110，M4001–M14401 为 273,142,759,890，M16319 为 264,004,751,010。精确值保留在逐格 CSV 和计划快照中。

相同 B2 表示调用入口声明的覆盖范围一致。各实现仍可能采用不同多项式、分块和尾部覆盖；libecm 只保守报告请求界限。因此这组数据比较完整实现的成本，不代表各实现执行了相同数量的底层运算。

Stage1 使用相同的 CPU 标量 Edwards `48·lcm(1…B1)` 完成点，准备成本不计入 Stage2。13 份 save 均经过独立 Montgomery x-only ladder 验证；生产 Stage1 使用 Edwards 点公式。四条路径消费同一份 save，不再次乘 48。首次调用保留，轮换实现顺序，不丢弃预热。GPU 每格正式样本三次；CPU 已测单元每格一次。提前找到因子的样本独立保留，不混入完整 NF 时间。

计时边界分别为：

- Prime95：初始化、主计算、最终 GCD 三个互斥阶段之和。日志中的 Stage2 complete Total time 仅为主计算，不能单独作为完整 Stage2。
- GPU：`stage2_full_wall.total=init+main`，包含引擎内 NTT/S4 检查、树初始化、主计算及 GCD；不包含 Stage1、驱动入口选型、进程启动和计时前的 Montgomery/xADD 预检。嵌套算子计时用于定位瓶颈，不再加到完整时间中。
- CPU：构造曲线至完整 libecm 返回，包含构造成本；不包含读档、进程启动和 JSON 发布。使用 S=1，显式 NTT/plain；两后端可选择不同多项式规划。

另存进程墙钟；收集器每 250 ms 观察退出，因此它包含最多一个轮询周期的退出检测延迟，不用于精确估计启动开销。GPU 三次样本显示中位数与最小/最大值，不是置信区间；CPU 参考与 Prime95 单次历史点没有误差估计。

### 设备、版本与证据

普通余因子耗时除以承载耗时，在低/高 B2 两档 13 个条件上的中位比为 1.293/1.304，范围分别为 0.501–1.814、0.425–2.031。比值大于 1 表示承载较快；小余因子可能因承载位宽膨胀而变慢，例如 M1009 两档均适合普通余因子路径。M16319 高档承载从 260.051 降到 128.042 秒，但仍高于 Prime95 四线程的 52.502 秒；这些是完整实现成本，不能表述为同线程算法加速。

按逐调用互斥计时计算，初始化占完整 GPU Stage2 的比例在低档普通/承载分别为中位 26.7%/23.4%，高档为 23.1%/19.5%。主计算仍占大部分成本，初始化也有可观优化空间。`gpu_phases` 只堆叠互斥 init/main；组件各自中位数不必等于总时间的中位数。进一步定位 NTT、准备、归约或下降瓶颈，应使用原始嵌套算子计时和工作量，不能将它们重复相加。当前数据也支持按 N 与承载指数实际选择路径，而不是统一强制承载。
