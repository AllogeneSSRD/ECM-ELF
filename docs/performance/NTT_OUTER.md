# Stage2 NTT outer 计划性能

## 当前策略

生产自动表要求 RTX 4060 Laptop、sm89、tile12、warp tail、compact scratch，以及原 radix 上限 M4。默认 k24 使用协作 M6，k25–27 使用 M8；其他长度保留 M4。任意 radix 覆盖仍使用开发引擎。

另有默认关闭的实验开关 `NTT_FUSE_MID_COOP=1`：在相同设备和布局条件下，k21–23 使用 M6。它只扩展自动表，不改变 k24 及以上、其他设备或其他布局。该开关是诊断环境控制，不是 INI 正式选项。

M 表示一个 outer pass 融合的 radix2 层数。执行计划在最少 pass 中选末段较宽的分解；它并不要求每段都用最大 M。实际计划如下，末尾 tile12 另算一遍：

| k | 默认 outer 分解 | 实验 outer 分解 | 正向总遍数 |
|---|---|---|---|
| 21 | 4+1+4 | 3+6 | 4 → 3 |
| 22 | 4+2+4 | 4+6 | 4 → 3 |
| 23 | 4+3+4 | 5+6 | 4 → 3 |

逆向按反序使用相应层次。数学变换数、radix2 等价蝶形数、pack/carry/S4 和曲线语义相同；减少的是全数组遍历和提交，不是数学 NTT 数。协作 M5–M8 的 radix 轴在 shared 中交换，不能按“越宽越好”选择。

每个完整 outer pass 逻辑上读写 L 个8-byte域元素。一条卷积有两正向、一逆向，均减少一遍时，数组读写量少48·L·batch bytes；k21/22/23、batch1分别为96/192/384 MiB。该数排除根表、pointwise的额外输入、pack/carry/S4，且不等于实测DRAM流量，缓存命中会改变后者。

独立计划的 base+cached-root payload 在 k21 为4,326,048→6,424,192 bytes，k22 为7,471,808→6,424,320，k23 为13,763,328→6,424,576。中段并非都更省表空间；正式运行由同一描述器重新计算预算和缓存准入，不复用旧计划的容量估计。这些是单计划分量，不能相加当进程峰值。

## 验证范围

设备为 GPU1 RTX 4060 Laptop（24 SM、8 GiB，UUID `8a67b1f8ef1c3177a822813a7ac2224d`），驱动610.88，CUDA13.3.73、MSVC14.51.36231。保持用户默认55 W及1800 MHz上限设置；没有调节功耗/时钟，也没有停止GPU0外部任务。实际频率随负载变化，不能称为固定频率测量。

独立生产运行时探针使用 PTX3/canonical 算术，同一二进制比较自动表与强制 M5–M8。独立 GMP 正向/逆向与缓存门禁检查30,277,632 words，bad=0；故障注入检出1错并退出3。中段条件与强制模式边界672项 bad=0。

算子扫描为 k20–24、batch1/4、每计划10样本，每样本串联8次完整卷积；不丢弃 warmup。计时为设备事件，排除输入、根表构建和校验。全部500样本、16,252,928,000个最终 A/B words 与默认结果一致；完整大形状对照是路径一致性，独立 GMP 门禁提供另一依据。

M6 相对 M4 的完整卷积时间减少量为：

| k | batch1 | batch4 |
|---|---:|---:|
| 21 | 2.05% | 21.47% |
| 22 | 8.05% | 19.23% |
| 23 | 17.40% | 15.03% |

这组数据证明中段候选值得完整曲线验证，不能替代生产收益验收。强制 M6 在 k20 分别慢2.67%/15.35%，实验表不扩展到该长度。k24 已默认 M6，重复路径的微小差异视为波动。

算子二进制 SHA256：`9dec2bb00730c7239a3b904062b8a2c5b5b472a48c1a2b8fb620797f791239ee`。高利用率采样中 SM1365–1800 MHz，中位1560 MHz；功率31.87–55.41 W、中位54.88 W。原始NVML在空闲处曾报告590.01 W，该异常值保留，不能作为真实功耗使用。

## 固定 D 完整曲线

Stage2二进制 SHA256=`29792a4b616392e8e7a6f217ce91a5f3914206c2cd8359bd9eefc70ea5d41851`，生产引擎、PTX3/canonical、sm89。使用B1=20、sigma26的有效Stage1 save，保持设备与工具链条件；arena6300、fold640 MiB，host项fold=0。短校准、短batch选型、Graph及tune运行写回关闭。每格4次/侧、交错off/on和on/off，无丢弃预热；全部80条曲线GMP/selftest与抽查bad=0，因子/rootfold指纹、数学NTT长度分布及S4分块相同。

各格中位数之和57.009633→56.002389秒，减少1.77%。这是所选固定D矩阵，不是一次生产任务或自动选型全位宽矩阵，不能外推所有生产B2。最大样本的NTT模块 `full_peak` 3190.44→3184.44 MiB；它是模块账本峰，不是进程联合显存峰。

M521最大仅k19，开关两侧数学内核计划相同，首轮相差3.483 ms。独立8次/侧复测为0.143223→0.142591秒，未复现持续回退；同组M2203为0.605061→0.594289秒。两组原始结果分别保留，不替换首轮矩阵。承载项差7.640 ms，小于on侧MAD31.450 ms，当前没有稳定收益证据。

另有4423-bit、7995-bit普通/承载、P155520四组各一次/侧的完整叶子诊断，共8条，全部目标N上的叶子指纹一致；普通余因子与承载投影也一致。这是完整路径一致性证据，不能替代独立GMP；诊断时长不计入性能。正式80条曲线高利用率采样736点，SM1545–1800 MHz、中位1800，功率14.51–54.83 W、中位47.72，设置上限不代表每条曲线实际恒频恒功耗。

## 管理员剖析

Nsight Systems2026.1.3对M4423、B2=2.6×10¹⁰、D60060、batch256各采集一条完整曲线，输出与未插桩样本一致。两侧kernel数20,730→19,551，outer累计1.770102→1.312061秒，tile累计1.684472→1.696273，S4归约0.323136→0.322963。剖析时长不进入上面的正式样本。

本进程kernel/copy/memset事件并集窗口为6.878430/6.401491秒，其中无本进程GPU事件区间合计0.683408/0.648367秒，约9.94%/10.13%。它既不证明全卡空闲，也不能将全部空隙归因CPU计算。`cudaMemcpy` API持续时间包含等待GPU；其5.024548→4.595080秒不能解释为纯PCIe传输，也不能再与kernel总时间相加。

Nsight Compute2026.2.1按Systems精确kernel身份/第几次调用采集k23正向热点，均16次重放，核对grid、CTA、寄存器及完整曲线结果。时钟/缓存控制均为none，没有更改GPU设置。指标如下：

| 指标 | M4 pass | M6 pass |
|---|---:|---:|
| grid.x / CTA线程 | 512 / 256 | 4096 / 256 |
| registers/thread | 94 | 48 |
| static shared/block | 128 bytes | 18,432 bytes |
| registers允许的CTA/SM | 2 | 5 |
| 实测活跃warp占峰值 | 30.82% | 81.34% |
| SM throughput占峰值 | 33.10% | 56.86% |
| DRAM throughput占峰值 | 88.45% | 91.59% |
| replay SM时钟 | 1797.35 MHz | 1796.33 MHz |

单个pass分别处理4/6层，工作量不同，不能用单kernel秒数直接计算整次NTT加速。两者DRAM都接近高吞吐，M6的较高占用率与更少全数组遍历共同适合该范围；不能认为继续加warp会按比例提速。完整曲线及算子对照才是性能依据。
