# Stage1 性能依据

## 口径与当前策略

CUDA Montgomery 默认 ladder、TPB128、按容器选择 TPI，分档寄存器；PRAC 默认不编译。GPU Edwards 默认窗口 NAF。已测局部最佳不能扩大到其他位宽/设备或直接替换默认。

共享CGBN专用平方和carry-save装配融合均为显式构建实验，默认保持原CGBN。4060 Laptop的三容器、Mont0／Edwards完整B1=5000对照均未获得收益；逐批save、独立CPU验算、算子吞吐与真实点核NCU见[专用平方验证](CGBN_SQUARE.md#平方装配与redc融合的完整stage1资格)。

完整曲线 wall、GPU kernel 时间、批量摊销 s/curve 和短时投影分别报告。生产 B1=10e6…260e6 的短时采样按完整/窗口工作比投影，排除冷准备、最终归一化/save；checkpoint 不算已完成曲线。

重复实验采用预热及相反或交错顺序，保留完整矩阵、失败样本和原始日志。CGBN 主矩阵每个条件测一批，NTT 主矩阵每个条件测三批。管理员 NCU 会重放，采集时间不计作吞吐。Nsight Systems 的自身事件间隙不等于整卡空闲比例。

### 样本与计时

- **RTX 4070 Ti NTT** 在 2610 MHz 上比较相同的 29 个完整梅森数（61–262139 位）。0.62.4 在 1–128 条范围自适应搜索，0.62.3 穷举 1–32 条。各版本用获选计划实测每种曲线三次，B1=1024 用于 M61、M127 和超过 20000 位的输入，其余用 B1=10000。两版都取阶梯 CUDA event 区间。见 [RTX 4070 Ti 全位宽矩阵](#rtx-4070-ti-全位宽矩阵)。
- **NTT 0.62.2** 使用 GPU1 RTX 4060 Laptop，覆盖 61–262139 位的 26 个完整梅森模数。每个指数重新测量 1–32 条曲线，在调优候选中选实测吞吐最高的计划。两种曲线复用计划，各跑三次真实 Stage1，取 ladder 的 CUDA event，排除准备、回读和发布。
- **RTX 4060 Laptop 历史 NTT** 与本卡 0.62.2 共用 26 个指数、B1 和阶梯计时边界，每指数各测三次。Edwards 最早一版是 0.60.0，Montgomery 是 0.59.9。跨版本曲线体现各版本的实现、计划和并行数。
- **CGBN 0.62.3** 使用两张 GPU，在相同的 13 个 318–16272 位余因子上按曲线族各测一批。两种曲线都采用主循环设备计时。见 [CGBN 两卡对照](#cgbn-两卡对照)。
- **Prime95** 使用 4.0 GHz 单核原生 Stage1 计时。Edwards 覆盖 29 个指数，Montgomery 覆盖历史的 13 个指数，每指数三次。历史数据 B1=1,000,000，Edwards 补测按各指数的 B1 归一化。图中按完整梅森指数定位，GWNUM 仍用原始 `k,b,n,c` 设置。日志未记录精确程序版本。见 [CPU 基准和补测](#prime95-单核基准与-b1-外推)。

GPU 用实际批次时间除以参加设备主循环的曲线数，再乘 `1,000,000 / B1`。NTT 排除曲线构造、初始化、末点回读、GCD 和发布。阴影覆盖两张 GPU 各自最新的 NTT 和 Prime95 三次样本的最小至最大值。RTX 4060 Laptop 的 0.62.2 相对 0.61.3，两类曲线各 26 个指数的中位耗时均下降，降幅中位数分别为 Montgomery **32.5%** 和 Edwards **32.8%**。4060 Laptop 上，PARAM0 的 NTT 在 M12511 和 M16319 的折算耗时较低，Edwards 的 13 个共有指数均以 CGBN 耗时较低。见 [RTX 4060 Laptop NTT 全位宽矩阵](STAGE1_MERSENNE_NTT.md#最佳配置全位宽矩阵) 与 [历史 Prime95 单核基准](#prime95-单核基准与-b1-外推)。

固定形状对照分别测量短逆变换、前向读入融合、块宽和进位的收益。0.62.3 另有 2560／5120 点归约与 16384 点单曲线调优的专项复测。见 [短逆变换](STAGE1_MERSENNE_NTT.md#短逆变换)、[前向 tile 与进位](STAGE1_MERSENNE_NTT.md#前向-tile-与进位)、[0.62.3 专项复测](STAGE1_MERSENNE_NTT.md#加权归约与-16384-点单曲线调优) 和 [同卡模平方对照](STAGE1_MERSENNE_NTT.md#同卡完整模平方与-prpll)。

## Edwards 与 Montgomery 的 Stage1 耗时差

同一张卡上，对相同输入、B1 和批量计算 `100 × (Edwards 主循环耗时 / Montgomery PARAM0 主循环耗时 − 1)`。负值表示 Edwards 耗时较少。CGBN 横轴为剥除已知因子后的余因子位宽，NTT 横轴为完整梅森模数的位宽。

### CGBN 两卡对照

![两张 GPU 上 CGBN Edwards 相对 Montgomery PARAM0 的主循环耗时差](attachments/stage1-cgbn-ed-mont-delta.png)

2026-11-12，两卡用同一份 ECM-ELF 0.62.3 测量版（CUDA 13.3.73、sm89、MSVC 14.51.36231、驱动 610.88），各测 13 个 318–16272 位余因子。每张卡先短跑预热两种曲线，再按指数交替安排 Edwards 和 PARAM0，正式测量每种曲线、每个输入一批。两卡均为 TPB128、每 SM 发射两个 block。同一张卡的两种曲线使用相同的 TPI、B1、批量和初始 sigma。按 TPI 4／8／16／32，B1 依次为 1,000,000／200,000／50,000／10,000。4070 Ti 批量为 3840／1920／960／480，4060 Laptop 为 1536／768／384／192。

Edwards 取原有 `loop_gpu_ms`，Montgomery 在测量版中另记每次主循环发射前后的 CUDA event 并求和。两者都排除初始化、Edwards 字典、回读、GCD 和发布。早期 4060 的全局 `gputime` 仍可从 `data/experiments/stage1_unified_4060_0600/cgbn/` 复算。见 [Edwards 计时](../../src/ecm/stage1/edwards/cuda/edwards_runtime.inl#L119) 与 [Montgomery 发射位置](../../src/ecm/stage1/montgomery/cuda/runtime.cu#L645)。

### NTT 两卡对照

![两张 GPU 上 NTT Edwards 相对 Montgomery PARAM0 的主循环耗时差](attachments/stage1-ntt-ed-mont-delta.png)

RTX 4070 Ti 使用 0.62.3 的 29 个指数，RTX 4060 Laptop 使用 0.62.2 的 26 个指数。同卡、同指数的两种曲线复用相同的卷积类型、变换长度、digit 位宽、pass、Graph 参数和批量。每种曲线取三次设备计时的中位数。阴影以 Edwards 最短／Montgomery 最长和 Edwards 最长／Montgomery 最短给出样本比值范围。55 组中有 **54 组的中位耗时差在 ±0.65% 内**。4070 Ti 的 M127 为 −1.61%，样本比值范围为 −4.06% 至 +1.50%。两张卡的有符号差异中位数分别约为 +0.01% 和 −0.05%。

Edwards 仍用 Atkin–Morain 构造曲线与初始点，主机用 `u = (1+y)/(1−y)` 转为 Montgomery x 坐标。Suyama PARAM0 直接准备自己的 Montgomery 初始点和曲线系数。两种初始状态随后都交给同一个 x-only 二进制阶梯。每步的差分加、倍点、NTT 乘法和进位执行同一套设备代码。曲线构造、归一化、因子检查和保存均在图用的阶梯计时之外。见 [Edwards 映射和 NTT 入口](../../src/ecm/stage1/montgomery/cuda/ntt/workflow.cpp#L88) 与 [共享阶梯步](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu#L751)。

本批 Montgomery 使用 `lcm(1…B1)`，Edwards 使用其 48 倍。B1=1024 时两者分别执行 1478 与 1484 步，Edwards 多约 0.41%。B1=10000 时分别为 14446 与 14451 步，多约 0.035%。例如 M262139 的整段 Edwards 耗时在两张卡上分别多约 0.40% 与 0.41%，按各自步数归一化后差异均小于 0.01%。见 [标量构造](../../src/ecm/stage1/montgomery/cuda/ntt/workflow.cpp#L144)。

百分比图的 `--cgbn` 读取 `data/experiments/stage1_cgbn_curve_cost_0623/{gpu0,gpu1}/`。每个 `--ntt-pair` 按 Montgomery、Edwards 顺序传入同卡的两份 `summary.json`，分别使用 4060 的 0.62.2 矩阵、4070 Ti 的 0.62.3 主矩阵和 radix-5 补测。逐点数据 `cgbn_curve_delta.csv` 和 `ntt_curve_delta.csv` 保存在 `data/benchmarks/stage1_cgbn_curve_cost_0623/`。见 [百分比绘图脚本](../../tools/bench/plot_stage1_curve_cost.py) 与 [CGBN 工作行生成器](../../tools/bench/prepare_stage1_gpu_matrix.py)。

## 探寻最佳曲线并行数量

设 `B` 为曲线数，`T(B)` 为固定阶梯步数的整批设备耗时。追求吞吐量时选实测 `B/T(B)` 最大的批量。95% 档取达到峰值吞吐 95% 的最小实测批量。关心单批返回时间时直接比较 `T(B)`。

### RTX 4070 Ti 全位宽矩阵

ECM-ELF 0.62.4 在 RTX 4070 Ti 12 GiB 上重测 29 个 61–262139 位完整梅森数，包含 2560／5120／10240 点的 radix-5。每个指数用原生调优在 1–128 条范围比较线性和加权候选。每个候选先预热 100 步，再取三次 192 步样本的中位数。达到停止倍增的条件时会交替复测。本轮自适应搜索每个指数实际测了 21–34 个不同批量。Edwards 与 PARAM0 各按获选计划运行三次实际 Stage1。M251 的 Edwards 有两条曲线在构造时已找到因子，127 条中有 125 条进入阶梯，图表按 125 条摊销。

构建为 Windows CUDA 13.3.73、sm89、MSVC 14.51.36231。自适应调优和生产矩阵的 2478 个 GPU 利用率至少 50% 的遥测样本均为 2610 MHz，板功耗 17.90–246.19 W，功率上限读数 285 W。174 个生产批次逐组复核 20,676 条曲线结果，两个曲线族各有 898 条与 0.62.3 同 sigma 的记录，均一致。日志中的因子均通过整除检查。生产中显式分配和可用显存差值的较大值最高为 104 MiB，出现在 M131071 的 88 条 Edwards 批次。

纵轴为归一化吞吐：批次吞吐 `B/T(B)` 除以**同一 NTT 长度**的单曲线吞吐 `1/T(1)`，即 `B·T(1)/T(B)`。各条线在 `B=1` 时均为 1；8 条时 `L=512` 为 7.01，`L=16384` 为 2.94。批次耗时中位数见上表。

曲线数增加的是同一 stream 中每个算术阶段的 `grid.y`。每位的三个 forward 批量是 `4B / 5B / 2B`，inverse 是 `4B / 4B / 2B`。一次 tile pass 的块数等于该次变换数乘 `L/2^t`。例如 `L=512,t=9`，第一层单曲线只有 4 块，8 条可给 32 块，让 24 SM 有更多独立工作；`L=16384,t=12` 时这一层单曲线已经有 16 块。较大的 L 还提高每条曲线的显存流量和归约工作，扩批的边际收益更小。较小 tile 增加块数但可能多一次 outer pass；因此 tile 也需按 `(L,B)` 筛选。比如 `L=2048` 的实测 1 条选 t=8，8 条选 t=11。

对最长的 `L=16384` 另以相同模数、B1=256、362 个 ladder 步复测（各 1 进程、3 样本，均核对 GMP）。1／6／7／8 条的批次为 148.333／346.801／398.682／448.982 ms，吞吐分别为 6.74／17.30／17.56／17.82 条/秒。6 条已达 8 条吞吐的 **97.1%**，批次延迟少 **22.8%**，适合作为该长度的折中；仍要最高吞吐时选 8 条。该复测的 18 个高利用率（≥20%）遥测点为 1500 MHz、3.24–21.69 W、62–66 °C，证据见 `batches_long_l16384/`。

复现批量扫描可用 `tools/bench/bench_stage1_mersenne_ntt.py --mode batches --rounds 2`，同时指定 `--probe` 与新 `--output` 路径。最长档的一曲线平均每步由 B1=41 的约 1.07 ms 变为 B1=256 的约 0.410 ms，两次计时合并了 Graph 尾部和中间操作数等成本。绘图参数 `--input` 指向扫描的 `summary.json`，`--output` 指向 `data/figures/` 下的 PNG。见 [批量吞吐绘图脚本](../../tools/bench/plot_stage1_ntt_batch_throughput.py)。

### 输入与工况

GPU START 工作行中的已知因子逐项通过整除验证，计算出的实际 N 位宽与原生 GPU 输出相符，并与 CPU 原工作行的分解目标一致。本节历史图的横轴使用目标余因子位宽。Prime95 的 ECM 参考源码用 `setN` 剥除已知因子以确定因子检查目标，GWNUM 的主循环仍按原始 `k,b,n,c` 建立 FFT。因此实际算术位宽对比图将 Prime95 放在完整梅森指数处。CPU screen 日志未记录已知因子列表及精确二进制版本。参见本地 Prime95 31.06b01 `ecm.cpp:1199,1220,6885,7208` 和 [按算术位宽对比](#stage1-ntt-与-cgbn-和-prime95-对比)。

两次 GPU 测量均使用 device 0、RTX4070 Ti、60 SM、TPB128、120 个 block，即发射 2 block/SM；实际驻留仍受资源约束。Edwards 为 NAF w6、HWCD 倍点，Montgomery 为 Suyama PARAM0。TPI4/8/16/32 对应 B1=1e6/2e5/5e4/1e4，批量为 3840/1920/960/480。不同构造使用各自的进位余量，容器不强制相同：M1009 的 Edwards/Montgomery 为 **384/512 bits**，M12511 为 **12288/13312 bits**；不能把这些点的差异全部归因于点运算公式。

Montgomery 原生运行日志直接记录卡名和 SM 数；Edwards 的 device 0 由分析时设备枚举对应到同一张 RTX4070 Ti，枚举时驱动为 610.88，完整设备身份保存在忽略的证据目录。**运行时 GPU 频率、功耗及其他并发负载未记录**。另外，Montgomery CPU 日志的执行时段约为 17:33–17:40，GPU 为 17:34–17:40，二者重叠；这是现有工况参考，不宣称隔离运行。精确 CPU 型号和 Prime95 版本未写入这两份 CPU 日志。

## Prime95 单核基准与 B1 外推

历史 13 档的两类曲线均为 B1=1,000,000、4.0 GHz 单核，每输入 3 个有效计时。日志将 worker 绑定到逻辑 CPU 1，并报告 AMD Zen 架构。精确 CPU 型号、Prime95 版本及 CPU 功耗未记录。Montgomery 是日志中的曲线构造名称，Suyama sigma 与 PARAM0 的对应参照 Prime95 `ecm.cpp:4960–4961,7359`。

### avx-ecm 单核对照

对照 [独立版 avx-ecm `118e015`](../reference/AVX_ECM.md) 与 ECM-ELF 0.62.14。Windows 主机为 Ryzen AI 9 HX 370，两者固定逻辑 CPU 1，本轮未独立采样实际频率或功耗。输入为完整梅森数，十档覆盖 127–4093 位。`B1=B2=100000`，各档每路径运行三次，主矩阵交错运行，32 位掩码修正随后单独补测。52 位与 ECM-ELF IFMA 每批 8 条（sigma=26…33），32 位每批 16 条（sigma=26…41）。Montgomery 对照均使用 Suyama PARAM0 和未乘额外挠子因子的素数幂标量。ECM-ELF Edwards 使用 NAF w8，提供不同曲线构造下的吞吐参考。

avx-ecm 用 GCC 15.2 `-O3 -march=znver5` 构建，链接与 ECM-ELF 相同的 GMP 6.3.0 Zen3 DLL。Windows 构建修改了字符串声明及 64 位 GMP 接口，独立克隆保留原样。两份实验构建另行标记。一份只将 52 位 IFMA 的载体识别上限从 2047 位放宽到 4096 位，另一份只修正 32 位梅森加减的两处掩码。ECM-ELF 使用 MSVC 14.51.36231，关闭指数缓存和周期检查点。

左图使用 avx-ecm 原生日志的 Stage1 时间，从曲线构造完成后开始，至最终 GCD 和 save 写入前结束。右图统一使用进程启动至退出的墙钟。avx-ecm 在启动时筛至 \(10^8\)，与本次 B1 无关，计入右图。两图均按实际曲线数摊销，点为三次中位数，误差线为最小到最大实测值。只绘制通过存档和因子校验的 avx-ecm 档位。

![avx-ecm 与 ECM-ELF 单核 Stage1 4K 吞吐](attachments/stage1-avx-ecm-4k.png)

原版梅森路径中，52 位 IFMA 的 Stage1 循环吞吐是 52 位 FMA 的 1.36–1.75 倍。跨过 2048 位后，原版 IFMA 通用 REDC 未通过校验。M4001 上，通过校验的原版 52 位 FMA REDC 为 2.335 秒／曲线，扩展识别版 52 位 IFMA 折叠为 0.582。后者与 ECM-ELF Montgomery 的 0.580 基本持平。ECM-ELF Edwards 为 0.428，较该扩展版少约 26.5% 墙钟。FMA REDC 与 IFMA 折叠的差值同时含指令路径和归约方式的变化。

扩展识别版与 ECM-ELF Montgomery 在 2053–4093 位的五个墙钟中位数相差不超过 4.1%。修正掩码后，32 位梅森内核仅在 M127 的采样点领先 52 位 IFMA，Stage1 循环为 0.0053 对 0.0075 秒／曲线。在 M521–M2017 的四个采样点，32 位用时为 52 位 IFMA 的约 2.0–2.8 倍。16 lane 的优势在这些档位抵不过 32 位算术的开销。

用 ECM-ELF PARAM0 对拍 1,320 条存档，覆盖 32 位构建的全部 16 条 lane，比较可逆分母的仿射 X、不可逆分母的 GCD 和报告因子。原版 32 位梅森路径有 120 条奇数索引 lane 与参考结果不符，修正掩码后 240 条全部通过。原版 52 位 IFMA REDC 在本次五个 2K 以上输入的 120 条记录均不符。另以独立 Python 整数梯在 `B1=1000` 完成 120 项检查，复现 M991、M4001 在 sigma 26 的已知因子 8218291649、24007。

CPU 的六组主循环中位数都以 **w12** 最快。w10 与 w12 的循环吞吐相差约 0.8%–1.8%，字典却只有四分之一。短任务用 **w6–8** 更合适。IFMA 在 M1279、M4253、M8191 的整批最短中位数分别为 w8、w6、w6，其中 M8191 的 w4 与 w6 只差 0.1 ms。GMP 标量分别为 w6、w8、w8。M8191 的 IFMA 从 w12 改到 w6，主循环从 197 ms 升至 213 ms，初始化却从 708 ms 降至 90 ms，整批墙钟从 995 ms 降至 405 ms。更大的 B1 能摊薄准备成本，本轮没有测量生产 B1 的最佳窗口。

### 长任务的窗口选择

点运算公式及常用 B1 的实际列数与非零数见 [Edwards NAF 算术成本](../architecture/NAF.md#点字典与执行成本)。

比较 w10 与 w12 时，用相同位宽和批量的整批主循环时间。设 w12 的循环比 w10 快 `r=1−Tloop12/Tloop10`，多出的字典准备时间为 `ΔD`，则 w10 的主循环超过 `ΔD/r` 后，w12 才预计占优。用本页短测估计，1279／4253／8191 位 CGBN 在两卡的门槛约为 1–2／4–8／14–24 秒每批；CPU IFMA 八路约为 6／19／50 秒每批，GMP 单曲线约为 0.4／1.8／4.5 秒。这些是同形状外推，完整大 B1 未复测。

生产口径是数百条曲线、吞吐折算数十秒／曲线，整批约上万秒。每批只编码一次，点字典一次为所有曲线各建一份。对比窗口时将编码和建表的整批时间差除以曲线数，再和摊销主循环的时间差相加。以 8191 位的 4060 Laptop、384 条曲线、整批 10,000 秒为例，B1=260e6 的 w12 主机编码约 0.45 秒，字典 CUDA event 约 0.56 秒，分别摊销约 1.2／1.4 ms 每曲线。这两项合计约占整批的 0.01%。按短测循环比值估算，w12 对 w10 节省约 1.7% 的整批循环，量级为 170 秒。这是固定批量的估算，完整生产 B1 未复测。

在这个长任务口径下，若 w12 能在原批量下放入预算，CGBN 优先试 w12，再用运行日志对比 w10 的实测主循环吞吐。若 w12 迫使减少批量，比较两个批量的曲线／秒。8191 位上 w12 的字典为 w10 的四倍，4060 Laptop 的 384 曲线约用 1.50 GiB，4070 Ti 的 960 曲线约用 3.75 GiB。预算有限时从 w10 或 w8 开始。GMP 长单曲线可先试 w12，8191 位 IFMA 八路整批的估计门槛约为 50 秒。

以 8191 位、B1=260e6 为例，加上编码和点状态后，4060 Laptop 的 384 曲线在 w10／w12 需要约 502／1710 MB，4070 Ti 的 960 曲线约需 1114／4134 MB。若请求 w12、配置 `naf_memory_mb = 512` 且设备空闲预算充足，前者会选 w10，后者会选 w8。

另用 ECM-ELF 0.63.1 的 sm89 三容器构建在 GPU1 RTX 4060 Laptop 上测实际单曲线。M8191、B1=100000、sigma=20260922、HWCD、8192/TPI16，关闭周期检查点，w8／w10／w12 各交错运行三次，九个存档末点一致。利用率至少 50% 的 124 个遥测点均为 1500 MHz、8.26–9.16 W。CUDA event 字典加主循环的中位数依次为 **43.463／42.490／42.046 秒**。w12 的 4 MiB 字典比 w10 的 1 MiB 多花约 276 ms，主循环省约 720 ms，合计省 444 ms（1.0%）。同形状估算 w10 到 w12 的门槛为约 16 秒主循环，其他位宽或设备需重新测量。证据见 `data/experiments/edwards_naf_config_single_8191/summary.json`。

## CUDA Edwards 倍点 HWCD 与 2XY

![两张 GPU 上 2XY 相对 HWCD 的 GPU 主循环和整批墙钟省时率](attachments/stage1-edwards-hwcd-2xy.png)

2XY 的主循环收益从 347 位的 **5.4%** 降到 8191 位的约 **0.2%**。M12511 上两卡的主循环都约慢 **0.05%**，整批墙钟有快有慢。曲线在 4253 位和 16319 位仍有局部上升，因此单凭位宽无法确定收益。8K 起端到端收益大多落在配对波动内。

M16319 在 4070 Ti 的三对复测中，主循环中位时间从 **36.416 s** 降至 **35.970 s**，配对省时中位数 **1.28%**，范围 **1.22%–1.39%**。4060 Laptop 在同位宽省 **0.16%**。两卡整批墙钟的配对省时中位数分别为 **2.27%** 和 **0.05%**。图中 4070 Ti 该格采用三对复测，初次三对另保留。初次有一批 HWCD 在运行中出现功耗和片长突变，主循环 48.670 s，同轮 2XY 为 35.887 s，表面省时 26.27%。后两对只有 1.35% 和 1.52%。突变来源未确定。

两条路径在同一个 CGBN NAF 核内计算相同的点。2XY 直接求 $E=2XY$，HWCD 用 $(X+Y)^2-X^2-Y^2$ 求 $E$。默认的 CGBN 模平方调用相同的 Montgomery 乘法核心，2XY 在每列省去两次模减。按 32 位 limb 数 $n$ 估算，模加减的工作量随 $n$ 线性增长，CGBN 朴素 Montgomery 模乘约随 $n^2$ 增长。这个量级关系解释了加减节省为何可能被宽位模乘摊薄。实际运行还受容器、TPI、指令安排和寄存器占用影响。见 [NAF 架构](../architecture/NAF.md#点字典与执行成本) 和 [CGBN 模平方与模乘入口](../../third_party/cgbn/include/cgbn/impl_cuda.cu#L1027)。

如果构建启用专用平方，粗略的单次倍点省时为 $T_S-T_M+2T_{\mathrm{sub}}$。平方比乘法快得足以抵消两次模减时，HWCD 也可能更快。该式按算子时间相加，只用于判断量级。

独立算子探针使用相同的 CGBN 域函数、容器和发射几何，在七个位宽上分别测模加、模减、模乘和模平方。每核每条链 10,000 次相依运算，先预跑一轮，再按正反顺序各类交错测五次，取 CUDA event 除以批量操作数的中位数。两卡的模减／模乘成本均从 347 位的 **38% 左右**，降到 8191 位的 **1.3% 左右**、16319 位的 **0.28% 左右**。这与宽位下加减节省被模乘摊薄一致，也说明 4070 Ti 在 M16319 的 1.28% 收益无法由孤立模减成本直接预测。探针记录与源码位于 `data/experiments/stage1_edwards_doubling/field-gpu*-verified.csv` 和 `field_probe.cu`。探针本身未另采功耗。

## GPU Edwards 主机等待与自适应切片

Edwards binary/NAF 使用阻塞设备等待，并按约 100 ms 目标调整切片。正数 API 参数允许固定切片。NAF 在检查点、停止和完成边界按需导出坐标。实现、边界和停止语义见 [Stage1 架构](../architecture/STAGE1.md#gpu-edwards)。以下为原等待策略的独立对照。

## 资源与瓶颈

4608/TPI16 PRAC 的一个自然分配样本为172 regs、实际176，TPB128 时寄存器最多容纳2 blocks/SM；cap168 可容纳3。强制 TPI32 样本为109/112 regs、4 blocks/SM，但同时减小每 block 曲线数、增加 padding/跨 lane 成本，端到端未因此更快。

已采集的 natural/168/TPI32 achieved occupancy 为16.34%/19.37%/27.12%，issue active约30.60%/30.93%/38.93%。这些 profiler 值说明资源权衡，不能独立证明瓶颈成因或加速比例。DRAM 吞吐很低，主要成本仍在依赖多精度算术、发射与局部存储/调度。

normalized PRAC 按 ADD=A、DBL=D 统计：ADD=4M+2S，DBL=3M+2S；若平方与乘法同价，工作权重为6A+5D。该权重用于投影，不代表固定 GPU 周期。

## 限制与后续

## 收尾与输入归一化
