# CUDA Stage2：CPU 归一化、求逆与 GCD 的成本

## 结论

当前 CUDA 生产路径已经使用 **GPU 批量模乘 + CPU/GMP 少量求逆与 GCD**。把现有 CPU GCD 再改为 CPU 没有增量收益；把全部归一化移到 CPU 也不能普遍加速。

本轮算子对照表明：

- **批量 baby 归一化保留 CUDA 混合路径。** 8192 点时，它比全 CPU 快约 2.9～7.8 倍。8191-bit、仅1024点时，全 CPU 快约31%，适合进一步研究小规模分流。
- **少量 GCD 保留 GMP。** 16个 GCD 时，GMP 比本轮实验性 CUDA 二进制 GCD 快约41～350倍。该 CUDA GCD 是对照原语，不是现有生产功能，也不代表经过优化的 GPU GCD 库上限。
- **可继续优化尾部块乘积。** 8191-bit、8192叶子时，全 CPU 块乘积/GCD 为119.0 ms，生产 CUDA 块乘积内核加 CPU GCD 为252.2 ms。该算子区间减少52.8%；完整 Stage2 的收益尚需固定输入 A/B。
- 既有完整曲线中，baby 归一化约占0.51%～1.86%，CPU baby 求逆占0.026%～0.079%，CPU giant 求逆在可分辨样本中占0.018%～0.20%；整个尾部块乘积/GCD占0.54%～4.53%。这些区间嵌套，不能相加为阶段总占比。

图中前三幅均采用 `CUDA墙钟/CPU墙钟`：大于1表示CPU较快。右下角来自不同输入、不同频率的完整曲线历史证据，不能把其绝对时间与本轮算子时间直接相减。

| 环节 | GPU 工作 | CPU 工作 | 代码入口 |
|---|---|---|---|
| Baby 归一化 | 256点组内乘积树、逆传播、负仿射系数 | 每组一次 `mpz_invert`；异常组恢复 | [points.cpp:614](../../src/ecm/stage2/cuda/points.cpp#L614)、[baby_giant.cuh:16](../../src/ecm/stage2/cuda/device/baby_giant.cuh#L16) |
| Baby 设备路径不可用 | 点生成；普通坐标读回 | 256点分组的前缀批量求逆与仿射转换 | [engine.cpp:362](../../src/ecm/stage2/cuda/engine.cpp#L362) |
| 驻留 Giant | 16点段乘积、64段组乘积，保留齐次叶子 | 每组一次求逆，累计 Gamma；非单位组恢复 | [points.cpp:261](../../src/ecm/stage2/cuda/points.cpp#L261)、[points.h:78](../../src/ecm/stage2/cuda/points.h#L78) |
| 尾部叶子归并 | 每64叶子一个块乘积 | 对块乘积做GCD；命中后细查叶子 | [batch.cpp:915](../../src/ecm/stage2/cuda/batch.cpp#L915)、[point.cuh:396](../../src/ecm/stage2/cuda/device/point.cuh#L396) |

生产优化默认值在 [options.cpp:365](../../src/ecm/stage2/cuda/options.cpp#L365) 启用 `NTT_BABY_DEVICE=1`；引擎内的环境变量读取回退值0不是最终生产默认值。预算不足等条件仍可回退CPU批量归一化。

Giant 常规驻留路径并不逐点计算全部仿射坐标：它保留 `Z_i·X−X_i` 齐次叶子，通过分组求逆与 Gamma 修正缩放。因此不能将“所有 giant 逐点归一化”的成本套到当前实现上。

- CPU：Ryzen AI 9 HX370，未固定CPU频率；单线程GMP，使用仓库 `gmp-zen3/dist`。Windows11、MSVC14.51.36231。功耗读数不作为性能或能效结论依据。
- 每实现显式预执行1次，随后交替次序计时3次，表取中位数；原始min/max保留。预执行是本算子试验协议，与生产tune的默认无warmup规则无关。
- 归一化：实际模数位数512/2203/4423/8191，确定性随机非零X/Z、素数模数，Montgomery表示；不包含点生成。输出为主机端普通表示的负仿射系数。
- GCD：同位宽奇合数 `257·q`。1个GCD使用随机余数；16个以上混合随机余数、0、257、q、N，覆盖单位、非平凡因子和饱和。所有对照使用相同输入；该混合分布不是生产命中率模型。
- 块乘积/GCD：主机随机叶子、64叶子一组、至少一个非单位块。CUDA使用实际生产块乘积内核；因Montgomery缩放是模N的单位，核对最终GCD相等，不要求中间乘积表示相等。
- CUDA/主机传输数组与设备工作区预分配，计时不含上下文建立、夹具生成、初始驻留输入上传、结果验证及清理。CPU归一化保留每调用GMP前缀临时对象的分配；这与CPU回退实现一致，并非排除所有GMP内部分配。

### 对照边界

| 测试 | 共同输入/输出边界 | CPU计时包含 | CUDA计时包含 |
|---|---|---|---|
| 归一化 | 驻留X/Z → 主机系数 | X/Z读回、导入、256点批量求逆、负仿射转换、导出 | 生产乘积树、组根读回、GMP求逆、逆根上传、逆传播/叶子核、系数读回 |
| GCD | 驻留余数 → 主机完整GCD | 余数读回、导入、GMP GCD、导出 | 实验二进制GCD、完整结果及步数保护标志读回 |

## 归一化：CPU只在部分小批量占优

单位ms，均为n=3中位数。每格CPU/CUDA处理同一批点。

| N bits | 1024点 CPU | 1024点 CUDA混合 | 8192点 CPU | 8192点 CUDA混合 |
|---:|---:|---:|---:|---:|
| 512 | 0.961 | 0.637 | 7.432 | 0.964 |
| 2203 | 7.245 | 5.050 | 57.745 | 7.380 |
| 4423 | 22.008 | 20.238 | 172.448 | 29.333 |
| 8191 | 56.325 | 81.904 | 450.382 | 154.086 |

8191-bit、1024点的CPU候选节省25.580 ms，耗时减少31.2%，吞吐约为CUDA混合的1.45倍。8192点则仍应采用CUDA；其3个实测值为180.244/154.086/120.738 ms，波动明显，故保留整个范围，不据此精确拟合交叉点。另一冻结会话的同格CUDA中位数为120.649 ms、CPU为449.587 ms，方向一致；不把两次会话拼成同一个n=6样本。

只有4位宽、2个点数，尚不足以建立可靠的CPU分流阈值。高层乘积树并行度较低可能是小批量损失的来源，本轮未用逐核剖析确认其贡献。异常分母恢复仍由原生产实现负责；本轮归一化只验证可逆分母核心，不宣称完成因子恢复路径验收。

| 512 | 0.047 | 1.910 | 0.345 | 2.070 |

16个时CPU分别约快40.5/125.8/226.5/349.6倍。但大批量的结论不同：512-bit、1024个时CUDA实验核2.149 ms、CPU2.771 ms；2203/4423/8191-bit同批量则CPU仍快约2.3/6.6/15.7倍。全量1/16/128/1024结果在汇总CSV中。

## 计算量、传输与收益上限

设实际算术位数为S，`w=ceil(S/64)`，每个值 `L=8w` bytes；baby数P，`g=ceil(P/256)`，最终块数 `K=ceil(P/64)`。

对于P为256倍数且所有分母可逆的baby归一化：

- CPU分组算法约为 `4P` 次普通模乘 + `g` 次求逆。
- CUDA混合算法为 `4P−3g` 次Montgomery模乘 + `g` 次CPU求逆，分为8层乘积、7层逆传播、1次叶子核，共16次核提交。
- CPU候选从驻留输入下载 `2PL` bytes 的X/Z；CUDA混合路径下载 `PL+gL`、上传 `gL+g`，后者含组状态字节。忽略常量和错误恢复，两向合计分别为 `2PL` 与 `PL+2gL+g`。
- CUDA局部工作区约为 `(4P−g)L+g`，包含X/Z、乘积树和系数输出；不包含全局NTT工作区或进程峰值。若只计X/Z之外的新增归一化区，为 `(2P−g)L+g`。
- 因而CPU分流并不会减少所有传输：相对现有混合归一化，它通常要下载更多坐标。收益必须来自CPU算术与提交成本的差异。

最终块乘积：设备执行 `P−K` 次Montgomery模乘，每块最多63次串行依赖，再在CPU做K次GCD。当前主机叶子边界下，相关上传/下载为 `(P+K)L` bytes；全CPU候选可消除这些传输。若未来叶子始终驻留，CPU候选将需要额外 `PL` 下载，必须重新测量。

设一个可替换区间的占比为f，该区间改进倍数为r，则完整时间减少比例为 `f·(1−1/r)`。即使无限加速，收益也不超过f。

- 4916-bit生产样本整个尾部仅0.536%，完全消除这一阶段也最多减少约0.54%的引擎时间。
- 12285/16272-bit小P样本整个尾部约4.5%；这是尾部全消除的上限，**不是纯CPU GCD的占比，也不是已测得的完整加速**。
- CPU baby/giant求逆已很便宜。主要成本仍在点生成、G树、fold/下降及其NTT/S4算术；不应因算子倍数较大而降低这些方向的优先级。
