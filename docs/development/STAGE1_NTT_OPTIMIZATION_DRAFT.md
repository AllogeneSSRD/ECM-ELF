# Stage1 NTT 优化开发记录

## 0.59.2 逆向 tile 直接加载频谱

将乘积的操作数指针直接传给 Stage1 首个 inverse tile。每块处理一个曲线和乘积，沿用原有变换顺序，平方只读同一个输入。共享的 tile butterfly 与逆向外层调度保持统一，独立的 Stage2 tile 入口仍按原方式读写。Stage1 少启动三个 gather kernel，频域临时数组每曲线减少 `4·L` 个 64 位字。

本地 0.59.1 与 0.59.2 均为 CUDA 13.3、sm89、CGBN 5120 档。RTX 4060 Laptop GPU1，驱动 610.88，频率和功耗设置未调整。用完整梅森数、Montgomery PARAM0、LCM 和 sigma 11 起点，关闭定时检查点，按 AB、BA、AB 交替启动，比较三次设备 event 的中位数。计时覆盖阶梯和提交间隔，排除曲线与标量准备、Graph 建立、末点回读和发布。

- B1=256，4003、8191、16001、32749、65521、131071 位，每档 1、4、8 条曲线。18 条件的改善中位数 4.45%，范围 −1.35% 至 7.85%。32749 位单曲线 48.733 → 49.391 ms。
- B1=4096，32749、65521 位各 1、4 条曲线。三个条件改善 2.28–2.57%；32749 位单曲线 751.689 → 763.386 ms。保留这项 1.56% 退化，后续可按实际批次复查 tile。
- 132 次性能运行逐条比对归一化 X、因子与 save checksum。生产验收另覆盖直接提交、Graph、CGBN 与 Python 对照、构造和末点因子，以及改换计划后的真实断点恢复与 Stage2 队列交接。
- 原始数据与 200 ms 功耗采样在 `data/experiments/stage1_ntt_fused_0592/` 的 `matrix/`、`long/`。复测入口为 [compare_stage1_ntt.py](../../tools/bench/compare_stage1_ntt.py)。

## 0.59.3 可选 Goldilocks 加权卷积

增加 `ntt_convolution = "weighted"`。线性卷积保持默认，使用独立打包实例，检查点共用规范整数 X/Z。加权计划以最长 digit 和单域系数界选择最短二次幂，GPU 负责加权打包、变换、逆权重、按位汇入 limb 及回卷进位。详见 [数学与实测](../performance/STAGE1_MERSENNE_NTT.md#加权循环卷积)。

独立 GMP 探针在 32、33、63、64、65、8192、8193、262144 位检查两组 X/Z 的进位边界。4003、8191、16001、32749、65521、131071 位分别用 64 位起始 sigma 跑 4 条真实曲线，全部一致。生产验收另验证两后端的同批构造和末点因子、Python 独立对拍、过短加权长度拒绝、线性中断后切换加权恢复，并确认 Stage2 队列交接和不中断 save 相同。

GPU1 B1=256 矩阵 18 条件的加权设备耗时改善中位数为 25.51%，范围 −3.12% 至 57.92%。长标量 B1=4096 四条件改善 13.47–39.39%。所有 132 次 A/B 运行逐条比较 sigma、X、因子和 save checksum。原始日志及功耗证据在 `data/experiments/stage1_ntt_weighted_0593/`。

## 0.59.4 复用阶梯步内的 E 频谱

第二批的 E 频谱位于第五个平面，两种归约都只占前四个平面，第三批只需重新打包 DiffSq 和 Sum。每个 ladder bit 的前向变换数由 12 降至 11。乘积输入、归一化和检查点语义延续现有两种后端。

GPU1 上分别用线性和加权后端对比 0.59.3，沿用 B1=256 的六位宽、1／4／8 曲线矩阵和三次交替启动。216 次候选和基线运行的 save 与因子逐条一致，生产验收通过。线性条件耗时改善中位数 0.13%，范围 −0.30% 至 1.21%，加权中位数 0.16%，范围 −0.16% 至 0.65%。结果主要在单百分比范围，不能据此估算大幅加速。活跃设备样本均为 1500 MHz，线性 8.27–19.47 W、63–70 °C，加权 8.21–15.06 W、64–66 °C。原始记录在 `data/experiments/stage1_ntt_reuse_0594/`。

## 0.59.5 融合加权系数归约

每个 CUDA block 为 128 个目标 limb 计算所需的系数范围，将相关系数逆权重后放入共享内存，随后在同一次 kernel 汇入 limb。消除了完整系数数组的中间写回和每个 ladder bit 的三次独立逆权重启动。独立的回卷扫描继续处理窄顶 limb 与规范化，前四个频谱平面承担临时输出，第五个 E 频谱保留给下一批。

- 复验两后端的生产路径、同一因子与跨后端恢复。32、33、63、64、65、8192、8193、262144 位的合成状态均通过 GMP 的两组 X/Z 对拍，8193 位的 Compute Sanitizer memcheck 与 synccheck 各报告 0 错误。共享原位逆变换通过了 512、4096、16384 点的八种 tile／warp 组合。
- GPU1 的 18 个 B1=256、四个 B1=4096 条件用三次交替启动对比 0.59.4 加权与 0.59.5 加权。设备耗时改善分别为 0.98–3.43% 和 0.94–2.67%。活跃样本均为 1500 MHz，标准矩阵 8.07–15.19 W、64–69 °C，长标量 10.94–18.12 W、66–69 °C。
- 显式长度 8192、9689 位、B1=20 的 1／4 曲线比较覆盖密集 digit，改善 6.08%／15.73%，活跃样本 1500 MHz、17.79 W、67 °C。另对 4003、32749、131071 位的 1／4／8 曲线做 0.59.1 线性至 0.59.5 加权的累计实测，B1=256，改善 7.11–60.57%，活跃样本 1500 MHz、7.99–19.34 W、64–67 °C。
- 四组对比共 198 次运行，保存点、因子与 save checksum 逐条一致。构建为 CUDA 13.3 / sm89，GPU1 RTX 4060 Laptop，驱动 610.88。原始证据在 `data/experiments/stage1_ntt_carry_0595/`，计时边界与 0.59.2 相同。

## 0.59.6 Stage1 NTT 批量调优

- `ecm.exe --tune ntt` 由 CUDA worker 独立执行。两种后端使用同批合成整数状态，先粗搜并确认平台区，再细测区间和峰值肩部；同一批量下候选必须得到相同的两组 X/Z。调优按吞吐给出峰值与 95% 推荐，生产自动模式按任务实际活跃曲线数选卷积，不改变 sigma 的安排。
- 生产批次容量提高到 32，检查点继续使用原有的 32 位活跃掩码和整数 X/Z。GPU1 在 M4423、B1=32 对 16／32 条两种卷积各自用独立 Python 对拍。M9689、B1=4096 的两组真实队列在 bit 128/5924 中断，换用 weighted、tile 9 和 32 位 Graph 窗口恢复，save 与不中断的 linear 一致，并完成 Stage2 交接。
- GPU1 的实测和可复用 tune 记录在 `data/experiments/stage1_ntt_batch_tune_0596/`。验收入口为 [生产对拍](../../tools/test/test_stage1_ntt_production.py) 和 [自动选型测试](../../tools/test/test_stage1_ntt_tune.py)。使用方式及结果见 [Stage1 NTT 调优与显存](../performance/STAGE1_MERSENNE_NTT.md#批量调优与显存)。

## 0.59.8 共享 NTT 调优矩阵

- Stage1 NTT 与 Stage2 共用 `tune.toml`、发布锁及单个 `[ntt]`。形状复用基于安全长度、digit 位宽、活跃批量和计划约束。Stage1 调优输入的指数不进入摘要表。Stage2 既有分表在读取后归并，旧摘要导入按更新时间选择聚合值。
- 每个 Stage1 候选先执行 100 步，重置原始状态后计时。控制台及日志使用同样的单行摘要，峰值档和 95% 推荐档由本轮数据计算。
- GPU1 复验 Graph 与直接提交预热、跨指数查表、16／32 曲线正确性和续跑。用 `ecm.exe → ecm_cuda_stage2.exe → ecm.exe` 交替写同一个默认文件，保留既有 Stage2 位宽矩阵和两类 NTT 行。CPU 门禁覆盖旧分表归并、行排序、列定义和损坏摘要拒绝。原始结果位于 `data/experiments/shared_ntt_tune_0598/`。

## 0.59.9 按 NTT 长度调度

先推导各输入和卷积类型的合法长度，再按长度依次执行。保留同一输入的算术参考结果，供两种卷积跨长度对拍。控制台和镜像日志开头共用一行类型字段说明。验证入口为 [Stage1 NTT 调优门禁](../../tools/test/test_stage1_ntt_tune.py)，本机证据位于 `data/experiments/stage1_ntt_length_order_0599/`。

## 0.60.0 Edwards Stage1 NTT

Edwards 沿用 Atkin–Morain 构造、原 sigma 规则和 `48·lcm(1…B1)`。GPU 执行前将基点映射到 Montgomery x 坐标，共用 PARAM0 的 NTT 阶梯、线性和加权卷积及 tune。Stage1 save 已采用这个 x 坐标。Edwards NTT 的 checkpoint 身份带 `ntt-v1`，与 CGBN Edwards 各自恢复。完整梅森模数、1–32 条活跃曲线和现有 NTT 内存约束保持适用。

GPU1 RTX 4060 Laptop 上，M4423 的 32 条曲线在 linear、weighted、auto 和 CGBN 下均与独立整数阶梯末点一致。M65 在 B1=8、sigma=9 发布因子 31，M35 在 B1=128、sigma=16 完成恒等点且无 Stage2 点。M9689 的 16 条 Edwards 在 bit 128/5930 停止，由 linear 切换至 weighted 后恢复，存档与不中断版本一致，队列转为 Stage2。Montgomery 原生产回归全部通过。原始记录位于 `data/experiments/stage1_unified_4060_0600/production_check/`。验收入口为 [NTT 生产回归](../../tools/test/test_stage1_ntt_production.py)，比较口径和图表维护在 [Stage1 性能](../performance/STAGE1.md#stage1-ntt-与-cgbn-和-prime95-对比)。

## 0.60.1 加权 radix-5

`5·2^k` 的一层 DIF 由打包融合内核执行，得到五组连续子变换。频谱排列在点乘阶段保持一致，逆向 DIT 后撤销跨段旋转因子并执行 radix-5 逆合并。radix-5 对称与反对称部分共用乘积，五点 DFT 使用六次域乘。正反跨段旋转表合计增加 `8·2^k` 个域元素。两种构造共用设备实现，检查点保持规范 X/Z。

GPU1 对所有 13 个混合长度各测两组接近可用指数上界的合成状态。四条曲线的两组 X/Z 在 Graph、直接提交和 GMP 间一致。20480 点在 Compute Sanitizer memcheck 和 synccheck 下均为 0 错误，32768 点加权二次幂也通过 GMP 对拍。生产回归覆盖两类构造、非法长度、跨卷积续跑和混合 tune 的缓存回读。

同输入的 78 批生产对照全部存档一致。三个较大降阶点节省 12.41%–27.33%，较短降阶点受到新增变换调度开销影响。当前由显式长度启用混合路径。证据和测量脚本位于 `data/experiments/stage1_ntt_radix5_0601/`。见 [指数阶梯与实测](../performance/STAGE1_MERSENNE_NTT.md#指数位宽与变换长度的阶梯)。

## 0.60.2 默认启用较短的混合档

生产与调优均移除 2560 点以下的 radix-5 长度。默认候选在 53249–64000、102401–128000、204801–245760 位分别加入 2560、5120、10240 点。`auto` 对照加权二次幂与线性路径，读取旧 tune 后补测缺失形状。显式 tile 太宽时保留兼容的二次幂候选。旧 tune 的已淘汰测量行继续可读，选型按当前长度过滤。

GPU1 通过生产、续跑及调优回归。24 条 PARAM0 的三个代表指数均由 `auto` 选中对应混合档，与二次幂存档逐条一致。原有 tune 的旧混合行与 Stage2 行均保留。证据位于 `data/experiments/stage1_ntt_radix5_0602/`。

## 0.61.1 点公式数据流探针

初版用额外 GPU kernel 生成松弛 `E`，复核数据依赖后改为由 `A24·E` 的逆变换入口生成并缓存。第三批仍读频谱平面 4，第二批少打包并变换一个操作数，无需额外 kernel。加权模数频谱全批共用。乘加守卫使用 `T·B²+B`，避免按一个完整乘积项预留余量而错过合法边界。旧守卫的初测和最终矩阵分别位于 `data/experiments/stage1_ntt_dataflow_0611/` 与其 `final/` 子目录。

两个实验只由探针设置。要获得生产资格，仍需在代表性 batch 与 tile 上重跑选型，并用真实 Edwards/PARAM0 的队列、save 和 checkpoint 做持出验收。当前的独立 GMP 资格覆盖进位极值、Graph、直接提交和从规范 X/Z 跨实验恢复。算法、上界、上游源码依据及实测见 [Stage1 点公式的数据流](../performance/STAGE1_MERSENNE_NTT.md#stage1-点公式的数据流)。

## 0.61.2 归约写回与打包热点

0.61.1 开发探针将坐标直写、单 tile 打包融合、进位缓存设为三个独立开关。0.61.2 把精确性守卫下的乘加和频谱复用一同接入生产及调优。进位缓存只在加权且指数不超过 65536 时默认生效。宽位宽结果分化明显，225287 位单曲线退化 4.88%，262139 位单曲线省时 8.84%。生产阈值依据前 26 组消融确定，再以 12 组独立条件复测。12 组均改善，CUDA event 中位省时 8.53%。

合成输入的 GMP 对拍覆盖 18 个形状，另有 8 条真实 PARAM0 曲线。Nsight Systems 对 8191／225287 位分别冻结生产规则和控制的逐节点追踪。9689 位、四曲线的单 tile 路径通过 Compute Sanitizer memcheck 与 synccheck。归约缓存只保留本 CTA 需要的 limb，较宽形状的下一项待验证是分段进位和后续 pack 的交接，需同时验证短顶 limb 回卷和规范 X/Z 的回读边界。

生产验收通过两类曲线的因子、保存点和续跑，以及完整和短调优。显存边界用例在 86243 位、12 曲线、20 MiB 预算时从 `dataflow=7` 回退到 `5`。实际驱动用量仍超过限制，运行按原有检查退出。128 MiB 预算下同任务用 `dataflow=7` 完成。

原始记录、重放脚本和版本见 [GPU1 热点消融和复测](../performance/STAGE1_MERSENNE_NTT.md#gpu1-热点消融和复测)。
