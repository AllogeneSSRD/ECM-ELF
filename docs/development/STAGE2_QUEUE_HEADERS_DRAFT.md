# Stage2 投递队列标签堆积修复：开发草稿

## 范围

修复自动 Stage2 投递时重复添加 `[Worker #N]` 的行为，并清理用户指定生产 worktodo 中语义冗余的标签。按仓库修复版本规则，版本由 0.44.6 增至 0.44.7。正式使用规则维护在 `docs/usage/STAGE1.md`；本草稿保留验证记录，完成后由用户决定整理方式。

## 调查与实现

共用入口 `ecm_worktodo_append_unique` 原本在每次新投递时无条件向文件末尾写入 worker 标签，再写任务。任务消费保留标签，因此即使单进程顺序投递也会不断积累空标签；pending 重试的任务去重仍然有效。

修复继续使用原队列编辑锁、活动/finished 去重和原子替换：先移除没有 worker 切换的冗余标签，再将新任务插入目标 worker 最后一段末尾。不存在显式分区时创建标签；文件头隐式 worker 1 直接复用。不同 worker 间的分隔，以及未知方括号标签后的显式边界保留。任务文本及同一 worker 的任务顺序保持不变。

## 验证

原始证据位于忽略目录 `data/experiments/stage2_queue_headers_20261021/`。

- `red/`：真实 park/flush 投递路径在旧实现上未通过已有空分区复用断言。
- `green/`：完整原生投递/恢复测试通过；新增覆盖 8 类队列布局及连续投递/消费，包含生产文件的重复标签形态、中间分区、非连续同编号分区、未知标签、隐式 worker 1、缺失 worker，以及重试后队列不变。原有最短队列、接收方 finished、不可写目标恢复验证继续通过。
- 生产文件在取得同一 `.edit.lock` 后备份并原子清理，移除了原第 21、23 行的两个冗余标签，现仅保留 Worker #1 和 Worker #2 各一个标签。13 条任务的原文、顺序与 worker 归属逐项一致，其他行的原始字节保持。备份位于生产根目录 `backup/worktodo_headers_20261021_020255/`，本轮清理清单在 `production_cleanup.json`。
- 生产可执行程序尚未同步；已运行的旧程序仍使用原投递逻辑，阻止后续新增重复标签需要部署修复版。
