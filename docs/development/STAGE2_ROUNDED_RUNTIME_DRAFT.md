# B2凑整与运行时调优联动草稿

用户授权保留B2凑整并恢复有限运行时搜索，同时每worker使用独立性能文件。本轮目标0.57.8。原始证据放`data/experiments/stage2_rounded_runtime_20261101/`，不修改生产队列或正在运行的配置。

## 定位

生产0.57.7请求B2=550000000000，在D746130／P69120上实际执行567296069340；性能文件按实际B2累积6次正常观察。旧代码明确禁用凑整时的D／baby／链长探测，并用请求B2过滤实际B2记录，所以日志持续保持模型保护。该限制在0.56.3也存在，不是校准边界修复引入。

## 实现约束

- 以请求B2作为最少覆盖合同，各候选D使用自己的实际凑整B2，模型计入扩大的真实工作。
- 性能行继续只用实际B2作为身份，不将不同实际覆盖量混为同一均值；多个请求落到同一实际覆盖平台时可复用。
- 先用便宜的容量估计排名，仅对有限候选作原生准入。原生容量可能随实际B2变化，至多4步求稳定准入，失败则拒绝；保持AutoB2上限与实时显存检查。
- 复用已有每家族搜索、额外时间和重复数预算，不展开D×后端×链长全网格。所有已准入项均覆盖请求B2，按含启动点检查的平均耗时比较。
- 现有紧凑路由hint未记录每候选实际B2，凑整时暂不复用该hint及其失败位图；保留按完整Shape和内存快照缓存的进程内计划。非凑整路径保持原快速缓存。
- 启动成本校准仍禁止继承生产凑整；显式ECM tune仍要求关闭凑整。

## Worker性能文件

复用现有`[workers.N.stage2] stage2_tune_profile`，不增加同义键。worker覆盖全局`[stage2]`路径，CLI仍优先；相对路径以ecm.toml目录解析。更新单一配置元数据、生成的双语说明及两GPU示例，补测试证明不同cwd下两worker仍各自读写文件。

## 验证进度

CPU边界测试通过：每D独立实际B2、精确观察匹配、覆盖平台复用、幂等、AutoB2/整数上限、强制ladder／容量拒绝和非凑整身份不变。现有runtime／point-backend统计门禁通过。

冻结生产tune的只规划对照中，0.57.7没有候选探测，新版恢复探测并分别报告请求与实际B2。该对照在GPU1运行，而原记录来自GPU0；运行时均值要求当前实测条件匹配，跨GPU记录仅供允许条件下的模型预测，不能冒充本卡参考。另用原记录的条件作CPU重放，核对请求B2可匹配其实际凑整B2并保留已有观察。

真实8440-bit输入的8条曲线，固定D6006、请求B2=26000000，实际B2=51879828：baby／chain依次为0/64、0/64、32/64、32/64、32/32、32/32、32/32、32/32；随后关闭学习仍复用32/32，性能文件不改写。全部NF、GMP零错，8条观察完整保留。

两worker文件隔离与自动D搜索通过：每worker10条M127曲线，既观察到D180180／实际B2=28021233240，也观察到D219450／实际B2=28440281100；全部覆盖请求27015978990。worker1文件在worker2执行后SHA不变，未创建全局fallback文件。这里只在GPU1顺序验证，不是两卡性能结论。

非凑整完整曲线对照通过，G根摘要、NTT次数与归约工作相同；启动校准五项回归及真实曲线通过。CPU重放同硬件条件的冻结生产文件，找回D746130／实际B2=567296069340的6次观察。现有runtime／point-backend统计和TOML枚举／worker覆盖及533项布尔别名门禁通过。
