## 0.62.0 基线

0.62.0 的双槽沿用单曲线选型结果，固定 D/P、实际 B2、承载和执行布局。显式固定 D 时两槽使用该值。auto 在同一路线上比较串行和双槽，至少 9 条曲线，去掉头两条和尾一条后要求中段吞吐提高至少 3%，且整批墙钟无退化。双槽显存准入失败时退回单槽。独立尝试较小 D 是基准脚本的行为。 [双槽调度](../architecture/STAGE2.md#双目标阶段调度) · [基准候选](../../tools/bench/bench_stage2_parallel_matrix.py#L137)

同一把阶段锁覆盖整段 baby 点生成与归一化、单个 giant 点块、单批 G 树与 fold、整段下降。每个区间连续持锁，等已提交的 CUDA 工作完成后放锁。一个 giant 点块可以供多批 G 树使用，每批重新竞争锁。两槽各自保留 CUDA 上下文和缓冲，阶段锁交接无需额外回读。初始化、F 树构建、求逆、末尾累积和 GCD、验证及发布处于锁外。父进程目前在子进程退出并确认持久回执后补位。 [阶段锁](../../src/ecm/stage2/cuda/phase_gate.h#L116) · [G 树批次](../../src/ecm/stage2/cuda/batch.cpp#L381) · [补位](../../src/ecm/stage2/task.cpp#L460)

## 本轮实施范围

- [x] **先重叠下一条的准备和上一条的发布。** CPU 线程提前读档、校验并生成候选计划，GPU 提交前按当时的可用显存重新准入。引擎返回并释放工作区后即可补 GPU 槽，结果校验和持久回执决定检查点何时推进。单槽和双槽分别限制 GPU 上运行的曲线数，主机准备和收尾队列保持有界。 [现有准备入口](../../src/ecm/stage2/task.cpp#L123) · [回执与恢复](../architecture/CHECKPOINT.md#74-双槽-schema-4)
- [x] **让 tune 的准备与当前计算重叠。** 路线固定或同一候选明确需要第 2 次重复时，提前准备下一条。预约中的重复在验证通过后才计入样本。依赖最新成绩的选型先准备候选，收到上一条已验证的内存观测后再决定路线，结果 JSONL 和 tune 持久化可以随后完成。 [候选重复](../../src/ecm/stage2/planning/runtime_tune.h#L351) · [观测验收](../../src/ecm/stage2/planning/planning.cpp#L470)
- [x] **把 GPU 交接点前移到下降与块积收尾。** 当前下降叶值回到主机后会重新上传，GPU 计算块积再读回，GCD 在 CPU 上执行。验证驻留叶值直接供 GPU 块积使用。块积和校验快照到主机、工作区可释放后，由下一条接手 GPU，上一条继续做 CPU GCD、GMP 校验和发布。命中因子后的定位或非单位重放需要 GPU 时，按同一设备槽调度。结合 GPU 时间线核对锁内空档，再评估能否把主机准备移出临界区。 [块积和 GCD](../../src/ecm/stage2/cuda/batch.cpp#L953) · [重放条件](../../src/ecm/stage2/cuda/engine.cpp#L568)
- [x] **按双槽吞吐独立评价 D/P。** 固定实际 B2，先试单槽优选路线，再试附近可准入的 D/P 和布局，按完整队列吞吐排序。在 B2=27,015,978,990 下，D 从 210210 改到 180180，P 从 20160 降到 17280，giant 点从 128521 增到 149940，G 树批数从 7 增到 9。14328 与 16272 bit 的 D=180180 均通过双槽启动预检，实跑分别有一条和两条曲线的下降前沿退回主机路径，窗口因实际路线改变被排除，原始日志位于 `data/experiments/stage2_parallel_0620/full_two_wide/`。后续合格双槽样本分别使用 D=120120 和 D=90090。准入应核对下降时的显存余量和实际驻留状态。 [D 与点数](../../src/ecm/stage2/cuda/plan.cpp#L88) · [宽位矩阵](../performance/STAGE2.md#0620-串行优选与双槽)
- [x] **验证只保留一套大工作区的交接。** 优先在整段 giant/fold 结束后、下降前换出折叠余式 H 和归一化所需状态。F 树和逆多项式已有主机数据，换出后释放闲置设备工作区，恢复时仅上传仍需的数据。P=17280 的宽位试跑中单份 H 约 30–34 MiB，假设双向带宽各 12 GiB/s，往返纯拷贝约 5–6 ms。实测应计入同步、分配和缓存重建。若重建开销明显，再评估同一 CUDA 上下文内复用大 NTT 工作区，保持每条曲线的数学状态私有，并统一管理设备显存租约。逐批换出会随 G 批数增长，还可能搬运未消费的 giant 坐标。 [读回和释放](../../src/ecm/stage2/cuda/remainder.cpp#L564) · [显存生命周期](../architecture/MEMORY.md#giant-与工作区共同时间线)

## 验收

- 在同一设备、输入及实际 B2 下，分别与同 D/P 的原调度和最快单槽对比。短批记录整批墙钟除以完成数，持续队列同时记录整窗墙钟和去头尾后的 s/curve。覆盖窄、中、宽位以及生产 B2 和显存边界。
- 分别计时准备、GPU 交接、块积与回读、校验和持久回执，记录峰值显存、实际驻留路径和额外传输字节。检查锁时间与 GPU 时间线上的空档。
- 核对 NF 和因子结果、命中及非单位重放、中断恢复与回执去重。同一算术路线比较目标环叶值摘要及 NTT 计数。更换 D/P 时核对实际 B2 覆盖和数学结果。


## 0.62.1 结果

1. 单槽和双槽使用相同的进程协议，各保留最多一个额外进程。GPU 完成与持久回执分别确认。保留因子归因的 3600 bit 双槽整窗长 1.1%，中段基本持平，因此该模式的双槽默认预读至 2048 bit 算术位宽，单槽和仅报告因子的双槽至 4096 bit。
2. 预读同时缓存 tune。下一条仅在取得 GPU 许可后选择路线，并采用前一条已验证的内存观测。发布锁对照确认磁盘写入前即可选择，最终四个样本均只计一次。
3. 驻留下降复用设备叶值和另一块前沿缓冲做块积。仅报告因子且采用默认点策略时，完成块积和检查后可提前让出 GPU。Nsight 对照中 G 树和 fold 的锁内 GPU 空档最多，主机叶准备的边界见性能文档。
4. 独立 D/P 搜索保留为显式选项。318 bit 选中原 D 的另一布局，1939 bit 保留原布局。两组重启均复用实测最快的合格路线。
5. 单套工作区整条租约和 fold 后换出 H 均通过宽档驻留及算术核对。两条短批吞吐接近最快单槽，H 交换增加峰值显存，恢复分配和上传耗时 17–21 ms。两种方式均作为显式实验。同一上下文内复用工作区需要先把当前进程级的模数归约状态、页锁定缓冲与事件隔离到曲线，避免不同曲线覆盖在途数据。当前重建开销和整窗收益有限，优先测 G 树与 fold 的锁前准备。 [进程级 CUDA 状态](../../src/ecm/stage2/cuda/options.h)

现行默认、测量窗口、设备条件与原始证据入口见 [Stage2 性能](../performance/STAGE2.md#队列预读与工作区交接)。
