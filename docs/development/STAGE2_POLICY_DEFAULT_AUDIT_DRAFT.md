# Stage2 点策略默认值与布局三态检查草稿

提交版本：0.56.3。本草稿记录开发检查，正式入口分别见[Stage2使用](../usage/STAGE2.md)、[点策略架构](../architecture/STAGE2.md#完整区间点块策略)及[性能说明](../performance/STAGE2_PREPARATION.md)。性能验证二进制的0.57.0标识及原始证据保持原样；提交时仅将公开版本号改为0.56系列的下一个补丁号。完成后由用户决定草稿是否清理。

## 默认值决策

本轮保留 `stage2_giant_tail_balance=false`。无实际借块时可以消除额外工作，但真实借块的回退仍需完整预算资格，不能仅由未触发的26格计时决定默认启用。

`stage2_groot_balanced` 增加三态：`"auto"`、`true`、`false`，默认 `"auto"`。CLI支持auto/true/false及0/1别名；CLI auto也必须传递给曲线子进程，覆盖同一TOML中的强制值。tune继续记录解析后的布局0/1，不把请求auto作为第三种算法。

## 检查到的隐性成本

旧实现直接用请求布尔值切换点成本先验、完整Shape及观察身份，禁用跨曲线路由hint，并令命中／非单位进入原路径重放；没有发生借块也受影响。当前修改按实际分块记录身份：无借块沿用原成本、legacy route hint及原执行路径，实际借块与32链继续隔离。原生规划使用最终点块容量，不能仅使用粗略容量推断。

执行日志分别记录requested、实际tail_balance及borrow_points；结果保留请求值与实际值，重放另有point_policy_replayed。重放后的完整时间不进入普通性能样本。旧tail=0观察可继续使用，旧tail=1观察保持原有身份，不重写原始历史记录来合并成绩。

## 模型检查，不是GPU峰值实测

原生CPU入口使用P17280、D180180、I149940、C138240、T32768、W126、64链及GiantMemoryPolicy默认参数。原／平衡的Giant组件峰值为296372456／222303032 bytes，差74069424 bytes，约70.64 MiB。组件不包含完整NTT、owner及驱动，不能相加推导进程峰值；原分块重放可能要求更大的空间。

同入口按实际seed位步计数：尾点数1时，原1173519、平衡1173332次点主核模乘，只少187次；尾11700时，5607440→1276280。计数不包括归一化、段积和多项式。微小尾块的理论收益很小，不能由此保证完整耗时更快。

证据为忽略目录 `build_dev/stage2_policy_audit_0_57_0/` 的源码、编译入口及result.txt。CPU调度38802项、联合生命周期6097066项、runtime profile和portable接口检查通过；TOML解析与实际GUI编辑器读写三态通过。
