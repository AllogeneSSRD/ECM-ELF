# Stage2 位宽增长研究草稿

本轮是离线研究与优化规划，以0.57.0标记后续优化的分析基线，不改变算术内核、默认选型或配置。既有0.56.4布尔配置修改保持独立。本草稿保留研究验证，完成后由用户决定是否清理。

## 证据与实现

- 重读0.56.0冻结的13位宽普通／承载52次独立开关调用，主统计只取off侧26次，不使用学习最优成绩。两侧点调度和NTT工作量相同。
- 独立重读0.54.0固定D2310／P240、两档小B2、每格3遍的156条CUDA控制；旧OpenCL同批数据没有加入CUDA拟合。
- 新分析器维护在`tools/bench/analyze_stage2_bit_complexity.py`，输出CSV／JSON及三类图，并可生成自包含HTML；默认不写docs、不运行GPU。
- 首次离线结果保留于`data/benchmarks/stage2_bit_complexity_20261101/first01/`，最终汇总和图使用独立`final01/`目录，不覆盖首轮证据。
- 对当前0.56.4二进制只读运行cuobjdump；静态栈帧及来源SHA位于`data/experiments/stage2_bit_complexity_20261101/static_resources/`，没有运行GPU或改变显卡控制。

## 研究结论及正式入口

从约8k到16k，普通／承载引擎分别增至4.328／3.537倍，NTT蝶形代理只增至2.444倍。高位点组占53.90%／58.76%；点乘仍是W²，普通S4归约也保留平方项，不能将全部增长归因于NTT。经验指数和复杂度分开记录，固定显存可能迫使P缩小的条件性立方解释没有套到本批P近似不变的数据上。

正式性能说明为[位宽性能](../performance/STAGE2_BIT_SCALING.md)，数学推导为[复杂度资料](../reference/ECM_STAGE2_BIT_COMPLEXITY.md)，HTML是同一结果的阅读副本。同步修正了正式文档中“32／64尚未接入生产”和“新策略尚未包含seed成本”的过期描述。

下一轮以高位点模平方、私有数组／协作乘法及baby共同工作复用为优先探针；没有将任何尚未实现的方案写成当前生产能力。TODO与验收条件在正式性能页维护。

## 工作量公式核对

同一性能报告补入符号表、逐阶段点／模乘／卷积／NTT／归约计数、内存和传输公式，以及合并后的Stage2复杂度。用当前生产规划头进行CPU查询，对照52条冻结调用，全部长度分布、分阶段卷积数、归约系数数及baby／fold容量一致；证据保留于`data/experiments/stage2_bit_complexity_20261101/formula_audit/`。

CGBN本地实现的完整乘法及Montgomery平方沿用二次部分积循环；1.585对应递归Karatsuba，不是CGBN库名所保证的复杂度。单点NTT候选长度单独计算，并记录当前宽位下尚无交叉点实测；没有把候选方案写成已实现的点后端。0.56.4的配置修复已另行提交，不与本文档／分析器混合。
