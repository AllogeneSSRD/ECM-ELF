# GPU Stage2 原路径优化草稿

本轮沿用非 relocation 的完整 giant 网格，relocation 保持可选且默认关闭。本草稿保留实验过程；有效结论另同步到正式说明，完成后由用户决定如何处理草稿。

## 范围与基线

目标是 giant 点生成、多项式尾部和完整多项式覆盖边界。所有新测试使用 GPU1 RTX 4060 Laptop；不调整设备频率或功耗。曲线、Stage1 末点及实际 B1/B2 相同时必须保留因子结果和异常回退。

基线为 0.36.0，二进制 SHA256 `5f3628ec2c848a3829e5b91120e1c91406ce5fb8112eca9259bc9f3912a9314d`，冻结输入和来源位于 `data/experiments/gpu_stage2_relocation_20261018/matrix03/`。新证据位于 `data/experiments/gpu_stage2_original_20261018/`，不改写旧证据。

旧基线中，10232-bit 低档的完整 init+main 中位数为 28.332531 秒（3 次），其中一条分阶段日志的 giant 为 7.495 秒。它包含 seed、chain、分段乘积和后续同步，不能作为独立 chain 核耗时。

## 待证伪的假设

1. 宽位实例统一派发到 256-word 模板，可能因局部临时数组大于实际 160 words 增加缓存压力。
2. 每一步 chain 复制前后两对坐标；轮换缓冲区可能减少局部存储流量，也可能因动态索引退化。
3. 固定 64 点的 chain 在短尾处并行度不足；减小 chain 需额外 seed，应比较合计成本。
4. 补到完整 G 覆盖边界减少不规则形状，但增加点数和 NTT 长度，完整耗时未必改善。

## 验证方法

独立点探针直接提取生产模乘和 xADD，以 GMP 的八乘法多项式坐标公式校验所有 chain 的末点及首末 chain 的全部点。坐标按原 Montgomery radix 逐字一致，包含接近 radix 的奇数模数。探针只用于选择候选，生产采用前仍需真实 Edwards save 的全路径校验、NF 对照和因子/非单位回退测试。

完整多项式覆盖边界必须按当前 `I=floor(B2/D)+2` 计算：令 `G=ceil(I/P)`，则最小扩展值是 `B2'=max(B2,(G*P-2)*D)`。它增加实际覆盖范围，不得以原 B2 或单纯形状优化名义报告。

`profile_baseline_low02/` 保留原路径Nsight/CUPTI诊断：chain两次合计4.137秒，paired seed两次合计2.551秒。该进程在数学计算结束后的结果身份INI读取处失败，trace仍完整导出；不作为成功曲线或正式耗时样本。`profile_baseline_low01/` 的工具超时也保留。剖析工具增加显式 `--ini` 并绑定INI哈希，避免依赖程序目录中的默认身份文件。

## 点生成实验

`point_probe01/` 保存探针结果、EXE、生产算术提取结果及编译源。每行是一次探针进程：一次预热，随后三次 CUDA event 内核运行取均值；GMP 检查在计时区间外。它不是完整曲线性能样本，选择阶段的编译和 CPU 检查可能并发，不作为冻结正式矩阵的一部分。

轮换缓冲区在同一短尾探针中约为2163–2236毫秒，比复制坐标的实现慢，未用于生产。缩小数组容量没有建立明确收益，生产保持原有宽度派发。32线程块不改变每条chain的64点长度；例如453条chain对应的CUDA块由8个变为15个。

仅调整线程块的 candidate01 SHA256 为 `49efce4e7fb295bba0aabbe9ba4aead8a027e91a6245c7bd3187a05dcafb772c`；两个单次完整诊断分别为低档26.948247秒、高档76.955649秒，完整叶均与冻结0.36.0相同。证据在 `schedule_selection01/`，这是选择阶段的单次诊断，不与正式三次样本混合。采集器最初仅读debug日志而漏读engine日志中的总计时，原失败脚本保留为 `select_point_schedule_failed01.py`；恢复读取已有低档证据后继续高档，没有重跑或删除低档调用。

## 均衡 G 树与门禁

原非满树的左侧集中布局会产生很不均衡的高层输入。新布局以密集二次幂小块为单位分散空位，空位仍为常数1，根保留相同的非单首多项式。F树和下降不变；数学、偏移和raw容量证明见 [固定资料](../reference/ECM_STAGE2_G_TREE_LAYOUT.md)。压缩请求枚举已同步，不能套用原G树的请求签名。

`ntt_memory04/` 的数组分配检查681453项、独立密集请求/布局检查8470436项均通过。旧CPU夹具缺少Graph禁用状态及合成tile选择依赖；修正夹具后通过，前三次失败目录保留。此夹具不测试CUDA Graph对象或GPU算术。

`s4_memory01/` 的组件检查299592项、2136个分配事件及错误模型注入通过；完整请求程序576种、42624个分配事件、118117项检查通过，GPU调用数0。

`tree_gates02/` 的48组独立GMP多项式/节点通过，故障注入被拦截，带258叶尾批的完整有序请求及S4路由签名匹配。`tree_gates01/` 保留采集器把tune选择JSON和plan JSON一起计数导致的失败；修正筛选后使用全新目录重跑，不更改原始证据。`gates01/` 的Edwards门禁覆盖普通/承载、因子10007、gcd=N反例1186519、baby零和宽位chain及重分短尾，均通过。
