# GPU NTT Stage1 Edwards1：扩宽与批量调优规划

## 0.70.0 实施结果

CUDA Stage1 已支持 `32 ≤ p ≤ 1048576`，最大二次幂变换为 131072 点，新增的加权混合长度为 40960 点（5 × 8192）。65–128 段由最多四个 warp 并行求组摘要，进位同时覆盖线性回卷、加权归约和延后到 pack 的写回。配置、执行、共享 tune 以及 GMP 探针使用同一组长度约束。逐指数复算 1048545 个输入、三种选长结果及 22 个尺寸行，详见[完整尺寸表](../performance/STAGE1_MERSENNE_NTT.md#ntt-and-transform-sizes)。

- 双卡 GMP 探针各通过 28 组算术检查，含 524288／524289、786432／786433、900001、1048575／1048576 位，分别跑线性及加权的阶梯与独立平方。每组四路边界状态，覆盖 Graph／直接提交和跨数据流恢复。另有八次超界输入拒绝。宽档合并访存 PFA 的同步检查通过。[算术对拍与验证日志](../../data/experiments/stage1_ntt_128segments/)
- 生产 worker 在 M1048573 上使用 131072 点线性 x-only 和 65536 点加权 w6 得到相同的 Edwards save。在 M900001 的 w6、B1=512 上，第 388／745 列中断，从 131072 点线性切换至 40960 点加权续跑，保存点与连续运行一致。已知因子任务 `M786417/7` 的 CPU GMP 标量、CUDA 线性与加权路径得到相同的规范坐标。40960 和 131072 点的 `--tune ntt` 行均通过校验并写入共享表。[宽档生产与调优检查](../../data/experiments/stage1_ntt_128segments/qualify.py) · [已知因子对照](../../data/experiments/stage1_ntt_128segments/cofactor.py)
- 两卡共 84 个条件、252 个正式样本。M524309 首选已测的 32768 点加权二次幂，M900001 以 40960 点混合长度领先，M1048573 采用 65536 点加权二次幂。单曲线与并行结果、频率功耗及二进制身份见[变体矩阵](../performance/STAGE1_MERSENNE_NTT.md#扩宽后的双卡-edwards-naf-变体)。当前仅扩充合法长度。设备、NAF 窗口、B1、预算联合选批及更多 tile 的搜索按后续计划进行。

M1046305、sigma=9、B1=B2=8 时，CPU GMP 标量和两种卷积的原生 Edwards NAF 都发布因子 31；两次 CUDA 执行均进入了宽位主循环。Compute Sanitizer 的 `memcheck` 在 1048576 位、131072 点线性平方上报告 0 个错误，`synccheck` 在 900001 位、40960 点加权进位上报告 0 个错误。本轮还修正了生产回归中对 Edwards 单位元的旧预期，按现行 save 合同检查 `STATUS=IDENTITY`、零坐标和校验值。[因子日志](../../data/experiments/stage1_ntt_128segments/positive-1046305-weighted/run.log) · [显存检查](../../data/experiments/stage1_ntt_128segments/memcheck.log) · [同步检查](../../data/experiments/stage1_ntt_128segments/synccheck-verified.log)

## 初始实验设计（0.70.0）

本轮分析基于 ECM-ELF 0.69.23（`9835c703`）。Edwards1 沿用仓库的 Atkin–Morain Edwards 构造、sigma 和 `48·lcm(1…B1)`。实验分 x-only 阶梯（窗口 0）和原生 Edwards 2XY NAF（窗口 2–12）。本文的“单线程”按一条活跃曲线 `B=1` 计，GPU 内部仍用多线程做变换和进位。先在已支持的 52 万位内取得两张卡的基线，再用同一套算术和批量验收扩展位宽。本轮仅推导尺寸和设计实验。[Stage1 用法](../usage/STAGE1.md#cuda-全宽-ntt)

## 1. 承载位宽和变换长度分别扩展

用 `p` 表示梅森承载指数，`W=ceil(p/32)` 表示 32 位 limb 数，`S=ceil(W/256)` 表示分段进位的段数，`N` 表示 NTT 点数。含已知因子的任务同时记录实际余因子位宽。**32 个段覆盖 262144 位，64 个段覆盖 524288 位**。32 段以内由一个 warp 扫一组段摘要，33–64 段再扫描高半组并传递低组进位。段数由承载位宽决定，同一个 `N=32768` 既可用于线性卷积，也可在约 52 万位用于加权卷积，此时需要 64 段。较小输入能否走分段路径还取决于卷积、批量和计划。[进位实现](../../kernels/cuda/stage1_ntt_segments.cuh#L64) · [生产分派](../architecture/NTT.md#stage1-分段进位与-pack-融合)

完整尺寸表只维护在 [NTT and transform sizes](../performance/STAGE1_MERSENNE_NTT.md#ntt-and-transform-sizes)。当前二次幂变换最长 65536 点，混合加权长度为 2560、5120、10240、20480。二次幂的 radix、tile 和 outer pass 属于执行形状。混合长度把五点变换与五条二次幂子变换组合起来，可用带 twiddle 的 radix-5 或 Good–Thomas PFA。PFA 省去跨两因子的 twiddle 乘法，但需要在 pack 和逆向写回时置换，二者可以同长度对测。[混合长度准入](../../include/ecm/stage1/ntt_length.h) · [五点变换](../../kernels/cuda/stage1_ntt_radix5.cuh)

| 次序 | 输入与候选 | 需回答的问题及通过条件 |
| --- | --- | --- |
| A．现有上限 | 在 262144、393216、409575、491520、524288 附近测界内外相邻整数，补 393241、500009、524287 作为代表。收紧界另测尺寸表的常规边界和孤立指数。 | 核对实际选中的线性、保守加权、原生 NAF 加权计划和 GMP 末点。524289 在现行版本应被拒绝。先取得 20480、32768、65536 点的真实 Stage1 成本。 |
| B．增加进位段 | 首个研究档从 524289 位开始，保留现有合法 N，比较多组 32 段串接与分层前缀扫描。 | 对 64→65 段、完整和不满末段、跨组生成/传播/截断、全传播回卷到零逐 limb 对拍。比较独立写回与延后到 pack 两种消费者。 |
| C．增加 NTT 形状 | 以 1048576 位（128 段）为拟议探测终点；此点保守加权 65536 点、线性 131072 点可作算术对照。先评估 40960（5 × 8192）填补混合档的收益，更大混合档按系数界及数据决定。 | 每形状验证 N 阶单位根、加权根、digit/线性零尾、无符号乘积界及 2XY 四倍界。检查 offset 和分配字节数、共享内存、正逆排列及规范回卷。实测足以覆盖建表和置换成本后再选入自动候选。 |

扩宽涉及输入准入、进位摘要及其消费者、`resolve_packing`、配置的长度范围，以及共享 tune 对长度和层数的校验。目前 tune 读取显式限制 `log≤16`、`N≤65536`。每增加一档，先用实际选长入口核对两端及邻点，再更新权威表；扩展档获准前留在本草稿。Stage2 交接按目标余因子和自身后端能力单独验证。[尺寸与选长](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu#L280) · [共享表校验](../../src/ecm/stage2/planning/tune_portable.h#L197) · [配置源](../../config/ecm_options.json) · [已完成的 64 段验证](STAGE1_NTT_OPTIMIZATION_DRAFT.md#64-段进位与-524288-位准入)

## 2. 单曲线延迟与多曲线吞吐

4070 Ti 12 GiB 的 0.62.4 全位宽矩阵提供了搜索起点。61–262139 位共 29 个完整梅森输入，在 2610 MHz、活跃采样 17.90–246.19 W 下，候选预热 100 步后取三次 192 步阶梯设备计时的中位数。M131071、M225287、M262139 的自适应峰值批量依次为 **88、60、30**，达到各自峰值 95% 的最小实测批量为 **52、38、22**。M262139 单独穷举 1–128 后得到 **45／26**，自适应峰值已达穷举峰值的 98.62%。这些数来自 x-only 阶梯；原生 NAF 有不同的字典和列成本。约 50 万位已有模平方探针，可用于挑选形状，整批 Edwards 的峰值仍待测。[RTX 4070 Ti 全位宽矩阵及原始证据](../performance/STAGE1.md#rtx-4070-ti-全位宽矩阵) · [约 50 万位模平方对照](../performance/STAGE1_MERSENNE_NTT.md#约-50-万位的-gpuowl-混合-ntt-对照)

| 实验 | 固定项与对照 | 独立报告 |
| --- | --- | --- |
| 单曲线，B=1 | 固定 GPU、p、B1、sigma、窗口及端点，先比较线性与最短合法加权形状；混合档在同 N 下比较 radix-5/PFA，再比较 tile、outer 分层、Graph 和分段 carry／pack。 | 整批设备 µs/列，整曲线计算秒数，建表时间。Nsight Systems 区分主机提交空隙、Graph 与 kernel，Nsight Compute 只剖析主导的正逆 tile、pack 或归约。 |
| 多曲线，B>1 | 对同一输入、两张 GPU 各自调优。同 N 保留单曲线赢家作对照，在每个候选批量重新筛 tile/outer；看 CTA 波次、寄存器、共享内存、spill 和显存流量能否解释平台或下降。 | 对固定列数 J，记录整批设备时间 T、摊销 T/(B·J)、有效曲线列/s 和真实曲线/s；同时给出峰值批量、达到峰值 95% 的最小实测批量及各自整批延迟。 |

第一轮在 RTX 4070 Ti 和 RTX 4060 Laptop 分别复用 29 个基准指数，加上表 A 的宽档。固定连续 sigma（从 26 开始），短样本以 B1=512 筛形状，入围档加 B1=4096 复测建表摊销。两卡分别建表和排名。**宽档在容量内先试 1、2、4、8、16、32**，补容量端点；若 32 仍有增长，继续 64、128 或可行上限。保留原调优的 SM 波次候选，峰值与 95% 阈值附近补非二次幂（含相邻整数）。选择 M262139 及一个约 52 万位的代表，穷举可行整数批量核对搜索遗漏。若峰值落在容量上限，标记“预算内峰值”；4、8、16 只作为宽档待检验的候选。

## 3. 在显存预算内搜索 batch

当前 `--tune ntt` 的默认指数列表止于 262139，显式 `--bits` 已接受至 524288。它测合成 x-only 阶梯；生产拆批另按设备 UUID、形状、目标与算术位宽、B1、曲线、标量倍数及 NAF 窗口读取真实样本。无兼容记录时从容量内的 64 条起步，有余量的长任务会探索容量、基础批量及其附近。改进重点是补全宽档覆盖，在大窗口或大 N 下先剪掉放不下的格子，再用原生 Edwards 生产时间选择批量。[合成调优](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L489) · [生产选批与采样](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L647)

对每个合法 N 和 NAF 窗口 w，令 K=2^(w−2)，x-only 取 K=0。现有生产容量预估以字节计：

- 每曲线字典 `D=K·(32N+16W)`。其中 `32NK` 为四份常驻频谱，`16WK` 为 GPU 建表临时空间。主机建表仍须容纳常驻频谱，另查主机 RAM 和准备阶段。
- 每曲线预估 `V=88N+128W+D`，固定预估 `F=160N+32W+floor(B1/4+16)`。总预算取上下文就绪后空闲显存的约 80%，有正数 `ntt_memory_mib` 时再取二者较小值。可行批量先按 `floor((预算−F)/V)`（不足取 0）裁剪，再取主机容量、128、剩余曲线数及正数字典上限 `floor(naf_memory_mb·10^6/D)` 的最小值，最后一项仅用于 D>0。记录预算估值与实际分配，GPU 建表转主机的情况单列。[预估公式](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L424) · [分配与预算检查](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu#L420)
- 例如 p=524288、N=32768、W=16384 时，w8 每曲线频谱 64 MiB、GPU 临时空间 16 MiB；w12 对应 1024 和 256 MiB。仅按字典计算，w12 的 B=8 在 GPU 建表阶段就需要 10 GiB，足以排除 8 GiB 卡上的该组合。w8 的 B=8 则只需 640 MiB 字典预算，尚须加上同时存活的工作区。这是容量推导，实测峰值另记。[字典布局与生命周期](../performance/STAGE1_MERSENNE_NTT.md#奇数倍点字典与显存)

| 调优环节 | 计划操作 | 判定依据 |
| --- | --- | --- |
| 生成候选 | 对每张卡、p、卷积/N 分别预算窗口 0、6、8、10、12。为 host/gpu 建表分别列出固定、常驻和临时开销，先复算已有估值，标记因主机 RAM、总显存或字典预算跳过的格。 | 同时保存可用显存、配置预算、请求/发射/有效 B、建表后端和回退原因。预算不足时比较减 B、减 w 或主机建表的可行组合。 |
| 采集和排序 | 复用合成矩阵作种子，记录合成吞吐；生产用同输入和 sigma 前缀交替复测候选，每格至少三次取中位数，保留范围。小预算例与正常预算分别跑，尾批、构造提前出因子和部分续跑另列。 | 用生产有效曲线/s 选峰值与 95% 档，计时从标量准备到结果归一化；另报主循环 CUDA event 和含发布的任务墙钟。对照现行推荐档的吞吐、等待时间及探测成本，差异在重复波动内时保留较小批量。 |
| 回放与归档 | 在同设备重读调优表，分别检查满批、尾批、预算缩小和缺少新字段的旧表。每个胜出方案实际完成一项分批 Edwards 任务。 | 确认所选形状可分配、队列无漏跑或重复，合成与生产记录可区分。保存 NAF 列数、非零列数、窗口、字典阶段时间，显存峰值采用运行时 `max(owned_bytes, observed_bytes)`。 |

## 验收与证据

1. 用 GMP 核对模乘、平方、全传播与最高 limb 屏蔽，再按固定构造、sigma、B1/B2 核对规范末点、因子及临界 B1/B2。覆盖完整梅森数、已知因子承载、NAF 字典分母出因子与异常 x-only 重放。抽查线性↔加权换计划续跑，跨批量对照同 sigma，验证 Stage2 交接。[生产回归](../../tools/test/test_stage1_ntt_production.py) · [已知因子验收](../../tools/test/test_stage1_ntt_known_factors.py) · [NAF 参考](../../tools/test/test_edwards_ntt_naf_reference.py)
2. 后续每轮保留 GPU UUID／SM、驱动、功率上限、频率／板功耗采样、二进制 SHA、输入、重复数、计时边界、实际计划和逐次结果。`data/experiments/` 保存日志与剖析，`data/benchmarks/` 保存逐格汇总。单曲线与多曲线各出榜，字典、主循环、整任务采用各自时间边界。[矩阵采集](../../tools/bench/bench_stage1_ntt_best.py) · [设备矩阵分析](../../tools/bench/analyze_stage1_ntt_device_matrix.py)
3. 先交付当前上限的双卡延迟、吞吐与容量矩阵，再决定是否实现更宽进位和新长度。通过算术、正式入口和续跑验证的范围同步到尺寸表；经同设备复测的批量结论更新到 Stage1 性能文档。
