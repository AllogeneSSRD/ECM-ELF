## tune 重构方案评审（0.70.0 基线与验收设计）

0.70.0 的显式 `--tune ntt --bits p` 先解出候选形状，随后对每个候选各自搜索批量。每个实际试测的配置先预热 100 个 x-only 阶梯步，再从同一起点计时 3 × 192 步，按三个 CUDA event 耗时的中位数计算总曲线步/s。生产缺表时的短测是 100 + 3 × 128 步。倍增增益小于 5% 时会对相邻两档交替各补两次。每个样本计整个窗口，包含轮询同步，准备和末点回读在计时区间外。原生 Edwards NAF 的生产列计时独立于这两个合成测试。[调优采样](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L205) · [设备计时边界](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu#L1167)

1. **从 p 生成合法计划。** 用生产精确性判定列出线性二次幂、加权二次幂和适用的加权混合长度，再为混合长度列出普通 radix-5、直接 PFA、合并访存 PFA。同长度的三种实现分别计时。使用当前任务或配置的 GPU、链、B1、NAF 窗口和预算；只有 p 且没有 NAF 工作负载时，合成 x-only 结果只用于生成候选。对收紧界才允许的长度直接使用原生 NAF 采样。[选型与容量](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L400)
2. **按每个候选的容量粗测。** 结合上下文空闲显存、总预算、字典上限和主机容量求可行 B 上限，再裁剪到程序上限 128，生产时另受任务剩余条数限制。可行集合为空时记录约束原因；容量为 1 时只测一次。其他形状先测单曲线、一个内部批量及容量端点。内部档优先用已测的 95% 档，宽档缺历史时从 4 或 8 条起步，邻近批量去重。若精确分配失败，收缩该候选的可行区间。
3. **按两个目标精调。** 分别保留单曲线延迟和并行吞吐的领先者，将落入测量波动范围的候选一并复测。对入围者调 tile、outer、Graph、批量和峰值邻档，输出单曲线计划、实测峰值以及达到峰值 95% 的最小实测批量。所有成功试测的配置（含落选的 tile 和 radix 变体）记录 `iter_per_s = 有效曲线数 × 计时步数 / 设备秒数`、实际形状、dataflow、重复数、计时步数、离散度和显存峰值。生产另记含建表的 `curves_per_s`。合成阶梯步与 NAF 列分别排名。[现行测量行合并规则](../../src/ecm/stage2/planning/tune_portable.h#L614)
4. **跨 p 复用与补测。** 每次重新判定精确性、实际数据流和当前容量。对相同 GPU、测量口径、兼容算术实现、N、digit 宽度、批量及执行形状逐行匹配。已有行仍能容纳、且覆盖本次所需比较点时直接复用；预算缩小只裁去超额档，扩大只探索新增区域和有希望的邻档。同 N 若跨过进位段数、2XY 融合门限或 NAF 工作负载发生变化，旧计划作为起点，在新 p 快测确认。保留旧数据，记录哪几格复用、补测或被预算跳过。
5. **以设备时间确定采样长度。** 先试跑估算整批每步时间，据此选择连续步数。建议先试粗测每窗约 20 ms、精测约 50 ms，并设置最少步数、最长窗口及调优时间上限。每项测量先跳过独立预热，再在固定的中间连续区间放 CUDA events；尾部回读、存档和不完整窗口另计。用有效曲线步总数除以中间区间总秒数计算均值，再对重复窗口取中位数及波动范围。对手交替运行；同一 p 的 NAF 候选用相同的真实 digit 序列、覆盖非零列和零列；不同步数的校验在共同列游标比端点。短任务允许从同一起点重复完整标量并按实际列数合计。上述时长须通过双卡重复性与总调优时间确定。

验收用冷表、热表、预算缩小、预算扩大，以及长度相同但跨融合门限的两个 p 各跑一次。记录新增实测格数、调优墙钟、端点和最终吞吐。热表全覆盖时应无新增测量，部分命中只补缺口；代表位宽另以预算内穷举对照峰值及 95% 档。

## 1. 承载位宽和变换长度分别扩展

用 `p` 表示梅森承载指数，`W=ceil(p/32)` 表示 32 位 limb 数，`S=ceil(W/256)` 表示分段进位的段数，`N` 表示 NTT 点数。含已知因子的任务同时记录实际余因子位宽。**32 个段覆盖 262144 位，64 个段覆盖 524288 位**。32 段以内由一个 warp 扫一组段摘要，33–64 段再扫描高半组并传递低组进位。段数由承载位宽决定，同一个 `N=32768` 既可用于线性卷积，也可在约 52 万位用于加权卷积，此时需要 64 段。较小输入能否走分段路径还取决于卷积、批量和计划。[进位实现](../../kernels/cuda/stage1_ntt_segments.cuh#L64) · [生产分派](../architecture/NTT.md#stage1-分段进位与-pack-融合)

完整尺寸表只维护在 [NTT and transform sizes](../usage/TUNE.md#ntt-and-transform-sizes)。当前二次幂变换最长 65536 点，混合加权长度为 2560、5120、10240、20480。二次幂的 radix、tile 和 outer pass 属于执行形状。混合长度把五点变换与五条二次幂子变换组合起来，可用带 twiddle 的 radix-5 或 Good–Thomas PFA。PFA 省去跨两因子的 twiddle 乘法，但需要在 pack 和逆向写回时置换，二者可以同长度对测。[混合长度准入](../../include/ecm/stage1/ntt_length.h) · [五点变换](../../kernels/cuda/stage1_ntt_radix5.cuh)

## 3. 在显存预算内搜索 batch

当前 `--tune ntt` 的默认指数列表止于 262139，显式 `--bits` 已接受至 524288。它测合成 x-only 阶梯；生产拆批另按设备 UUID、形状、目标与算术位宽、B1、曲线、标量倍数及 NAF 窗口读取真实样本。无兼容记录时从容量内的 64 条起步，有余量的长任务会探索容量、基础批量及其附近。改进重点是补全宽档覆盖，在大窗口或大 N 下先剪掉放不下的格子，再用原生 Edwards 生产时间选择批量。[合成调优](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L489) · [生产选批与采样](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L647)

对每个合法 N 和 NAF 窗口 w，令 K=2^(w−2)，x-only 取 K=0。现有生产容量预估以字节计：

- 每曲线字典 `D=K·(32N+16W)`。其中 `32NK` 为四份常驻频谱，`16WK` 为 GPU 建表临时空间。主机建表仍须容纳常驻频谱，另查主机 RAM 和准备阶段。
- 每曲线预估 `V=88N+128W+D`，固定预估 `F=160N+32W+floor(B1/4+16)`。总预算取上下文就绪后空闲显存的约 80%，有正数 `ntt_memory_mib` 时再取二者较小值。可行批量先按 `floor((预算−F)/V)`（不足取 0）裁剪，再取主机容量、128、剩余曲线数及正数字典上限 `floor(naf_memory_mb·10^6/D)` 的最小值，最后一项仅用于 D>0。记录预算估值与实际分配，GPU 建表转主机的情况单列。[预估公式](../../src/ecm/stage1/montgomery/cuda/ntt/tune.cpp#L424) · [分配与预算检查](../../src/ecm/stage1/montgomery/cuda/ntt/ladder.cu#L420)
- 例如 p=524288、N=32768、W=16384 时，w8 每曲线频谱 64 MiB、GPU 临时空间 16 MiB；w12 对应 1024 和 256 MiB。仅按字典计算，w12 的 B=8 在 GPU 建表阶段就需要 10 GiB，足以排除 8 GiB 卡上的该组合。w8 的 B=8 则只需 640 MiB 字典预算，尚须加上同时存活的工作区。这是容量推导，实测峰值另记。[字典布局与生命周期](../performance/STAGE1_MERSENNE_NTT.md#奇数倍点字典与显存)

| --- | --- | --- |
