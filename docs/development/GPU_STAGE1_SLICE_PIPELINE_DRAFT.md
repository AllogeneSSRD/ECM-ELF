# CUDA Stage1 切片提交窗口开发草稿

前置提交 `197f38b7` 发布 0.63.4 的 PRAC v2 种子缓存。流水线改动从该提交继续。上一轮 M4423 跟踪和原型证据见 [PRAC 执行实验](../architecture/PRAC.md#cpu-ifma-与-rtx-4070-ti-的首次建表和主计算)。

## 实现

共用 [切片提交函数](../../src/ecm/stage1/cuda_slices.h) 在同一 stream 排入最多八片。每个窗口只确认一次完成，确认后再读取 CGBN 错误报告并更新进度。Edwards NAF 和二进制、Montgomery CGBN ladder 和 resident/PRAC 复用这一调度。Edwards 二进制任务在保存、停止和最终输出时导入主机 GMP 状态。含固定步长的独立 Edwards 调用、Montgomery 调试 dump 和 PRAC 限时采样保持逐片边界。checkpoint 读写格式不变，保存的坐标对应已同步的游标。

这次实现保留了窗口结束时的单一完成点，队列可以在窗口边界暂时耗尽。此结构允许现有 managed 错误报告和即时快照继续在设备状态稳定后由主机读取。持续补片需要将错误报告和点快照改成独立的按序读回槽，并明确定义停止时允许的最大在途工作量。CGBN 和 NTT 使用不同的执行器，本轮改动覆盖 CGBN。

## 测量方案

使用 M4423、B1=100,000、B2=0、连续 sigma 从 26 开始。Edwards 选 NAF w6 和默认 HWCD，Montgomery 使用 PARAM0、LCM=12，分别测试 ladder 和 PRAC 7 档（baseline、寄存器 cap 168、100 ms 目标）。三者均为 sm_89、4608/TPI16、128 个线程每块，即每块 8 条曲线。GPU0 RTX 4070 Ti 有 60 个 SM，比对 128、480、960 条曲线。GPU1 RTX 4060 Laptop 有 24 个 SM，比对 128、192、384 条曲线。1/2 blocks per SM 表示总 launch grid 与 SM 数的比例。

两张卡分别用 UUID 绑定，在独立工作目录同时运行。每张卡的处理顺序为新旧交替，每格各两次，第二轮反转旧版和新版顺序。关闭周期检查点。旧版为上轮 0.63.3 冻结构建，SHA-256 `d05e05bbbe58b3c3599a01dcbeb409ea1a673f51e3f37957682f75ad2ea16a93`。新版 0.63.4 实验构建 SHA-256 为 `e2974128cd1369d6734245448135b6f8261ef278e98ae59f5a09240317bba722`。两者使用同一 CUDA 13.3.73、MSVC 14.51.36231、GMP 和编译配置，设备算术实例对象逐字节相同。驱动 610.88，Windows WDDM，未调整时钟、功耗或优先级。

主计算是各算法自身日志中的边界。Edwards 用 `arithmetic api_seconds`，涵盖设备准备、字典、切片及末点读回。Montgomery ladder 用设备侧起始事件到最后窗口尾事件，PRAC 用上传后到末点下载的执行墙钟。每种算法自身的前后对照遵循相同范围。进程墙钟包含启动、准备与发布。原始记录、日志、GPU 遥测、构建清单位于 `data/experiments/prac-execution-4070ti-20261114/`。

## 主矩阵结果

72 个正式样本均完成，按 GPU、算法、批量逐组匹配最终 save 末点和校验值。128 条曲线组的三种算法也在两张卡上分别一致。负载采样（利用率至少 70%）的各样本中位数范围为 4070 Ti 57～190 W、2610 MHz、37～60°C，4060 Laptop 14.7～26.2 W、1500 MHz、50～58°C。表内为各两次的主计算时间中位数，百分比为用时下降的比例。

4060 Laptop 的 Edwards 2 blocks/SM 在主矩阵有一轮变慢，另在 4070 Ti 空闲时补测三对。三对均缩短，降幅为 0.91%～1.22%。补测中位数为 22.601 → 22.370 s（+1.02%），进程为 23.288 → 23.019 s（+1.15%）。合并五对后主计算为 22.601 → 22.385 s（+0.96%）。补测与主矩阵的 save 摘要一致。逐次结果见 `pipeline-edwards-2b-confirm-gpu1/results.json`。

## 停止与续跑

RTX 4070 Ti 使用同一 M4423、B1 与 128 曲线，设置每秒检查点。实际触发继承的 Windows 停止事件后，四种路径保留了可解码的部分检查点，未发布部分 save。恢复完成后与原版不间断运行逐条比较末点和校验值，全部一致。四个样本的信号至进程退出耗时分别为 Edwards NAF 0.921 s、binary 0.844 s、Montgomery ladder 0.265 s、PRAC 0.266 s，单次测量，供核对停止边界。

另通过现有 Montgomery 回归中的 27 项用例、184 条末点对照，以及 Edwards 4608 容器上界的 binary、NAF HWCD、NAF 2XY 三组独立 CPU 末点检查。Edwards 等待探针的 1280 档已构建，测试在 4060 Laptop 上调入诊断的设备等待并通过点不变量检查。证据位于 `pipeline-restart-gpu0`、`pipeline-prac-gates/summary.json`、`edwards-pipeline-probe/check.log` 和 `pipeline-host-wait-probe/`。

## 两片与三片滚动提交

`ECM_CUDA_STAGE1_SLICE_DEPTH=2|3|8` 选择两片滚动、三片滚动或八片组尾等待。滚动版为每片保留起止事件及完成事件，在同一默认 stream 上把该片的 32 B CGBN 报告复制到对应的固定页 host 槽，再记录完成事件。设备报告保留首个错误，主机只回收最旧完成槽，并用该片设备计时调整后续切片。曲线点缓冲、标量和字典由整个任务共享。

收到停止请求后停止补片。周期检查点到期时也暂停补片，在已提交的片都确认完成后抓取快照；写入成功后才更新持久进度。保持 checkpoint 格式。固定 Edwards 探针和 PRAC 限时采样继续使用原逐片边界。

主对照使用 M4423、B1=100,000、B2=0、128 条曲线和前面相同的算法条件。完整进程计时与 `GetProcessTimes` 取自无 profiler 运行，CPU 核当量为进程 user+kernel CPU 时间除以进程墙钟。P95/P99 取同一进程相邻算术切片内核的 GPU 时间戳，按最近秩计算，含片间错误状态读回和调度间隔。停止测量在首次报告达到约 35% 后触发继承的 Windows 停止事件，附加 0、35、70 ms 三组错开时钟，计到进程退出。恢复试验使用相同模数、B1=20,000、每秒检查点。原始数据与复跑器位于 `data/experiments/prac-execution-4070ti-20261114/`。

八片对照 SHA-256 为 `e2974128cd1369d6734245448135b6f8261ef278e98ae59f5a09240317bba722`，两片和三片使用同一候选程序 `d2214296248847ea75b83f449dcfd825166ae80198df0a1101dbbfeebdf31460`。编译清单中变更的 CUDA 对象只有 Edwards、Montgomery ladder 和 PRAC 三个主机分派单元，设备算术对象的文件哈希一致。

常规墙钟每格两次，两卡可以并行且同卡串行。停止每格三次。第一条 4070 Ti 探索跟踪误与同卡 Edwards 首轮停止运行重叠，相关探索跟踪及三项停止样本保留原始日志，正式统计改用独立重测。两张卡的正式跟踪各格一次，和同卡的墙钟、停止、恢复测试分开。

两片的 P99 全部低于 0.84 ms，每格停止中位数均短于三片和八片，CPU 仍约占一个逻辑核。三片的两个 Edwards 墙钟中位数较两片少约 0.33～0.37 s，样本数有限，4070 Ti 第二对仅差 0.043 s。没有正式样本出现超过 100 ms 的片间隔，未覆盖先前 0.55～0.58 s 的同步长尾。Edwards 和 ladder 的短间隔总和在滚动调度下略增，PRAC 的总间隔减少。4070 Ti 的 32 B 错误报告拷贝本身中位数约 2 μs，P95/P99 还包含事件与调度时间。选择两片作为默认，三片与八片可覆盖。

## 正式配置与阻塞等待

本轮以 0.63.6 提交，`cuda_slice_depth` 和 `cuda_low_cpu` 加入 Stage1 TOML，默认用三片滚动提交，低 CPU 模式默认关闭。开启低 CPU 模式后，滚动完成事件、组尾事件及 Edwards NAF 字典完成事件通过 CUDA 的阻塞事件唤醒 host。配置验证覆盖全局值、worker 覆盖、非法值及 `0/1` 布尔别名。显式 TOML 深度优先于旧实验环境变量。

首轮对照使用 M4423、B1=100,000、B2=0、128 条曲线和三片滚动。两张 GPU 分别绑定 UUID，同卡开启和关闭各一次，关闭周期检查点。两种模式使用同一个预发布测试构建，仍显示 0.63.4，SHA-256 为 `692419fc1172ca369f7fbcd046c3802c94e5d69f5dbb3ffdc017a5f0a31d7528`。驱动 610.88，设备负载采样中位数为 4070 Ti 59.5～61.9 W，4060 Laptop 15.0～16.1 W。CPU 核当量按 Windows 进程 user+kernel CPU 时间除以进程启动至退出的墙钟计算。

| GPU | 算法 | CPU 核当量（关 → 开） | 整批墙钟 s（关 → 开） |
| --- | --- | ---: | ---: |
| 4070 Ti | Edwards NAF | 0.984 → 0.058 | 10.246 → 10.267 |
| 4070 Ti | Montgomery ladder | 0.969 → 0.036 | 12.675 → 12.550 |
| 4070 Ti | Montgomery PRAC 7 | 0.977 → 0.053 | 12.357 → 12.372 |
| 4060 Laptop | Edwards NAF | 0.975 → 0.035 | 16.951 → 17.466 |
| 4060 Laptop | Montgomery ladder | 0.977 → 0.022 | 20.949 → 20.939 |
| 4060 Laptop | Montgomery PRAC 7 | 0.986 → 0.043 | 20.638 → 20.623 |

六组开关对照的 save 摘要全部一致。开启后在两张卡上以 B1=20,000、128 条曲线和每秒检查点分别完成三种算法的停止与恢复。每格一次，发出停止信号到进程退出为 0.267～0.512 s，恢复后的末点与连续运行对照一致。4070 Ti 也完成了八片 worker 覆盖、两片 Edwards binary 和 Montgomery resident 补测。B1=5,000、8 条曲线的短任务整进程平均仍为 0.23～0.32 个逻辑核，启动、准备和发布的 CPU 时间在短任务中占比更高。

标记为 0.63.5 的实验构建 SHA-256 为 `4aa8ce74f4c9f2a68a0b896839d68c7b623c0466075bb2ee76181403b651fe62`。在相同 B1=100,000、128 条曲线条件下，只配置 `cuda_low_cpu=1` 并使用默认切片深度，两张卡每种算法各复测一次，末点均匹配。整进程 CPU 占用为 0.024～0.058 个逻辑核，负载采样功耗中位数为 4070 Ti 59.3～61.2 W、4060 Laptop 15.0～16.0 W。日志见 `configured-final-wall-gpu*/`。后续交错复测见 [Stage1 性能依据](../performance/STAGE1.md#同构建交错复测)。

原始配置、日志、GPU 遥测与末点摘要在 `data/experiments/prac-execution-4070ti-20261114/configured-*-gpu*/`，复跑器为同一目录树中的 `configured_slices.py`，恢复对照为 `rolling-verify-reference-wall-gpu0/results.json`。

0.63.6 提交前通过正式 TOML 回归、CUDA 4608 档增量构建和 RTX 4070 Ti 冒烟验证。冒烟保持默认三片并开启低 CPU 模式，以 M4423、B1=5,000、B2=0、8 条曲线跑 Edwards NAF、Montgomery ladder 和 PRAC 7，三组末点与此前短测一致。日志见 `configured-release-0636-wall-gpu0/`。
