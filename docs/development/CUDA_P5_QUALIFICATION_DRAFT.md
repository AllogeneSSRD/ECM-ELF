# CUDA P5 验收草稿

目标版本0.44.6，基线提交为 `5d15a93`（0.44.5）。完整重构的性能基线采用已冻结的重构前0.44.0程序（源码修订 `36171f4`），不以P4与P5之间仅版本变化替代P0～P4的总体性能对照。证据根为 `data/experiments/cuda_structure_p5_20261020/`，原始失败与采样不改写。

## 验收顺序与口径

1. 预检：16种位宽筛选/几何编译与40项构建身份/故障/跨PowerShell检查。通过后进入完整位宽构建和原生算术。
2. 完整位宽：Stage1全32档Edwards binary/NAF4/NAF5的独立GMP点/不变量/恢复检查，Montgomery至16384容器各PARAM0/2/3的末点存档对照及实际注册边界；Stage2七档容量与实际W=1…256、尾位1/63/64、通用/梅森模数的独立GMP检查，以及端到端存档、规划、回退/损坏拒绝和资源检查。正常默认与显式可选PRAC/Graph/诊断分别记录，不将未选择路径列为生产默认。
3. 多架构：按现有发布入口构建/拆分/打包sm60/70/75/86/89/120，分别核对CUDA12.6/13.3工具链、对象和镜像、源清单与发布身份。构建与镜像验收、兼容镜像运行及原生硬件运行分开；不得把JIT或sm89结果写成其他实体GPU验收。
4. 性能：完整功能门禁后，在GPU1串行进行冻结旧/新程序配对采样，覆盖Stage1两曲线及不同宽度、Stage2不同宽度/树大小及普通/合法承载。固定输入、算法/配置、GMP和设备，预热后交替AB/BA，记录进程墙钟及其内部独立边界；不相加嵌套计时。固定初始门限为新/旧配对耗时比的中位数和95% bootstrap上界不超过1.05；不能判定时保留原轮并增加样本，不修改门限或丢弃慢样本。正确性、完整性、来源不符的样本必须标错，不能纳入有效性能结论。
5. 最终核验：将通过证据绑定到最终源码、对象、二进制及发布包；仅增加修订号，提交P5文件。上一轮网页、`.gitignore` 和相关未提交文档按进入P5时的摘要保留，不混入P5提交。

## 环境与覆盖限制

预检发现本机GPU0为RTX4070Ti、GPU1为RTX4060Laptop，两者均sm89。运行只使用GPU1，不改变功耗、频率或其他进程。CUDA12.6可选的相容MSVC为14.16.27023，CUDA13.3为14.51.36231；实际构建结果仍需逐项确认。不同架构的实体GPU不在本机，原生硬件覆盖以实际证据为准。

性能记录应包含程序/源码身份、输入、样本数、设备、功耗限制或不可用状态、实际功耗/时钟/温度与测量边界。构建支持不构成所有架构的性能资格。

当前范围按用户后续指示收敛为本机LOCAL编译、完整位宽功能与性能验收；多架构发布暂缓，允许停止构建。本任务已停止自有发布构建，保留部分产物及全部诊断证据，没有修改生产算术或正式构建默认值。预检、sm89完整生产位宽、显式PRAC/Graph、跨block批次、受限开发、fold及TPB256/寄存器64配置均已通过。按用户进一步缩减后的9例本机配对性能检查已通过；完整26例计划保持未完成，不补测长B2。本草稿保留并随P5提交，完成后提示用户处理，不自动删除。当前结论和覆盖边界集中在[正式验收说明](../performance/CUDA_STRUCTURE_QUALIFICATION.md)。
