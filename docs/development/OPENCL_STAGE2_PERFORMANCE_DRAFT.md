## 诊断记录

新增 `opencl_points` 设备事件/主机边界、`opencl_split` 与 `opencl_tail`。kernel嵌套于coordinates，点生成明细嵌套于baby/giant；不能相加为曲线总时间。

`data/experiments/opencl_optimization_20261029/diagnostic4667/`：4667 bits、B2=2600000，单次完整曲线。原64点提交为12.187472 s，其中点kernel10.813123 s；240点提交9.856918 s；CPU点3.468757 s。三次为不同配置，不能称n=3重复。

`groups4667/`：仍固定240点，仅改变工作组/giant基点。运行时自动工作组：kernel7.738507 s、总9.886708 s；显式group32：2.780082/5.047441 s；group8：2.864427/5.113268 s；group32并复用[D]Q：1.382963/3.502137 s。每配置n=1，未据此声明普遍收益。

## 实施边界

- giant按 iD·Q=i·(D·Q) 重标定；原始基点与完整iD标量仍作为独立GMP取样依据。[D]Q先检查分母，发现真因子则正常结束，饱和不能制造零仿射根。
- 显式点工作组，补齐global范围并保留id<count检查；设备/kernel上限先校验。
- 程序缓存只在一个Runtime/context内，键为完整源代码与完整编译选项；不依赖哈希碰撞，不跨设备/上下文/进程。仅共享不可变program，每个计划创建独立kernel。
- 进程内固定设备枚举快照，避免重复ICD枚举；曲线仍通过子进程隔离。热插拔后需重启worker以刷新编号，所有上下文和命令错误继续传播。
- 专家环境开关用于同二进制对照；正式默认值待门禁和矩阵确认后写入正式文档。

## 当前后续方向

7995-bit、高B2默认点kernel仍占代表调用的67.8%。CPU点分流在该小P输入进一步减少43.5%完整引擎时间，但尚无大P、多worker和更多CPU的分流模型，保留显式对照开关。原生点算术、chain及短NTT有界提交窗口继续列为待推进，不能据此声明已经实现。
