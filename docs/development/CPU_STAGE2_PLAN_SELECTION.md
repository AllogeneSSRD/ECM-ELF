# CPU Stage2 选型与内存实验草稿

## 候选筛选

以同一个 Edwards save、实际 B2 和线程数比较 D。第一步读入已有 worker.log，用原 FFT 的单系数占用估算其他几何，按 CPU 成本公式排列原轮表和 CUDA 共享表中的候选。输出的 MiB 是估值，模型分数是相对工作量。第二步用 CPU worker 的 `--d` 固定候选，重新建立真实 GWNUM 布局，执行 4096 MiB 准入和完整曲线计时。显式 D 和自动 D 使用相同的安全余量检查。[候选排序工具](../../tools/bench/rank_cpu_stage2_plans.py) · [CPU 实现](../../src/ecm/stage2/cpu/gwpoly.cpp)

例如在 M262139 的旧运行目录，以 `python tools/bench/rank_cpu_stage2_plans.py <worker.log> --b2 450000000 --memory-mib 4096` 可重现候选排序。M65521 的第一名 D=46410 在旧 FFT 上估计 3947 MiB，固定 D 后实际未通过建计划。保留失败日志。第二个候选 D=43890 从 FFT 3584 升至 3840，实际规划估值 3963 MiB，通过准入。最高分候选不能直接写成生产配置。

## 第一组整曲线实验

Ryzen AI 9 HX 370，GWNUM 31.6。复用 [B1=1000 宽位矩阵](../performance/STAGE2.md#cpu-宽位分区矩阵) 的余因子、已知因子与 sigma=26 存档。4T 限于逻辑线程 1、3、5、7，1T 限于线程 5；测试串行，启动前及运行中检查编译进程。未锁频，未采集有效频率和功耗。记录 worker 的整曲线秒数，每次独立进程，排除启动、读档与发布。原 DLL 标识 7444a53678a1e166，点递推实验 DLL 标识 03b8bdf6cfd6ec5c。下表均使用后者，仅改变 D。每格两次完整 NF。

| 指数、B2 | 原 D/P | 候选 D/P | G 块数 | 原耗时（秒） | 候选耗时（秒） |
|---|---|---|---:|---|---|
| M262139，4.5 亿 | 9240/960 | 10920/1152 | 51 → 36 | 42.74、41.68 | 37.42、36.73 |
| M65521，80 亿 | 34650/3600 | 43890/4320 | 65 → 43 | 47.64、47.36 | 40.48、41.01 |

候选仍使用完整 F 树。M262139 的 giant 点数从 48701 降至 41209；M65521 从 230880 降至 182274。原始命令、结果和阶段分项位于 [实验目录](../../data/experiments/stage2_cpu_planner_flow/)。

## 流程与后续实验

实验 DLL 尝试用一次梯形交付相邻两个巨步起点，并轮换三点引用以减少坐标复制。M16001、80 亿、D=120120、1T 各三次，基线中位 13.202 秒，实验中位 13.278 秒。M65521 的固定几何 4T 配对也接近持平。这项改动未纳入最终 DLL。几何实验在固定流程下进行。

最终 DLL 沿用原点递推；G 树的两个各含 2P 个系数的工作区在末块结束后显式释放，避免与末端下降缓冲同时存活。这个生命周期改动没有独立的耗时 A/B。新增两个候选参与原有成本排序、FFT 安全余量检查和内存复核。显式 D 的语义保持一致。

### 最终自动选型复核

最终 DLL 标识 `aa86c2b2f7acfe76`。复核使用自动 D，M58631 为独立于候选筛选的位宽。下表均为单次完整 NF，峰值取 Windows 进程的 PeakWorkingSetSize。M65521、M262139 的 4T 基线采用上述固定原默认 D 的两次中位数，未采集这四条基线的峰值。

| 指数／线程 | 旧 → 新 D | 原 → 新整曲线（秒） | 原 → 新峰值工作集（MiB） |
|---|---|---|---|
| M58631／4T | 34650 → 43890 | 46.958 → 37.717 | 2435 → 2952 |
| M65521／4T | 34650 → 43890 | 47.578 → 40.147 | 未采集 → 3158 |
| M262139／4T | 9240 → 10920 | 43.036 → 37.162 | 未采集 → 3089 |
| M262139／1T | 9240 → 10920 | 97.738 → 89.941 | 2540 → 3085 |

最终 CPU 存档与算术回归完成 36 项检查；两个新增 D 在 M16001、B2=1.2 亿、1T/4T 上各跑一次独立 GMP 三点投影，全部通过。运行中遇到的安全余量和预算拒绝仍然生效。[回归记录](../../data/experiments/stage2_cpu_planner_flow/final_regression/summary.json)

下一阶段按分配位置记录活跃系数的数量和字节、释放时刻及进程峰值。优先比较完整 F 树与仅保留上层、分段重建下层两种方式，对照建树、折叠和下降的实际代价。只有确认 M262139 的 D=30030、P=2880 在真实峰值限制内可运行，再与当前方案按相同实际 B2 比较。可复用 CPU tune 的缓存应区分位宽、普通／梅森算术、FFT、线程数、GW 构建和驻留策略，并在复用时重新检查内存。

分层方案需要保留归一化 baby 根及其原始顺序。建 F 时逐棵生成下一层要保留的子树根；主循环只读顶层 F 与倒数多项式。下降时沿已保存的上层传递缩放余式，每次重建一棵底层子树，输出该段叶值后释放。计划必须分别估算建树、主循环、下降三段的同时活跃对象，包括重建工作区、线程私有展开和 polymult 的临时空间。重点验证不均分子树、非满尾块、饱和分母、命中因子与中途停止。现有完整 F 树继续作为同 D 的正确性对照。

### 紧凑 G 树之后的预算实验

八段 F 树已经用于受限预算，宽位 G 树分层计时和固定 F／倒数预变换实验也已完成。[F 树重建](../performance/CPU_GWPOLY_STAGE2.md#0665-分段重建-f-树) · [G 树与缓存实测](../performance/CPU_GWPOLY_STAGE2.md#宽位-g-树与固定操作数)

### 相同实际 B2 下扩大 D

M262139、sigma=26、B1=1000、B2=459428970，1T 绑定逻辑 CPU 1，系数 FFT 长度 15360。自动计划 D=13860、P=1440、24 块，整曲线 65.516 秒。为探测生产估值排除的几何，另以 Windows Job Object 从进程创建时强制限制每进程提交量为 4096 MiB；启动器验证 worker 已继承该限制。对这几条探测曲线，显式提高传给规划器的 MiB 以进入八段 F 树，再读取系统记录的峰值提交量与工作集。每个几何单独运行，各计一条完整 NF。表中提交量含进程私有承诺内存，与驻留工作集口径不同。[探测脚本](../../data/experiments/stage2_cpu_inplace/capped.py)
