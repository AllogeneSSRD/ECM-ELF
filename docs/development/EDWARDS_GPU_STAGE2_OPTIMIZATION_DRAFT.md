# Edwards GPU Stage2 性能优化草稿

目标是在 GPU1 RTX4060 Laptop 上定位并优化完整 Edwards Stage2 成本，同时对照共用管线的 Montgomery PARAM0。固定曲线构造、sigma、B1/B2 和点覆盖，不通过省略曲线、点或检查声称性能收益。

基线为提交 b55f47d 的生产 Stage2。普通余因子与合法梅森承载分别记录；同一输入的版本比较固定 D，曲线族比较使用相同 N/B1/B2/D，但不将相同 sigma 解释为同一曲线。计时以完整引擎 init+main 为主，进程墙钟单列；嵌套计时用于定位，不重复求和。

原始数据保存在 `data/experiments/edwards_stage2_opt_20261017/`。Edwards 输入复用已独立验证的精确余因子 save；Montgomery PARAM0 由本机 GMP-ECM 生成同 N、sigma26、B1=50000 的 save。输入准备不计入 Stage2。首次本仓库 CPU Montgomery 准备在 16272 位失败，原始日志保留；因此使用独立原生 GMP-ECM 参考生成对照输入，不将该准备失败纳入 Stage2 时间或因子结果。

首个 10232 位 Edwards 对照在 D=180180、B2=27015978990 下完整耗时 44.708192 秒，init=7.625319、main=37.082872。`device_gleaf.t_prepare` 包含对先前异步点生成的等待，不能直接将整个区间归因于求逆或分组乘积；使用 CUDA 事件剖析区分真实内核成本后再决定优化。

性能样本保存实际频率/功率遥测，不修改设备设置。本轮实现、验证、正式交错矩阵、图表及权威性能说明已完成；本草稿按仓库规则保留，供用户决定清理。

## 定位与候选

相同 N/B1/B2/D 的首次 Montgomery PARAM0 为 44.687953 秒，与 Edwards 44.708192 秒接近。Nsight Systems 记录的 ladder 内核累计 26.644057 秒，其中 giant 尾块的四次调用累计约 20.079 秒；分段乘积仅累计约 0.704 秒。时间线证据在 `nsys_baseline_01/`；这些累计内核时间用于归因，不与完整墙钟相加。

候选在算术宽度超过 128 个 64-bit limb 且驻留叶预算足够时，把有效 chain 下限从 32768 改为 8192 点。已有较短输入保持原下限。首次候选 Edwards 完整曲线为 27.777511 秒，下降叶指纹与基线一致；这只是试探，尚不构成最终性能结论。

宽位数门禁另外覆盖非单位分组和非单位 [D]Q。非单位仿射转换失败后，原实现记录 GCD 并保留投影 X 作为占位叶，原始指纹依赖表示；但新尾块路径仍应保留旧结果。候选 1 在非单位基点样本中改变了因子集合，已拒绝。当前修正同时对非单位基点及新链生成后的非单位分组恢复逐点 ladder，复用已规划的坐标、索引、分段和分组缓冲区；重做前恢复逻辑 Gamma，物理工作计数保留实际重试。

统一规划与生命周期状态机为新尾块预留至少 8192 点的索引/seed 窗口，回退不再额外增长设备缓冲区。portable tune 记录实际有效阈值，旧 32768 路由样本不会冒充新路由。正式版本候选为 0.34.1；没有增加 CUDA 数学内核，优化作用于两种曲线共用的主机调度和已有设备点生成入口。

原 Prime95 Montgomery 历史 B1 为 20，本轮生成 B1=50000 的 PARAM0 对照以匹配 Edwards。正式性能比较只使用新矩阵中的相同输入条件，不将旧 B1=20 时间直接除以新 Edwards 时间。

## 验证与测量

最终候选 3 的独立门禁为 `wide_tail_gate_04/summary.json`：10 次跨版本调用，覆盖 8193-bit 的 8191/8192 点边界、16384-bit 的 8192 点、非单位基点和非单位分组。完整叶指纹及因子集合逐项相同，单位点的 chain/ladder 比较和 GMP 分段检查通过；拒绝的候选和原始证据保留。

`giant_cpu_gate_02/checks.json` 通过 265638 项断言、2054 个时间线条件、39665 个分配事件核对；`giant_native_plan_03/checks.json` 通过 12 组真实查询，涵盖新路由/预留容量、预算禁用、强制 ladder、诊断拒绝和大 B2。结果输出 22 项回归与完整 Edwards GPU 管线回归分别在 `submission_gate_01/`、`edwards_pipeline_01/`，均通过。这些是数学和离线流程检查，不做线上提交。

阈值边界另用正常模数、D=30030、I=8192、PARAM0 测量，每侧预热一次、正式四次，顺序 ABBA+BAAB。8193-bit 均值由 5.57977625 到 4.41558625 秒，16384-bit 由 21.73979 到 19.06783225 秒；完整 NF 和叶指纹一致。该调参探针证据为 `boundary_timing_01/summary.json`，不混入正式矩阵。

正式 `matrix_02/` 冻结基线 0.34.0 与候选 0.34.1，每格固定实际 N、sigma26、B1=50000、B2/D，六格分别比较 Edwards 与 PARAM0：383-bit 普通低档、10232-bit 普通低/高档、16272-bit 普通低档、10232/16272-bit 承载低档。四侧各预热一次、正式三次，共 96 次，预热与正式记录全部保留。无其他本任务 GPU 工作或编译与正式采样并发。

主指标沿用引擎 `stage2_full_wall.total=init+main`。它包含引擎内 NTT/S4 检查、主计算、GCD，计时前的 Montgomery/xADD 预检、启动、外层选形和 Stage1 另计；进程墙钟也单独保留。不能称为包含所有启动自检的进程端到端时间。

## 承载叶比较口径

`matrix_02/` 在第一个承载候选预热时停止，已入账的 17 条均为预热，尚无正式时间样本。原采集器要求原始 M 叶指纹跨路线完全相同，没有先投影到目标 N；该比较超出了当前承载合同。由于 Γ 逆元取自 N，不同 ladder/chain 投影表示可能改变 M 代表元。原采集器、停止日志和未入账调用保留，不覆盖。

补充的 `carrier_projection_01/` 使用两档宽余因子、两种曲线和两个构建，逐点比较 chain/独立 ladder，核对段积、组积、设备叶和 Γ；最终完整叶投影到 N，并与相同 N/B1/B2/D 的普通模数参考比较。诊断运行与计时分开；通过前不续跑正式矩阵。采集器将按每构建的已验证 M 指纹核对重复，跨构建则通过该独立目标环证明建立相等性。新计划只导入身份和原始证据完全匹配的已完成预热，所有正式重复仍重新执行。

## 完成结果

八次承载诊断均通过，累计1118160次逐点chain/ladder对照；完整目标环叶与普通模数参考一致。原始M指纹差异是表示问题，未为此修改正确的GPU算术实现。诊断实际执行源码保存在 `carrier_projection_01/collector_snapshot.py`；后续复用入口补充了源码冻结、身份检查和安全的环境字段记录，数学检查保持不变。

`matrix_03/` 导入17条已验证预热，再执行剩余7条预热和全部72条正式样本，三轮循环变换四侧顺序；96条均为完整NF。`audit_final_01.json` 核对全部来源、文件、二进制和源码哈希、目标环叶以及S4覆盖，`gmp_checked` 合计679488。原 `matrix_02/`、未入账调用和旧采集器保留，不覆盖或删除。

权威结果维护在 [Edwards Stage2性能](../performance/EDWARDS_STAGE2.md#固定-d-的-edwards--param0-优化对照)：五个宽位数条件的Edwards耗时减少9.24%–37.98%，10232-bit普通低档中位数44.687503→27.715751秒；PARAM0得到相近收益。383-bit控制组范围重叠，没有宣称加速。阶段图只堆叠互斥均值；shape是baby集合枚举，已经包含在init内。

最终PNG/SVG为 `data/figures/edwards_stage2_opt_20261017/final_03/`，CSV/JSON为同名 `data/benchmarks/` 路径。绘图使用本机Python3.14.7、Matplotlib3.11.1、NumPy2.5.2。早期 `final_01` 因采集用Python缺Matplotlib而未渲染，`final_02` 排版检查发现标签和图例重叠；统计和早期图保留，最终调整只涉及排版，数据未变。

本地生产产物为 `build_cuda_cmake/local_stage2_0_34_1/ecm_cuda_stage2.exe`。正式构建入口核对80份依赖和对象/工具链签名后复用已测试EXE，SHA256与矩阵候选完全相同（`2057d7cebb3f…`），不是另一个未经测量的重编译版本；验证日志为 `local_stage2_verify_01.log`。旧生产目录、配置和冻结证据均保留。
