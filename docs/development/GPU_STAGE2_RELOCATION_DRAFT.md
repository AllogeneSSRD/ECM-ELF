# GPU Stage2 relocation 开发草稿

目标：增加默认关闭的可选 GPU Stage2 relocation，保持原算法与原 B2/终端 guard 覆盖；NF 使用保守后缀，命中或目标 N 上出现非单位时重放原区间，再发布最终结果。短尾按完整 G 边界重分，避免独立 ladder 性能回退。只增加 Edwards 的新正确性/性能测试，GPU1 RTX4060 Laptop；原始证据写入 `data/experiments/gpu_stage2_relocation_20261018/`，不覆盖既有数据。

覆盖证明及 GCD=N 反例见 [relocation 参考](../reference/ECM_STAGE2_RELOCATION.md)。新功能版本0.36.0。Stage1 save 和提交格式的 B1/B2 不改变。NF 与 F 都须经过现有算术门禁；试算结果不能先发布。

选 D、Auto B2 与内存准入保留原区间估算，为原区间重放保留可行形状。relocation 不向旧 ECM 调优样本写入实测时间；纯 NTT 样本可复用。实际试算/重放时间和范围独立记录。这个版本不宣称已有 relocation 的自动选形时间模型。

开发步骤：统一范围与短尾纯整数规划；接入配置、CLI 和进程传递；分离 giant 绝对索引与局部索引；捕获所有非平凡 GCD/非单位并重放；验证几何、NF、因子、GCD=N、非单位及普通/承载路径；在固定条件下比较 NF 和 F 的完整耗时，更新当前架构/使用/性能文档并提交。本草稿完成后保留，由用户决定处理。

## 实施与门禁

实现入口为 `src/core/ecm_stage2_relocation.h` 的范围/短尾规划和 `src/cuda/ecm_cuda_stage2.cu` 的 `run_batched`/`run_real`。绝对 giant i 与局部树偏移已分开；试算的非单位状态先于旧 gcd=N 丢弃门禁记录。probe 不做见证命名，命中后复用共享 baby/F，执行原区间并发布原算法结果。INI/CLI、子进程、内部指标和计划输出已接通。版本0.36.0。

构建保留 candidate01（SplitCompile8、ptxas 内部 INVALID_HANDLE）、candidate02（SplitCompile1成功）及 candidate03（仅补 baby 非单位的重放计时，使其包含最后检查排空）。candidate03生产 EXE SHA256：`e11800591621683dcd8027900bbb7c0ef7f52f06f8f19d0f8ec75605102e3def`。末点及算法没有因计时修正改变。构建复核补充 HostOnly 的 relocation 头文件依赖检查；schema/构建脚本按仓库 LF 规则规范化，生成的配置摘要同步。

`gates01` 是日志采集问题（原始自检统计不在单一 debug 文件）；`gates02` 请求了只支持 P≤64 的 fold 诊断而反例 P=240。原始证据均保留；修正采集范围后 `gates03` 完成，`gates04` 加入短尾逐点对照与互斥阶段计时求和断言，共26项调用通过。几何探针157752项检查；宽 chain 18827点、短尾141121点全部与独立 ladder 一致。小素域、普通/承载完整目标叶与独立参考一致；真实 Edwards 因子10007及 gcd=N 反例因子1186519在开关两种模式下相同。诊断调用不用于性能结论。

`matrix01` 第一条预热因完整目标叶指纹被标记为诊断模式而拒绝计时；原始调用和采集器快照保留。`matrix02` 清除该诊断，保持 clean=1，使用既有下降叶指纹核对重复一致性。正式比较的四份NF输入复用上一优化矩阵；两份F输入独立生成。其中1000367上的剩余点阶20873，由独立有限域BSGS和直接点乘核对，用于区分后缀命中与baby非单位两类成本。


## 目标零 baby 坐标补验

最终复核发现旧 affine helper 把 Z≡0 当作 x=0 占位叶并返回成功，因此既有 noninv 计数不能单独表示“是否出现目标 N 非单位”。candidate04增加独立状态：设备 baby 的 bad_groups 或主机归一化非单位段均置位；不改变旧 helper、叶、因子或 noninv 统计。`baby_zero_repro01` 是尝试显式关闭生产固定 baby 路径而被拒绝的采集配置；改用受支持的分配失败注入进入主机回退，`baby_zero_repro02` 在旧候选复现主机/设备两侧都先执行probe。新的门禁要求两侧probe=0、原区间重放和完整叶一致。

因此在当前调用完整结束并入账后，通过下次调用的显式停止标记结束matrix02；12条预热及3条已完成正式调用保留，未启动调用只有停止说明。这份不完整候选矩阵不进入最终性能统计。最终构建和完整矩阵重新冻结，以使性能证据、边界修正及正确性门禁使用同一二进制。


## 最终构建与验证

candidate04完成目标零baby修正，按仓库规则规范化受影响源码/配置的文本字节后重新构建；算术内核保持不变。最终EXE SHA256为 `5f3628ec2c848a3829e5b91120e1c91406ce5fb8112eca9259bc9f3912a9314d`，正式本机目录 `build_cuda_cmake/local_stage2_0_36_0/` 经构建入口签名复核，EXE逐字节一致。`gates05` 的27项外层调用全部通过，含目标零baby子门禁4条调用（正常设备与强制分配失败回退，各测原算法/relocation），probe=0且最终完整叶一致。

`matrix03` 冻结最终本机EXE、运行库、81份编译依赖及采集辅助脚本，重新执行完整48次对照。增量审计只用于提前核对已入账调用，始终complete=false，不作为绘图门禁；完成后再做全矩阵独立审计。


最终代码复核将 legacy noninv 的注释改为“未能完成仿射转换的旧计数，饱和单独跟踪”。它不计入目标零Z，因此不能继续标注为包括gcd=N。这是一行注释的精确替换，没有代码或行数变化；`comment_equivalence.json` 保存新旧源文件SHA256，并验证逆替换后与实测二进制的冻结源码逐字节一致。构建清单和性能研究继续绑定实际编译的源码快照，不改写既有身份。
