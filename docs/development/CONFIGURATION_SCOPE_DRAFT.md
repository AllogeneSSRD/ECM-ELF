# 配置职责与队列保护开发草稿

工作从生产 Stage1 GPU worker 的启动错误开始。有效的 CPU 位宽策略与 GPU 目标同存时，原校验把 CPU 策略判为 GPU 启动冲突。进一步复现了反向配置使 CPU worker 停用合法任务，以及 OpenCL Stage2 因 CUDA 预设停止启动、因缺少可用 B2 停用任务的情况。

## 实施范围

- 区分任务格式错误和当前后端、运行配置或执行失败。只把任务本身的问题写成 `# ERROR`。
- 先确定实际目标后端，再应用其选项。按当前 worker 读取语义配置，仍检查全文件结构。曲线专用约束在任务构造确定后校验。
- GUI 保护配置路径、worker 编号和队列归属，提供分阶段追加参数，队列预览复用原生选择规则。显式的 `[shared] worker_count` 是同队列自动交接与 GUI 的共用配置。旧的显式 GUI 数量可作为兼容来源。
- v3 阶段选项允许 worker 覆盖。共享运行日志、滚动上限、完成记录及工作流 worker 数量保持全局。外部队列继续支持显式接收列表与队列段头。

## 验收范围

覆盖任务保留、真实输入错误标记、CPU 与 CUDA/OpenCL 同份配置、其他 worker 选项错误隔离、自动交接接收方资格，以及 GUI 的启动参数保护。正式配置规则见 [配置定义与解析](../architecture/CONFIGURATION.md)。

- 384 位 Stage1 增量构建与 30 项输入验证通过。v3 和旧配置的自动交接分别通过 13 个场景，包括没有合格候选时保留任务。
- OpenCL Stage2 的 13 项后端与队列回归通过。CPU Edwards Stage2 验证了独立 worker 配置校验。CUDA Stage2 的两个修改过的主机编译单元通过编译，完整 CUDA Stage2 链接和曲线执行待验证。
- TOML 夹具验证全部 v3 阶段键支持 worker 覆盖以及全局项限制。迁移测试 8 项通过。GUI 控制器、原生队列选择和 GUI v2 无窗口回归通过。
