# Stage2 重启覆盖 B2 与曲线数草稿

状态：0.52.3 已实现并完成离线及 GPU 验收。本轮保留逐曲线回执与最终 JSONL append，不实施仅 ckpt 结果存储方案。临时草稿保留，未自动清理。

授权行为：同一输入任务重启时，采用当前 worktodo 的有效 B2 和曲线数。已完成 150/960，目标改为 300 时续算 150 条；目标改为 100 时不再计算，按已完成 150 条封存结果并警告。NF 数量扣除因子命中曲线；已完成记录的实际 B2、D/P、时间不改写。

固定身份保留 AID、实际 N、完整 save SHA256、skip。可调整的目标数量、B2/Auto B2 独立存储；发布任务身份在恢复和调整期间保持，确保新旧参数的回执属于同一任务。

## 当前实现

State V3 分离输入 identity 与 publication_task，后者在导入旧档及重启调整期间保留，使旧 NF 回执继续参与最终任务封存。固定任务摘要使用 stage2-curves-v3、AID、实际 N、完整 save SHA256、skip；total、B2/Auto B2 单独存储。total 为 max(已确认完成数, 当前实际可用目标数)。正常 V3 恢复直接读稳定路径，无旧结果目录扫描。

V2 文件按原 total 和 B2 候选重新计算原摘要匹配。只有参数变化无法直接匹配时，才从带完整性校验的提交回执提取候选 B2。旧格式不存 B2 明文；若旧 B2 未保留在任何结果中，须先用原 B2 启动升级再修改，不能从摘要反推。多个旧档匹配时报错，不按时间或最大进度猜测。新档落盘后归档旧来源；归档失败停止，V3 重启可继续处理未归档的旧来源。

首先处理 pending：完整 JSONL 回执补记 done；无任何持久结果的尝试可放弃；数学回执已写但内部 JSONL 未完整提交时，调整策略报错，保留全部证据，需先用原策略恢复当前曲线。若完成数大于新目标，额外验证 save 确实包含这些完成记录，不因截短的当前选择范围而误判。

NF 封存仍采用最后完成 NF 的实际 B2、D/P 和时间。比如前150条 B2=10000、后150条 B2=20000，提交 curves=300、b2=20000，逐曲线 JSONL 保留各自界限。150/960 改为100时提交 curves=150、b2=10000，并警告请求小于已完成工作；不把新请求界限写到旧结果。因子命中仍单独发布，不混入 NF 数量。
