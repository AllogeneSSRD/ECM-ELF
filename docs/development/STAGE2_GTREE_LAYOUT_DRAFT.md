# G树窄位宽布局实验草稿

基线为提交`d28aa418`、0.54.5。生产M5987保存点的算术位宽5987、W94、D1141140/P103680，GPU目标1500MHz的对照中G树约18.52 s。当前分块布局默认只覆盖W>128且至少4棵完整G树。

## 假设与验证顺序

1. 分块布局降低根部较大操作数，使部分NTT跨过长度边界；先用生产packing查询枚举两种布局的精确长度和请求量，不能用次数比例代替。
2. 复制和请求分组可能抵消长度收益；相同D/P、batch、预算、点输入下对照完整曲线，分别记录G树、fold、引擎和父进程墙钟。
3. 多次G树的CPU准备和资源释放也可能形成空隙；若变换量不降低或收益不足，再针对准备、分配与同步定位，不同时修改多个机制。

默认性能保护：在获得证据前不扩展自动启用条件；实验必须显式锁定D/B2/算术，关闭自动选择、学习及短校准。两种布局执行同样的必需检查，并验证根摘要及小树独立GMP节点；不能把改变布局的实测写成旧布局的tune行。

原始输入、失败及正式对照保存在`data/experiments/stage2_gtree_layout_20261031/`，派生结果放在`data/benchmarks/stage2_gtree_layout_20261031/`。

## 实施与验收

0.54.6提供`NTT_GROOT_BALANCED=0|1`的固定参数实验；统一策略同时作用于内存/请求规划及执行。前端在父进程和worker校验固定D、关闭自动选择/学习/短校准等条件，并隔离旧tune读取。未设置变量时，原来的W>128且完整G批≥4条件保持不变。

原生packing确认M5987根部由65537→52225系数、NTT2²⁷→2²⁶；5872-bit普通根部32769→26113、2²⁶→2²⁵。4423-bit根部仍为2²⁶，不具备同样的长度收益。

首批14次计时：M5987各布局n=3，G树中位18.640→15.914 s；4423-bit各n=2为10.587→11.275 s；5872-bit普通各n=2为5.865→5.093 s。随后发现`nvidia-smi -f`终止时未刷新尾部，短样本未保留遥测。原始数据保留，不能按完整定频基准声称。

使用仓库已有Monitor增加逐行刷新的NVML记录器，每组每布局再复核1次。6次完整遥测重现两组G树约13%～15%的收益和4423-bit约5%的回退；有少量1455/1485MHz采样，按实际范围披露，不归一化。合计20次性能运行全部NF、clean=1，固定输入的根摘要一致，自检及抽查bad=0。

48项独立GMP节点及错误注入通过；8项布局/tune隔离门禁通过。CPU arena 681389项及请求/布局8539662项检查通过；共享OpenCL构建与32项功能回归通过；未设置变量的默认规划仍采用已有最快路线。故障测试、初轮CLI测试错误、CPU链接失败和遥测不完整的文件全部保留。

现有自动条件不扩大。正式结果及计时边界见[G树性能](../performance/STAGE2_GTREE_LAYOUT.md)，本草稿留待用户决定处理，不自行删除。

## 后续待办

- 布局成为ECM Shape、TOML行和运行时搜索的独立身份，精确重建旧行布局；不能只新增开关后借用旧测量。
- 以实际NTT长度、批处理、归约及显存准入筛选布局候选，再安排有界配对试跑；不只按W或P判定。
- 扩大预算边界、位宽和空闲设备验证后决定默认资格；CPU元数据和同步仍可单独剖析。
