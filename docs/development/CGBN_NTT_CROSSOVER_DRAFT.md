# CGBN逐行平方与整数NTT交叉点实验草稿

本轮实验不增加版本号。GPU1 RTX4060 Laptop，保留原CGBN／生产Stage2默认，不操作GPU0或调整显卡设置；编译与正常性能测量串行。原始数据写入`data/experiments/cgbn_ntt_crossover_20261103/`，图表和汇总各放在`data/figures/`、`data/benchmarks/`对应目录。

## 平方扫描

实现隔离的逐行三角形平方／双词WMAD REDC。每行只代表对角线及上三角，倍增需保留最高额外位，额外高词在两次归约后注入；商、进位、R和规范返回保持不变。首轮先检查GMP、别名、尾组、全1进位和最小容器，再看原生批量与独立延迟。

注意数学上有效的部分积少于n²，不代表CUDA发射的warp指令减少。每lane依旧持有完整输出区，动态掩码、倍增和REDC状态可能增加指令或寄存器成本。只在真实计时合格后才考虑生产接入。

## NTT交叉点

紧凑大整数打包复用生产Goldilocks forward／inverse与精确carry-cone，不使用多项式系数间隔。输入为同一组32-bit limb；输出为完整2s-bit乘积。计入打包、两次forward、合并pointwise的inverse、进位及解包；表和工作区初始化另记。输入／输出留在GPU，不把传输省略伪装为完整应用成绩。

同时比较普通Montgomery乘法：NTT完整乘积后接原CGBN REDC，对照原融合mont_mul；两侧保持原R和唯一规范代表。完整乘积与模乘分别给出交叉点。

批量分别检查1个整数的依赖递推、原生批量和更大吞吐批量；CGBN整数在一次kernel内递推，NTT需要多kernel，不人为拆散CGBN。NTT另外测CUDA Graph提交，Graph构建及首调用时间单列，不用预热丢弃首样本。全部输出对GMP比较，完整乘积递推消费高低半。

先测常用4K／8K／16K，再扩展32K和64K寻找边界；边界按实际支持的CGBN容器和资源限制报告，不无依据外推。每进程保留多个event样本，三进程轮次交错，记录二进制／依赖身份和GPU遥测。

## 已完成实验及边界

逐行模式24在512／8192正确，最高额外位必须延后两步注入，最后一行的h必须为0；56次GMP／保护区、2次故障注入及两类sanitizer通过。8192原生批量慢35.6%，NCU指令增加87.4%；置零的下三角未减少实际MAC发射，不接Stage1后端。保留原型，未来需改工作分配。

旧生产构建复用因`src/io/save.cpp`依赖身份过期被拒绝，没有绕过门禁。独立编译实际NTT五模块；新增受校验的ModuleBuild复用和仅作用于探针的LocalDefines。补了ABI、依赖、对象三种负例拒绝测试。原失败构建目录保留。

整数探针以紧凑打包链接生产NTT；check253调用（220成功／33故障正确拒绝），筛选195调用，冻结后独立324调用、1620个event样本。512和65536的两类sanitizer共24次0错误。128K额外测量是64K批量仍回退后开展的扩展，不扩大生产位宽。

单整数Graph完整乘积在16K首次胜出，模乘32K；192／1536批量直到128K才胜出。NTT128K／192完整乘积比CGBN快约3.84倍，普通模乘约2.13倍，但包含CGBN的255寄存器／大量local访问边界。常用4K～16K批量仍保留原CGBN，不能把单整数或超大实验容器推广为ECM整曲线收益。

NTT每次仍做两个forward，不利用固定第二操作数的频谱；Graph捕获整链，准备成本单列。Nsight导出DRAM单位会随capture改变，已按byte／Kbyte／Mbyte的SI单位归一，不能直接把原数值相加。整数NCU初次因固定正则中的竖线触发参数guard，未启动GPU；保留原脚本和目录，以引号内固定regex进行v2采集。数学／原型正式结论分别更新至reference及performance主题。

本草稿和全部失败／首次样本保留，完成后由用户决定是否清理；实验提交保持0.57.17且不带版本号前缀。
