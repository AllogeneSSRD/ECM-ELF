# Stage2 运行时选型准备优化草稿

本轮目标：减少生产队列反复执行相同成本计算和显存失败准入的主机开销，保持已测最快路线、默认性能保护和执行前准入。

## 证据与验证口径

生产 M5987 余因子5700 bits，B1=260000000、B2=1300000000000、D=1141140，单条记录的选型为8.2779935 s，其中两路线成本排名6.3970864 s，各重复拒绝16个候选。冻结输入位于 `data/experiments/stage2_phase_read_20261031/`；正式分析见 [准备开销](../performance/STAGE2_PREPARATION.md)。

假设及验证顺序：

1. 同一排名中重复插值相同 NTT 长度与 batch 成本；不可变估计器内的精确记忆化应减少计算，预测值应逐位一致。
2. 显存不变时，已证实不适配的候选反复消耗准入预算；短期父进程提示可跳过这些失败并继续探索。显存、设备、输入或环境变化必须失效。
3. 选型属于规划；在选型前进入规划阶段，应使 GUI 的读取阶段只覆盖读取和保存点验证，保持现有阶段名称。

测试使用隔离队列和复制的保存点、tune；不更改生产队列、配置、GPU频率或功耗。先运行 CPU 合约，再用同一二进制开关 A/B 和保存点完整曲线校验。不可将规划重放当作 GPU 引擎吞吐测试。

## 完成与证据

0.54.5实现不可变估计器的NTT成本、运行统计和位宽预测复用；严格匹配的运行样本只筛选一次。显存失败采用共享D表的有界位图，仅在完整作用域及精确free/total不变时使用；跳过后继续搜索，不把16次准入上限当成终止证明。没有保存完整跨曲线排名，也没有新增缓存文件或tune行。

CPU的2288项D搜索/缓存合同和模型逐项双精度对照通过；不同设备/显存、B1完整身份、测量更新后的新估计器、位图往返与损坏输入均覆盖。共享OpenCL worker构建及32项功能合同通过。原生CUDA两个设备对象经输入/对象摘要核验复用。

冻结M5987输入，串行规划的活动搜索n=3，准备均值4.871→1.418 s；排名3.498→0.215 s。完整两版各4次同一点NF，保持D/P/承载，队列204.434→199.620 s；原始profile未写回，根摘要及所有必需抽查通过。最后3条按剩余任务策略停止探索，完整队列收益不代表长队列稳态收益。正式依据与复现入口见 [准备开销](../performance/STAGE2_PREPARATION.md#准备复用的验证结果)。

证据根目录`data/experiments/stage2_preparation_20261031/`保留了受限环境导致的编译/路径访问失败、初轮测试错误及修正后的验收，不覆盖失败记录。`final_plan_ab/`同时验证内部开关；该开关不回退严格条件的预筛选代码，不能把关闭缓存的优化二进制当作旧版本。

本轮代码与验证完成。本草稿留待用户决定处理，不自行删除。
