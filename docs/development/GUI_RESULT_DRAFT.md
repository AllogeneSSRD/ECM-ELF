# GUI Result：开发草稿

## 范围

用户要求替换过时的 GUI 结果功能，命名为 Result，接入发布版 Result，支持 F/NF 等筛选及一键复制。按用户要求保持 0.44 系列，版本从 0.44.7 递增至 0.44.8。正式说明维护在 `docs/usage/GUI.md` 的 Result 一节；本草稿保留开发验证记录，完成后由用户决定整理方式。

## 实现

- `results.h/.cpp` 改为不依赖计算引擎的只读提交结果模型，使用共用 TOML 投影和 JSON 解析器，覆盖两个阶段、worker 覆盖及默认文件名。按规范化路径去重来源，保留各文件原发布顺序及不同文件中的独立行。
- `App` 移除事件驱动的 GUI 因子摘要写入、文本重建与退出 flush；因子事件仍更新 worker 状态和高亮。Result 展示只从正式发布文件取得 F/NF。
- 筛选状态、阶段、来源及原始 JSON 文本，支持筛选结果/勾选结果/单行复制及原文详情。复制使用原始行，不改 checksum，不合并或重排源文件内容。
- 文件大小与修改时间缓存独立于绘制频率，面板可见时 500 ms 检查一次。支持文件追加、替换、截短与删除；完整 JSON 末行可无换行，未完成尾行暂缓，损坏完整行提示并排除。
- 双语标题均为 Result。配置 schema 移除 `[gui] results_json`、`results_txt`，由生成器同步模板、默认值及配置参考。历史缓存文件不改写。

原始证据位于忽略目录 `data/experiments/gui_result_20261021/`、`gui_result_ui_20261021/` 及本轮 build 日志。

- GUI 及独立结果测试目标编译通过，GUI 自检 33 项通过。
- 只读 Result 测试覆盖来源解析、worker 覆盖、路径去重、F/NF/阶段/来源/文本组合筛选、复制字节与顺序、无写入刷新、半行追加、损坏行、文件替换/删除、重复独立行、大整数和中文手动文件来源。最终新增完整但不符合提交结构的无换行 JSON 拒绝检查，共 24 项，测试套件 `results-unit` 全部通过。
- 实际中文界面验证 F 筛选为 2/5 行、勾选后单条复制、全量筛选复制；剪贴板写入后回读逐字节比较成功，测试记录为 5 行、1684 字节，只有计数与字节数进入 trace，不输出 Result 内容。原生文件选择器使用 Unicode API，中文标题及文件类型筛选正常；自动化未完成原生对话框的完整文件选择，中文路径读取由独立测试覆盖。
