# Stage2 D 候选表与搜索改进草稿

本文记录候选表统一的研究、实施和待验收事项。**2080项共享硬编码表、NTT区间局部搜索和预算内重启已接入源码**。前期离线/只规划证据仍对应其冻结输入；当前实现尚未新增完整曲线性能样本，不声明矩阵性能已经持平。当前正式规则见 [Auto B2 / tune](../architecture/AUTO_B2.md)。数学与 Prime95 表的固定依据见 [Prime95 Poly Stage2](../reference/PRIME95_STAGE2.md#3-d-候选表的含义与适配条件)。

## 1. 结论

1. 统一硬编码表可行，并能消除当前运行、tune、旧接口及分析工具各自维护候选的分歧。
2. 当前 14 项表过稀：它只与 Prime95 当前启用的 88 项 poly 表重合 5 项；现有生产性能文件也含 4 个表外 D。但底层默认模型另枚举约 38 万个 D，因此“tune 表遗漏”不能等同于“默认运行从未考虑”。
3. 扩充应结合小素数轮、素数幂扩展、实际 NTT 拐点、树填充边界及已有有效测量。只复制 Prime95，或只选拐点下最大的 P，都不足以得到本 GPU 实现的最佳参数。
4. 比扩表更直接的搜索改进是：**全表模型筛选、按执行形状划分区间、少量局部实测、预算内跨区间重启**。以数值 D 为唯一邻接关系的下降不能跨越 NTT 翻倍后的性能上坡。
5. 新表中的值表示允许自动考虑的几何，不表示已经更快。默认替代仍需完整曲线配对证据和当前联合显存准入；原有中位数/MAD 门限保持。

## 3. 选型应看完整流程

定义实际目标位宽 n、算术位宽 S；普通路径 S=n，梅森承载路径 S=p。对给定 B2：

**P=φ(D)/2；I=⌊B2/D⌋+2；q=⌊I/P⌋；r=I mod P；G=⌈I/P⌉。**

G 次 G 树中有 q 个完整树及可能的短尾树；首树初始化 H，之后做 G−1 次 fold。规划应比较以下工作：

**T₂ ≈ T_baby(P,D,S)+T_F(P,S)+T_inverse(P+1,S)+T_descent(P,S)+T_accum(P,n)+T_giant(I,D,S)+q·T_G(P,S)+T_G(r,S)+(G−1)·T_fold(P,S)+T_small(B1,D,S)。**

公式是工作分解，不把嵌套的归约/NTT事件再次加到阶段墙钟。树有尾部，Newton 有不同请求长度，giant 有 chain/ladder 分支，分块还有准备和同步成本。NTT 的 Conv/s 只能估计其中的有限域卷积部分。

在 D/P 比值变化不大、暂忽略拐点的区间，固定开销约随 P 增长，主循环约随 B2/P 减少，产生 P∝√B2 的粗略尺度。它适合建立初始搜索范围，不能跨 NTT 或显存跳变直接外推最佳 P。

### 3.1 P 到 NTT 是整数阶梯

设一次乘法规划操作数有 M 个系数，h=max(1,⌈log₂M⌉)，槽位宽 v=2S+h。选择满足精确性界的最大 b：

**a=⌈v/b⌉；M·a·(2ᵇ−1)² < 2⁶⁴−2³²+1；L=nextpow2(2M·a+1)。**

fold 的代表形状 M=P+1；实际 F/G 树、inverse 和下降还要查询各自请求。树填充的顶层子操作数是 **2^(⌈log₂P⌉−1)+1**，P>1，不能一直用 P/2+1 代替。P 的增长可能改变 b、a、树高和 L；S 增加很少也可能翻倍 L。

代码依据：`src/cuda/stage2/ntt_runtime.cuh:2638`、`:2829`、`:3151`；完整请求程序 `src/core/ecm_stage2_requests.h:39`；公开纯形状查询 `src/cuda/ecm_cuda_stage2.cu:9775`。当前 portable 成本域拒绝 L>2²⁷，见 `src/core/ecm_stage2_portable_model.h:44`；这不是 shape 查询或全部设备的绝对长度上限。

以下是仅按 fold M=P+1 计算的最大 P，不代表整条曲线已准入：

### 3.2 显存不能仅用最大 NTT 筛选

当前 fold owner 在 reuse=3 时，w=⌈S/64⌉：

**B_owner=56w(P+1)+48 bytes。**

依据为 `src/core/ecm_stage2_geometry.h:102`；其他 reuse 布局使用各自公式。owner 预算可以构造廉价 P 上界，但完整准入还要计入实际 NTT 工作区、表、树租约、frontier 元数据、点缓冲、输出与阶段生命周期。owner 适配不意味着整条曲线适配，各模块峰值不能相加冒充进程峰。

驻留/回退会改变传输量和成本，接近 owner、arena、现场 free 边界的候选应归入不同搜索区间。必须由原生联合计划确认，不能把离线 fold 长度当作显存证明。

## 4. 原生只规划核对

本轮 24 项查询使用冻结 EXE `50171511de1dbc9b998e7a352173edbac4bc70cb181bb6c81da442e542d4e659`，冻结性能文件 `6562cafebba918d8d476ca6345a8fa6b72f18e0365b8d8ffc92c3e1ffa0eb417`。设备为 RTX4060 Laptop、驱动610.88，预算 arena6300/fold640/batch256 MiB。输入取既有 M503/M5003/M8011 余因子 save，实际位宽318/4667/7995、B1=20、sigma26；B2=2.6×10¹²，分别锁定普通和对应梅森承载。

所有调用设置 `--plan-only --short-calibration 0`，记录 `curves_executed=0`。24 项 fold 长度与离线公式一致，21 项现场初始 free 准入，3 项报告 `big_cap_refusal`。后者是规划容量拒绝，**不是运行 OOM，也不是性能失败样本**；请求程序仍可生成，因此仅看 `finished=true` 不足以放行。

### 4.3 小位宽还受树填充边界影响

## 5. 统一硬编码表的设计

### 5.1 唯一维护位置

建议新增 **`src/core/ecm_stage2_d_catalog.h`**，维护严格递增、去重的 D 字面量；P、素因子元数据由统一整数函数推导或编译期生成，不手工维护第二份 D/P 数值。编译期核对 D≥6、偶数、当前上限200000000及派生值无溢出。

消费者统一为：

- 原生默认 D 成本模型，替换当前在线47-smooth枚举。
- portable 默认平台比较、固定 B2 与 Auto B2 候选。
- portable tune 和仍保留的旧 `EcmEffort` 接口。
- Python分析工具通过同一表提取候选；生成器作为维护工具，不在运行时生成新的自动候选。

显式 `--d` 可保留手动研究几何入口并经过原生检查；自动选型来自共享表。显式 `--tune-d` 仍是用户指定的受限搜索集合，不暗中加入表外默认值。性能文件是测量数据，不再成为另一张隐式自动候选表：已知有效表外 D 在发布表时纳入；未列出的记录保留，但不静默改变自动候选域。

构建依赖、源码身份和发布清单应包含新头文件。涉及 CUDA 默认枚举的修改必须重新编译对应对象；只重编 host 无法同步该消费者。候选表 hash 可用于日志与复现，不应因候选增删就否定仍相同的 NTT 数学形状和合格原始测量。

### 5.2 候选生成与维护准则

离线生成，审查后提交字面量表：

1. 保留当前14项、短校准D210及有效既有测量，避免已知优良参数因整理消失。
2. 纳入Prime95当前有效poly表；保存其版本与来源，仅把它作为几何先验。
3. 扩展若干素数幂，尤其2的幂。倍增D会改变P/giant折中，能提供Prime95奇数倍轮之外的NTT位置。
4. 在代表性S和各个实际NTT长度边界两侧保留P邻项；也保留P跨2的幂时的树填充邻项。
5. 同P保留较大D作为优先代表，但保留已有测量和Prime95基项。较大D降低I，却会改变baby标量、CPU扫描和小素数处理，不能当作严格支配证明。
6. 记录生成范围、选取规则、输入hash、每项来源和候选集合差异。表扩大后，以真实工作负载和联合计划评估覆盖，不以项数作为质量目标。

本轮覆盖草案从282395个偶数47-smooth值中选边界代表，再并入上游/实测/幂扩展，得到 **2080 个不同 D**。生成所用S为52个代表位宽，覆盖128～16384范围内的选定点；fold边界取log₂L=14～27，树边界取P=2³～2²³。它是可审查的候选集合原型，**不证明所有实际位宽和预算均有最优候选**，也不要求测2080次完整曲线。

| 来源标记 | 草案中带该标记的 D 数 |
| --- | ---: |
| 当前表 | 14 |
| 已保留测量 | 18 |
| Prime95有效表 | 88 |
| Prime95值的2幂扩展 | 970 |
| fold NTT边界 | 1096 |
| 填充树边界 | 105 |

一项可有多种来源，以上数量不能相加当作集合大小。后续可在全请求成本和输入矩阵审查后压缩冗余；不要仅因同P或相邻D就删除有独立用途的候选。若新的S区间缺少合适点，通过维护工具补充字面量表，生产与tune仍读取相同集合。

### 5.3 表覆盖与 tune 等级分离

所有等级使用同一自动候选域。level只控制位宽/B2网格、重复数、最多搜索区间数、邻域测量数和总预算。先模型筛掉不可能有竞争力的形状，再按模型中心上下各一个合适邻项测量；不按等级从整个D表均匀抽几项。

这保留了用户要求的少量局部调优，同时避免低等级因候选稀疏直接遗漏适合小位宽或NTT平台的D。模型枚举2080个候选与计时2080条曲线是完全不同的成本。

## 6. 搜索改进

### 6.1 廉价筛选和完整准入分层

先由共享表派生P/I/G与完整请求形状，筛掉数学输入无效、portable成本域之外、当前未支持的G=1执行路径等项。用owner公式等建立廉价界，缓存同S/P请求形状；不能把一个驻留预算失败扩展为所有更远D失败，因为P不随D严格单调。

随后按完整模型成本排序，给少量领先项作原生生命周期准入。可从8项开始，必要时扩展；若前列均不适配，应继续查找可执行候选，而非无条件固定截断。候选变化的完整计划按实际S/B1/B2/D、预算、分块和执行设置缓存，现场free仍重新核对。初始形状查询可按S/P复用，含小素数工作和巨步尾部的完整计划不能仅按S/P复用。

Auto B2还要搜索多个B2，不能为每个D×B2重新构造全部固定工作：相同S/P的F树、inverse和下降形状先缓存，再计算I、完整G次数、短尾及fold重复数。会受预算和batch策略影响的执行成本另带条件键；既不重复规划固定部分，也不把不同尾部或分块伪装成相同形状。

### 6.2 按执行区间搜索

区间键建议使用fold/主要inverse/顶层树NTT长度、填充树高、fold/frontier驻留状态和giant生成分支等粗粒度特征。不要把所有请求明细拼成键，否则几乎每个P都成为独立区间。

每个区间按P组织邻近候选，并以D/P、模型成本和已有实测排序。同P的不同D是同组几何对照；数值D仍可用于展示和表的固定排序，但不作为性能方向的唯一含义。

测量步骤：

1. 保留当前默认基准及同条件已测赢家。
2. 在模型最有竞争力的区间选中心，先测中心及前后邻项，显著更快才移动。
3. 邻域无收益后，若预算允许且另一区间的预测仍有竞争力，直接选其模型代表作为新起点；无需逐项经过更慢的过渡D。
4. 每次只暴露少量新候选；低level限制重启次数，高level增加区间覆盖和重复精度。
5. 最终正式替代要求配对完整时间满足 **T_A+2MAD_A < 0.98T_B−2MAD_B**，并通过当前原生准入和执行路径资格。

跨区间重启是有限候选探索，不保证全局最优。预测只决定去哪里采样；没有完整测量时，不能据此宣布生产默认更快。固定B2的现有默认保护和Auto B2的模型资格需保留。

### 6.3 区分无效、延期和收敛

当前 `src/core/ecm_stage2_portable_driver.inl:619` 将“已有时间预计超过剩余预算”写入 `search.rejected`；`:627` 无观测也作相同处理，`:635` 用邻项是否耗尽打印complete。这可能把**预算未测**显示为窗口已完成，和数学/容量拒绝混在一起。

建议分为：tested、invalid/admission_rejected、budget_deferred、interrupted。只有规定邻域均已测或有独立无效理由，才能报告该区间完成；预算延期在下次tune优先继续，不能关闭跨区间候选。日志保留窗口/进度/完成及简短原因，内部曲线详情仍写证据文件。
