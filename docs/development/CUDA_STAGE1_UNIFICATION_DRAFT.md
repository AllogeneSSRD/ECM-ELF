# CUDA Stage1 统一执行架构实施草稿

状态：P0–P2、P3a 完成；当前实现 0.46.3，P3b 待实施。起点实现版本 0.45.28；实施提交使用 `[0.46.z]`。

本草稿是此次开发的权威记录；[规划报告](../web/architecture-review-20261021-cuda-stage1.html)保留获批方案、R1–R9 的依据和目标，不代表已经实现。规划来源为任务“规划统一 CUDA Stage1 架构”（01a15f10-45d2-7a73-aa13-9dc3702ef03d）最后一轮扩展方案。起点 ef800e6。既有沙箱诊断相关四项工作区修改不属于此次工作。

## 范围及合同

两种曲线以 CUDA 私有完整入口 `run_mont_stage1 / run_edwards_stage1` 对齐：解析选择、准备标量、恢复或构造批次、执行设备计算、验证末点、发布批次。简单阶段直接顺序表达，不为六个阶段制造六层转发。不建立跨后端策略框架；保留 CPU/OpenCL 合同、设备实例、注册表、等待探针与各算法切片循环。

正常数学身份始终为 curve + param（仅 Montgomery）+ sigma；标量和算法约束保持，Montgomery 六位余量、Edwards 一位余量保持。binary bits、NAF columns、PRAC plan index 与 M-equiv 分开。普通 Montgomery 切片不增加回读或归一化，Edwards 维持每片规范坐标回读。存档字节格式、版本、字段序及旧档读取保持。

必要修正：底层错误返回任务层并释放资源；模逆失败区分真因子与退化；明确准备/执行/持久化/发布失败及停止；单调墙钟触发周期保存；候选验证后提交；非法选择拒绝；进度归属单次运行；尺寸乘法检查；已完成普通坐标档跳过无用计算；先构造拥有结果数据的对象再发布。任务层仍独占批次外壳、锁、结果账本和最终清理。

配置持久化时必要 checkpoint 提交失败为失败，失败优先于停止；最后切片计算完成时执行验证和必要发布，停止阻止下一批。间隔零只禁用周期保存。尚未复现的尺寸与跨外壳备份风险按证据验证，不写成既成故障。

## 分阶段实施

1. P0：冻结五条执行路径和旧档、输入、编译身份；建立缺陷与正常行为对照。
2. P1：统一曲线 workflow 入口与后端分派；建立最小内部结果/失败合同及每次运行状态。
3. P2：构造期 GCD、CUDA/CGBN 错误传播、资源释放和执行失败归类。
4. P3：对称 checkpoint 模块、候选验证、进度提交与停止/发布协议。
5. P4：收拢低层入口、显式化 resident/PRAC 依赖、进度及预算、完成档优化。
6. P5：独立数学、停止恢复、旧档与错误注入、受限/完整档位、CPU/OpenCL/探针和增量编译验收；同步正式说明。

每阶段 local build 验证后更新本草稿并提交。使用正式 `tools/build`；CUDA 沙箱已知问题使用同参数非沙箱构建，不改变工具链或降低计算参数规避。遇到预期外重大问题停止。开发证据位于忽略目录 `data/experiments/cuda_stage1_unification_20261021/`，保留失败样本。

## 目标职责

- `cuda/stage1/execution.h`：两种完整运行入口，复用现有请求/结果。
- 两曲线 `workflow.cpp`：完整计算与批次输出顺序；不拥有任务账本或队列。
- `runtime.h/.cu`：设备选择、缓冲、发射、同步、错误检查和所需回读；实际 CUDA runtime 依赖保留。
- `batch.h / host_math.cpp`：主机状态、构造、验证与末点处理；普通 C++ 编译。
- `checkpoint.h/.cpp`：各曲线载荷编解码、恢复资格；复用共享 storage 的轮换、锁及外壳。
- 进度输出及诊断：普通 C++ 实现；策略继续归现有 host_policy。
- `launch / registry / instances / prac`：保留真实设备编译和测试边界。

## P2 完成：正确性、错误传播及资源归属

版本 0.46.2。Montgomery typed runtime 结果区分完成、停止、采样截止和失败；生产 workflow 直接接纳结果，旧 C 入口保留为适配。CUDA/CGBN 错误不再直接退出 Stage1 进程，缓冲、事件、报告、诊断文件和主机数据在提前返回/异常时清理。Edwards 缓冲/报告/事件禁止复制，低层入口可回传设备故障来源。设备故障使任务明确失败并停止队列，保留原行，不假设 context 可继续；普通执行错误仍按既有队列策略处理。逃逸异常按实际任务调用边界归类，不再凭 factors 是否存在猜测阶段。

PARAM0/PARAM2 不可逆分母分为真因子与退化。真因子立即写既有 submission 通道，保持索引的恒等设备通道在结果归一化时读取该因子，不产生伪 Stage2 点；恢复重新推导构造期因子，不修改磁盘格式。GCD=N 拒绝构造。有效公式保持，低层 PARAM2 不再把 sigma<2 改成另一 sigma。主机布局、乘法尺寸与分配结果增加检查。Montgomery 结果/参数/标量提前取得所有权；完成点和因子的旧外部格式保留。
