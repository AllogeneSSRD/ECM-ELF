# OpenCL Stage2 点提交与多曲线研究草稿

状态：0.54.3已构建并验证NVIDIA 513～8192-bit默认反馈式chunk／窗口；未自动选择CPU点或并行曲线数，未更新生产目录。当前结论与复现入口统一见[性能报告](../performance/OPENCL_STAGE2.md#自动点执行计划)，本文保留研究过程，完成后由用户决定处理。

## 诊断假设与反馈闭环

1. 宽位点SOS／private数组及组织不合适：只改group或内层展开，逐点对比完整X/Z，再看设备事件时间。
2. 单曲线提交点数不足：固定G批和NTT运算，扩大坐标窗口及chunk；NTT计数和每G批原始标量样本不得减少。
3. CPU准备、点生成和同步间隙可重叠：固定总曲线数，比较C1/2/4，分别记录完整吞吐、单曲线延迟、CPU及内存。
4. 多context可能只增加竞争：GPU点进程与CPU点分流分别测试，不能把多进程同时存在当作GPU物理并行。

首个多进程初筛在所有任务退出后立即查询Job，遇到active_processes退出记账延迟；改为有界等待完整进程树排空，原始失败保留在`small_p_screen/`。正式重复使用`small_p_repeat/`，未丢首轮。

## 实施

- PointGenerator允许一次生成多个G批的坐标；仍对每G批首／中／末从原Q、完整iD重算。末尾短批去重方式保持。
- `ECM_OPENCL_POINT_WINDOW=0..65536`，默认0；按已有batch额度估算上限并对齐原G批，不修改G树和fold划分。chunk继续独立限制单条设备命令。
- 参数在点生成前拒绝越界；不可逆种子、饱和分母、因子严格整除与失败排空继续由原路径处理。
- 多曲线工具只生成隔离任务，不并发消费生产worktodo。Windows Job计账覆盖继承子进程，不包含attach之前极短的启动段；峰值commit与NVML设备占用分开。
- 编译hint与睡眠等待只在`tools/experiments/opencl/point_codegen.py`的实验资源副本中测试，未修改生产内核或等待策略。PTX的local提取已限定声明行；旧探针结果中的程序级ld/st计数不能当作动态spill流量。

## 全位宽快速矩阵与giant chain（0.54.4，已验收）

用户确认先运行13位宽、B2=260000／2600000、普通／承载各三遍，再推进点算法。冻结OpenCL0.54.3与CUDA0.54.0，固定D2310/P240、arena512/batch64/fold640 MiB；两后端共312次计划调用。该范围不是生产B2矩阵，不能按B2比例折算为生产性能。原始目录为`data/experiments/opencl_full_matrix_20261030/quick_13/`。生产B2另52格只规划检查已通过，未开始性能计时。

### 可证伪的假设

1. 如果giant逐点ladder是主要额外成本，保持点数、G批、NTT工作及独立检查，改为相邻双种子加分段xADD后，giant设备事件时间应下降。
2. 如果>8192-bit的chunk16造成并行不足，保留baby策略，仅扩大有界giant链提交应减少命令数和giant耗时；不会改善baby耗时。
3. 如果下降、S4和同步成为剩余瓶颈，点内核下降不会按相同比例反映到完整曲线；必须分别保留设备事件、算子墙钟及父进程。

### 候选实现与正确性合同

- `Points::consecutive`每个工作项负责一小段连续倍点；一次ladder保留[k]Q与[k+1]Q两个种子，段内使用上一个点加Q、以前一个点作差分。首标量0的第一次递推使用倍点；末段、uint64范围和段长均检查。
- `ECM_OPENCL_GIANT_CHAIN=0|1`候选默认0，仅显式启用。已有CPU／AMD宽位分流保持。原始点计划的反馈只统计ladder，不将chain事件误当ladder样本。
- `ECM_OPENCL_WIDE_AUTO=0|1`候选默认0。NVIDIA 129～256 limbs在原16点seed后尝试完整32工作项组，再依据真实每bit事件耗时倍增，单CU波内最多256点；裁剪和尾批不训练。完整组的单位点成本若比seed差超过10%则退回16；后续升档每bit耗时增大超过35%时拒绝该档，停止继续增长。它没有1秒硬时限，原≤8192-bit模型不变；手动chunk/group继续锁定反馈。
- 链的非单位投影尺度不能直接用于因子或仿射根。主机对每条链命令的Z积求GCD；非单位时从原Q、完整iD独立重算整条命令，再进入原有取样、归一化和因子验证。正常路径的额外模乘/GCD及恢复成本单列。
- 非显式窗口允许有界的跨G批点暂存；显式窗口继续生效，显式point chunk也限制chain命令。G树分批、NTT次数、每G批原始取样和完整叶哨兵保持。
- 新点探针检查连续区间、尾段、零标量、uint64上界与非法参数；素数夹具不得丢失有限点。合数上的原始非单位另记，不冒充已比较的输出words。

### 点算法的工作量口径

仅统计当前OpenCL点内核中的Montgomery乘法调用，不把加减、访存、GMP检查和主机恢复换算为同成本。对正标量k，设L为其二进制位数：普通ladder需要3次基点转换、5次初始倍点、L−1轮（6次xADD＋5次xDBL）以及2次输出转换，合计11L−1次。不同k的L应分别求和，不能用最大位数冒充精确总量。

连续段含m≥2个点时，种子ladder保留两个相邻点，需要11L＋1次（包含两个点的4次输出转换）；其余每点是6次xADD＋2次输出转换，因此段总量为11L＋8m−15。长度1的末段为11L−1。首标量0另外按特殊分支计数。该公式描述算术调用数，不是GPU周期或吞吐预测；投影分母非单位时的整命令重算另计。

当前巨步已先将[D]Q归一化，标量位数约log₂(B2/D)，而不是log₂B2。单纯把独立ladder改成短段2点，算术下降接近一半；更长段可进一步摊薄种子。与此同时，工作项数从点数降为段数，可能损失并行度；段长和提交大小必须联合验证。宽位升档不减少上述调用数，主要检验命令组织；四设置A/B用于区分这两种作用。
